## 실제로 더 검증한 범위

- transform:399의 기존 S idle: 원본 SHA/1클립/6포즈를 확인하고 실제 AnimatedSprite2D
  엔진 시간으로 6/6포즈 재생. 프로필을 만들어 주입하거나 기본 게임에 연결하지 않음.
  기존 binder의 `runtime_walk_reference_height`를 호출한 결과
  `Require an authored walking or running reference`가 발생한다. 현재 선택에는 idle만
  있으므로 잘못된 스케일을 추정해 프로필을 생성하지 않았다. 필요한 것은 정상 RUN의
  기준 포즈 0/3과 검증된 발 기준이며, 단순 누락 프로필 파일을 채우는 문제가 아니다.
- 놀 E RUN 6포즈, E ATTACK 3포즈, 알비노 몽크 SW RUN 6포즈: 실제 PNG 맵/Main,
  실제 Monster.setup과 명시적 QA record clone으로 **3/3클립·15/15포즈** 재생.
  공격 마커 1회, 발 anchor/몸체·충돌·미러 금지·플레이어 상태 보존 통과.
  후보 주입이며 기본 연결은 0건이다. 원본 Main 캡처 15장과 내부 접촉표를 저장했다.
  시각 검토상 방향/전신은 보이나 RUN의 1/4, 2/5, 3/6 단계가 작은 Main 화면에서
  유사하여 반대쪽 지지 다리와 접지의 의미 검증이 끝났다고 판단하지 않았다.
- 신화 transform:130 E attack HOLD 대표 원본을 Git에서 읽어 SHA를 대조했다.
  내부 시각 검토에서 아래 왼쪽 공격의 검/효과가 인접 포즈 영역으로 뻗는 것을 확인.
  기존 엄격한 추출기로 다시 검사해 **6포즈 기대/13분리 요소 발견** 실패를 재현했다.
  단순 고정 칸 자르기로 효과를 버리거나 원화 구성요소를 임의 귀속시키지 않았다.

따라서 3개의 기존 일반 후보와 1개의 idle에 대한 추가 기술 증거는 생겼지만,
이것으로 328개 의존성을 해소하거나 최종 시각 승인을 승격하지 않았다.

## CI 환경 대조와 외부 차단

이전 partial locomotion run 40173677539의 artifact 이름에서 실제 checkout이
시험 병합 SHA `732aacf87f9a78b670f97b53293d61ae03ed99bf`임을 확인했다.
부모는 main `cba19558...`와 PR head `637e9e12...`이다. GitHub compare 결과는
현재 d76a098b와 diverged(merge 1개/후속 workflow 4개), 추가 변경 파일 0이다.
따라서 이 실패를 후속 게임 코드 변경으로 해결했다고 주장할 근거는 없다.

원격 doguri-N 로그와 job 목록은 읽었지만 추가 보고 artifact 다운로드
`pr122-gait-doguri-N-reports-732aacf...`는 GitHub Actions 저장소 응답 **HTTP 403
Forbidden**으로 실패했다. 파일은 받지 못했고 우회/동일 재시도하지 않았다.
CI의 상세 field 상태와 로컬 native-map probe의 차이를 확정하려면 해당 artifact에
대한 정상 접근 또는 CI 환경에서 대표 1사례의 field 진단 로그가 필요하다.
기존 6-case/full CI를 다시 시작하지 않았다.

기존 Godot Validate run 40187062534 (9ac7b16b)은 계속 확인 중이다.
소스 패키징 단계가 진행 중이면 엔진 import/부팅/전체 검증 종료로 보고할 수 없다.
최신 상태는 PR 본문/인계에 기록한다. 이전 SHA guard 성공도 새 SHA 전체 통과와 다르다.
