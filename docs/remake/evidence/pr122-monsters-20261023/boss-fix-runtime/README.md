# Boss repair runtime QA harness

This harness applies the unchanged `ActorMotion` to a game-scale `AnimatedSprite2D` in a 960×640 diagnostic ground arena. Its camera zoom and time scale are 1. It advances the original motion logic at 1/60 s, caps engine frames at 60 FPS, records simulation and wall time, and captures each distinct source frame plus attack-release frames. PNG saving may slow wall time; it does not accelerate playback. The grid is 32 world pixels, the amber cross is the actor origin, and the red dummy is a range marker. No image is sent to chat.

Run from the repository root, using a new output directory:

```sh
python3 docs/remake/evidence/pr122-monsters-20261023/boss-fix-runtime/run.py --key 'monster:얼음 여왕' --profile PATH/NativeMotionProfile.tres --directions E,S --out /workspace/runtime/NEW-boss-qa --render
```

Use `--directions E,SE,S,SW,W,NW,N,NE` for the mandatory 33 role/direction requests. A JSON `--case-file` can contain several cases with unique ASCII slugs; edit the placeholder profile paths and exact DB monster keys in `cases.example.json` before use. A missing role is recorded `NOT_AUTHORED`; it is never invented. Without `--render`, the same motion runs headlessly and emits diagnostics but no viewport PNGs. `--roles run` or another subset permits bounded partial candidate checks.

The runner resolves DB base records and world-catalog overlays/additions. It mirrors `monster.gd::_setup_animation`: reference speed is overwritten with the monster DB base movement speed, scale is the native pixel scale with native width ratio, and the original ActorMotion applies source `twilight_canvas_size` normalization. The native profile is duplicated in memory. Its explicit sprite offset must be copied as a catalog/record animation-profile override when integrating, because the actual Monster first sets default offsets from visual height and then applies explicit overrides. The harness intentionally retains that explicit candidate offset. Samples expose actual gait, move ratio, movement FPS, source region/texture size, actual scaled offset, release event and selected frame; reports include canvas metadata and actual versus stored reference speed. Attack contact index comes from the authored profile, while the real release clock remains original ActorMotion. A marker and a source index alone do not prove anatomical contact.

Rendering needs Godot 4.7.2 and Xvfb. The local non-system Xvfb dependency used for the self-test is `/workspace/runtime/boss-qa-xvfb/unpacked/usr/bin/Xvfb` from Debian xvfb 21.1.16-1.3+deb13u4. The runner can also use Xvfb from PATH. It creates `/tmp/.X11-unix` if absent. In the managed sandbox, execute the runner with `sandbox_permissions=with_additional_permissions` and `additional_permissions={network:{enabled:true}}` to permit the local X11 socket. Rendering uses X11/OpenGL compatibility and `LIBGL_ALWAYS_SOFTWARE=1`; the successful self-test reports llvmpipe LLVM19.1.7. No system package installation is required. Every invocation is bounded by the timeout (default 420 s).

This is not actual Main, AI/navigation/collision/damage integration, an approval of foot support/contact, or a mythic-quality verdict. Main review infrastructure exists at `tests/pr122_family_reuse_main_review.gd` / `tests/run_remaining106_visual_review.gd`, but it depends on global catalog/autoload registration outside this isolated harness. Integration and visual review remain separate. The virtual-canvas foot-error diagnostic follows the existing staging 1/8-height anchor convention and must not be treated as anatomical foot evidence. Approved assets, catalogs, ledgers and gameplay source are unchanged.

The included self-test uses the already existing queen r002 E RUN only, not newly authored repair art. It resolved all six RUN frames at DB speed66/reference-speed66 with native scale0.614285714286, canvas256×256, actual originalActorMotion scaling, and six rendered PNGs. It makes no production approval change. Initial parse/display failures are preserved. Output paths inside the receipt reflect its original runtime execution directory.
