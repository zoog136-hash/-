# 신규 영웅급 사망은 S 한 방향

대상은 기존 미승인25종이다. 승인84종은 재제작하지 않는다. 걷기 신규 제작은 제외하고 달리기·대기·공격·피격은 8방향을 유지한다.

신규 사망 원화만 남쪽S(index2) 한 방향으로 제작한다. 기존 다방향 사망 원화·클립·프로필과 실패/HOLD 기록은 모두 유지한다. 일치하는 기존 사망을 검증 후 재사용할 수 있으면 새로 제작하지 않는다.

## 적용 결과

- 기존 6후보: 179/182/231/260/11/7의 다방향 사망을 보존했다. 적용 전219개 기존 영웅급 자산의 바이트 SHA를 기록했고 이후 다시 비교한다.
- 하퍼197: 자기 greatsword 체형에 신규 RUN48을 제작하고 기존8방향 idle/attack/hit/death를 재사용했다. 신규 사망 원화0. 재질 분리7/48자세 때문에 품질은 HOLD다.
- 메이드 안나276: 신규 RUN48/ATTACK48/IDLE24/HIT24/DEATH6 =150개의 고유 원화 자세. 사망만 S 한 방향이다. 기존 미승인 chain-armour donor는 새 maid 복장과 일치하지 않아 혼합하지 않으며 원래 파일은 보존했다. 기존 후보에 이미 만든 사망 방향을 감축한 작업이 아니다.
- `DeathSouth.tres`에는 S 단일 클립6프레임만 있다. 최종 SpriteFrames의 `death_0..7`은 같은 S Texture 객체를 공유한다. 논리적 재생 참조192개를 고유 원화192개로 세지 않는다.
- 별도 검토했던 opt-in 패치는 후속 원격 확인에서 PR122의 공식 구현으로 대체했다. 최종 `actor_motion.gd`는 PR122 `4fda626b`와 바이트 단위로 동일하다. 기존 검토 패치/커밋/실패 기록은 이력으로 보존하며 최신 PR에 다시 적용하지 않는다. 새 wrapper/profiles도 보존한다.

## 검증과 집계

Godot 4.7.2의 실제 Main/Player에서 8후보 ×8입력 방향을 검사한다. 신규 공통 S 선택, 모든 프레임의 1회 순방향 재생, 마지막 프레임30초 유지, 반복 사망 요청 시 재시작 금지, 예약 공격의 유령 타격 방지, 기존 충돌/속도/인벤토리 보존을 확인한다. 기존 방향 사망 원화도 최신 PR 정책대로 마지막 자세를 유지하며, 사망 원화가 없는 초상화 대체 표시의 fade는 별도 대조한다. 단일 S 트랙만 있는 리소스에서도 8방향 요청이 모두 death_2를 선택하는지 추가 확인한다.

전투 타이밍·바닥 드랍·저장 호환성만 표적 회귀 검사했다. 전체 CI33은 실행하지 않았다. 이미지/전체 로그/대량 JSON은 채팅에 출력하지 않고 증거 파일에 보존한다.

후보8종은 기술 검증 대상이며 최종 완료 수가 아니다. 원작 외형·동작의 자연스러움·실제 접지 및 시트 간 일치가 미승인인 항목을 완료에 더하지 않는다. 신규 최종 승인0/정식 카탈로그 적용0/미승인25를 유지한다. 나머지 미착수17종은 후속 제작 대상이다.

최종 검사: 실제 Main 8후보/64입력 + 단일 S 트랙8방향, 168,937검사 PASS. 전투/드랍/저장27검사 PASS. 기존219파일 바이트 보존 PASS. 공통 코드 정렬 커밋 `fb5b5c16`은 기존 PR 브랜치를 변경하지 않았다.
