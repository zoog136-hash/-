# 영웅급 사망 마지막 프레임 유지 — 별도 런타임 검토

기존 `actor_motion.gd`는 death frame을 끝에 고정하지만 약 1초 후 modulate alpha를 0으로 만든다. 실제 Main의 8후보 ×8입력 검사에서 이 문제를 재현했으며 실패 보고서/로그는 `../evidence/death-south-20261022/baseline-runtime-fade-failure.*`에 보존했다.

사용자 2026-10-22 지시의 “공통 런타임 코드 수정은 기존 PR #122 담당 작업과 충돌하지 않도록 별도 검토”에 따라 공통 변경을 먼저 별도 패치와 복사 프로젝트에서 검토했다. `hero-corpse-hold.patch`는 아래 조건의 리소스에만 기존 opacity fade를 생략한다.

- 프로필이 `transform:`이고 SpriteFrames가 `pr122_hero_hold_final_death_frame=true`로 명시적으로 참여한다.
- 해당 플래그는 영웅급 전용 새 wrapper 리소스에만 있다. 기존 원화·SpriteFrames·프로필 파일은 변경하지 않는다.
- 원래 방향 클립·재생 시간·타격 마커·사망 시계·물리·드랍·저장 코드는 유지한다. 기본 카탈로그 연결은 변경하지 않는다.

복사 프로젝트는 실제 Main/Player와 동일한 스크립트/리소스를 사용하며 공통 스크립트 한 곳의 조건 분기만 다르다. 검토본에서 8후보/64개 실제 키 입력 방향, 1회 순방향 재생, 30초 마지막 프레임 유지, 반복 die 요청의 멱등성, 예약 공격 취소, 8개 비참여 리소스의 기존 페이드 대조 검사를 통과했다. 전투 타이밍·바닥 드랍·저장 호환성 회귀 검사도 통과했다.

그 뒤 검토된 코드와 SHA가 정확히 일치하는 변경만 `feature/pr122-hero-parallel`에 적용했다. 공통 런타임 변경은 원화/정책 묶음과 별도 커밋으로 제출한다. PR #122 원본 브랜치에 적용하거나 병합하지 않았다. 실제 feature 브랜치의 최종 결과는 `../evidence/death-south-20261022/feature-main-death-policy-opengl.json`을 기준으로 한다. 초기 overlay 영수증의 `branch_runtime_modified=false`는 적용 전 검토 시점의 기록이다.

기존 6후보/하퍼의 다방향 사망 원본을 유지했다. 메이드 안나는 신규 S 한 방향6자세만 제작했고, `DeathSouth.tres`의 동일 Texture 참조를 8개 death 입력 트랙에 연결했다. 8개의 새 방향 원화로 계산하지 않는다.

`prepare_runtime_review.py --overlay-dir <새 검토 경로>`로 별도 검토 프로젝트를 만들 수 있다. 같은 경로에 기존 검토본이 있으면 일치 여부를 검사하며 덮어쓰지 않는다. Godot 4.7.2, 독립된 `XDG_DATA_HOME` (`twilight-test-` 접두사), 실제 OpenGL에서 `validate_death_policy.gd`를 실행한다. 검토 복사본 실행 시에만 `TWILIGHT_HERO_RUNTIME_REVIEW=1`을 지정한다.

정식 캐릭터 외형/접지 승인은 별개이며 새 승인 수는0이다. PR122 통합 시 최신 공통 코드와 다시 비교하고 사용자 명시적 병합 지시 이후에만 통합한다.
