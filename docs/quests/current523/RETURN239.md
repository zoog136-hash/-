# 원본239 퀘스트 보상 귀환 연결

PR247 공개 `bc0ce7215b53ef970a58f13ddbeecf7e6641330c`의 결과형 API와 필요한 동일 아덴 이동 호출만 이 브랜치에 연결했다. 원본 스택 정체 검사 `regional_return.gd`와 1,236바이트 설정은 해당 커밋과 바이트가 같다. 다른 PR 전체, 126424 지역 전환, 상점/티켓/복구 기능은 가져오지 않았다.

`world.consumable_service.use_owned_native_return(item_key:String)`는 같은 결과 계약을 유지한다. `ok && saved && consumed==1`만 성공이다. 새 수령은 기존 PR238 검증 팩과 staged supplier를 사용하고, 퀘스트 완료/원본 수령 영수증/실제 native 소지를 같은 트랜잭션으로 저장한다. 정확한 Normal 키는 `귀환 주문서 (각인) · 원본#239`다. 과거 일반 이름·다른 축복·같은 이름의 보관 스택을 합치지 않는다.

이미 보관한 개체는 `use_owned_quest_return(physical_id:String)`로 연결한다. `quest_return239.prepare()`는 schema·원본 SHA·questID·rewardID·ItemClass·축복·최초 수량·현재 잔여·유일한 영수증·실제 완료/소지 합계를 검증한다. 독립 퀘스트 원본 ItemClass 전체 행을 검증된 PR238 상세 정의와 대조하고, Normal 변형 정체를 확인한다. `quest_reward_ownership`은 차감 후보만 만들며 이동/실제 차감/저장을 실행하지 않는다.

두 입력은 **같은 귀환 소비 함수**로 이동한다. 기존 `_safe_region_position()`, `_spawn_position()`, `_teleport_player()`를 재사용한다. 실제 검증된 같은 `aden_world`의 기존 안전 위치만 지원한다. 다른 맵이나 native M 목적지·좌표를 추가하지 않았다. 실제 물리 개체/인벤토리 차감 후보와 사용 영수증을 준비하고, 이동한 위치와 한 저장으로 확정한 뒤 소지를 채택한다. Native 스택을 임시 지급하거나 raw 보관 이름을 바꾸지 않는다. 별도 외부 차감/보상/두 번째 저장도 없다.

최초 수량 5의 보관 개체 한 개를 사용하면 같은 물리 ID와 최초 수량 5 영수증을 유지하고 잔여만 4가 된다. `item_grants.origin=held_use`의 `used_quantity`는 원래 지급량과 별도로 기록한다. 소진된 물리 참조를 다시 호출해 같은 이름의 다른 개체를 소비할 수 없다. 영수증 없는 과거822 보상은 새 출처를 만들지 않고 보존한다.

현재 기본 게임의 CannotUseItem/CannotTeleport, 잠금, 생존, 스턴/공포, 원본 정체·직업·레벨·기간도 유지한다. 저장 실패는 위치·수량·사용 영수증을 보존한다. 쓰기는 됐지만 오류가 반환되면 차감/영수증 후보와 map_id/position을 함께 디스크와 대조하고 확정된 경우만 채택한다. 실제 디스크가 다른 후보로 바뀌어 결과를 확정할 수 없으면 `uncertain:true`를 반환하고 재사용/저장을 막는다. 이런 경우를 보존/성공이라고 보고하지 않는다.

## 실제 범위

기존 실제811 저장본에는 239 보관 개체 57개, 총 212개가 있었다. 해당 복사본에서 실제 선택 UI→부분 사용→위치/차감/영수증 저장→재접속을 검사했다. 별도 새 Main은 전체 원본 획득 자동 완료를 실행해 영수증과 함께 native239 총 212개를 실제로 지급받고 같은 소비 API를 검사했다. 테스트가 임의 아이템을 발급하거나 퀘스트를 완료 표시한 결과가 아니다.

859/1281/239 세 소비자를 연결한 새 실행은 **원본 완료811, 일부 아이템 보상 사용 대기429**다. 두 소비자의 공개 체크포인트 `76a721f0`의811/480에서51개 퀘스트 대기가 추가 해소됐다. 57개 입력 스택 전부를57개의 완전 해결 퀘스트로 계산하지 않는다. 원본 레벨 목표104개 교정·최종 레벨86·제외160·잠김/기간/연계/반복/운영 조건2,650개는 유지한다. Native 수령 영수증은120개 퀘스트에 있다. 기존526/146종은 세 소비자를 연결하기 전의 기준이며, 신규 실행에서 남은 보관 ItemClass는143종이다.

과거822 저장본 원본 SHA `13e6d609f5fabf8cc7f1fd4a49c9432c379ad2e94b966978f547206b15a39ade`,811 기준 저장본 SHA `975b900968005f768b0154f2a2a9fe396954a1f098791d704b5d6d5930cdba92`를 그대로 보존했다. 사용자50칸 퀵슬롯과 기존 소유를 일괄 변환/삭제/재지급하지 않았다.

원본 전수 및 이전 두 소비자 증거는 `consumer-validation.json`의76a721f0 체크포인트이고, 후속 귀환과 회귀 검사는 [return239-validation.json](return239-validation.json)에 기록한다. 239 실제 보관34개/새 지급24개 검사, 기존 두 소비자36개/새 지급31개, 과거822 OpenGL UI754개, 팩 누락15개, Core44개 검사를 구분한다. 안전 지역 내 시작 위치·잠금·스턴·생존·다른 맵 플래그는 통제된 QA 조건이다. 실제 다른 지도 입장/원작 좌표/확률 전체 플레이의 증거로 확대하지 않는다.
