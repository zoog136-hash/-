# 퀘스트 실제 보상 소비 연결

이 문서는76a721f0의859/1281 두 소비자 체크포인트다. 추가239 연결의 최신811/429 실행과 원자 이동/영수증 검증은 [RETURN239.md](RETURN239.md)를 따른다.

원본 퀘스트 3,621개 정의와 획득 즉시 자동 완료 규칙을 유지하며, PR238의 공개 `f078a4651d53a2e0681e339ee4c4e81151e34e55`에서 소비 모듈 7개를 바이트 변경 없이 재사용한다. 다른 PR 전체를 병합하거나 보호·상점·카드 시스템을 복제하지 않았다. 모듈별 SHA와 의존은 [provider238-contract.json](provider238-contract.json)에 있다.

실제 연결한 아이템은 **859 전투 강화의 주문서 (각인)와 1281 음식 상자, 두 종류**다. 카탈로그에 있다는 이유로 나머지 34,743개 아이템의 효과가 완성됐다고 취급하지 않는다. 퀘스트 보상의 전체 원본 ItemClass 행을 검증된 아이템 팩의 전체 sidecar 행과 대조한다. TestItem·축복·원본 즉시 사용·직업·레벨·기간·서비스 지역·은신·재사용·잠금 조건을 임의로 풀지 않는다. 상자 출력은 실제 직업에 해당하는 원본 ID·수량·축복을 유지한다. 상자에서 나온 음식의 별도 사용 효과까지 이번 두 입력 아이템의 완료 범위에 포함하지 않는다.

## 수령과 기존 보관 개체

새 보상은 기존 PR238 `patch523_item_inventory.stage()`에 원본 ItemClass ID·수량·축복·강화를 넘긴다. 이 API가 반환하는 inventory/item_instances/gold는 전체 후보값이다. 같은 퀘스트 배치에서 먼저 준비한 보관 보상·재화를 포함한 후보를 기준으로 호출해 덮어쓰기 손실을 막았다. 퀘스트 완료·보상 영수증·재화·EXP·레벨·실제 소지를 한 저장으로 확정한다. 오류 반환 후에도 실제 디스크에 전체 후보가 기록됐는지 확인하며, 재요청은 중복 지급하지 않는다.

기존 개체는 `quest_reward_receipt`의 schema·원본 ZIP SHA·questID·rewardID·ItemClass·축복·최초 수량, 원본 행 전체, 실제 완료 이력, 개체별 잔여 수량과 인벤토리 합계가 모두 맞아야 선택 사용을 허용한다. 원래 보관 키나 지급 출처를 바꾸지 않는다. `quest_reward_ownership.gd`의 소지/차감 후보는 효과나 저장을 수행하지 않으며, 다른 소비자의 요금·출력·영구 상태를 대신 처리할 권한도 아니다.

859/1281은 그 검증된 개체 하나를 선택한 뒤 기존 PR238 소비자를 격리된 후보에 실행하고, 정확한 보관 개체 차감·실제 효과/출력·사용 영수증을 한 번에 저장한다. 수량 3개짜리 주문서를 한 번 사용하면 같은 물리 ID와 최초 수량 3의 영수증이 남고 잔여 수량만 2가 된다. 소진한 개체를 다시 선택해 다른 개체를 이름으로 소비할 수 없다. 전투 강화는 실제 근접 공격력 계산까지 연결된다.

저장 실패는 소지·효과·영수증·저장 바이트를 보존한다. 쓰기 후 오류가 반환된 기존 소비자의 새 native 스택은 디스크와 라이브 상태를 대조하여 재시도를 막고, 새 Main에서 확정된 저장을 복구한다. 선택한 보관 개체 경로는 전체 공동 후보가 디스크와 일치하면 같은 트랜잭션으로 채택한다. 미확정 결과를 성공으로 표시하거나 두 번 차감하지 않는다.

**과거 822개 완료 저장본에는 새 지급 영수증이 없다.** 이 저장본은 완료·보상·50칸 퀵슬롯·원래 파일 SHA를 보존하며 일괄 변환/재지급하지 않는다. 팩 설치만으로 이 보상을 이미 native 스택으로 받았다고 표시하지 않는다.

| 실제 실행 범위 | 원본 완료 퀘스트 | 일부 아이템 보상 사용 연결 대기 |
| --- | ---: | ---: |
| 현재 레벨 교정 코드, 아이템 소비 팩 없음 | 811 | 526 |

526/480은 아이템 개수가 아니라 **완료 퀘스트 중 일부 보상의 사용 연결 대기 건수**다. 두 소비자로 46개 퀘스트의 대기가 해소됐다. 새 실행의 native 지급 영수증은 65개 퀘스트에 있고, 해당 보상 총량은 859 66개·1281 23개다. 레벨은 86, 제외 160개, 나머지 잠김/기간/연계/반복/운영 조건 2,650개를 유지한다. 전수 정의 반영이 모든 보상 효과 완성이라는 뜻은 아니다.

## 실제 팩과 설치

퀘스트 v1 ZIP은 [기존 비공개 Drive 파일](https://drive.google.com/file/d/1qt_ZIoU2xuSHfnhrl2Yas4_BD-8uHWcH/view) 그대로다. 570,245바이트/SHA `77866c180d4224eff6d7e578759ec0820d6e50515e5c6bd8a67dc92421c20063`이며 새 파일이나 버전을 업로드하지 않았다.

아이템 소비는 PR238의 [기존 비공개 정상 팩](https://drive.google.com/file/d/1yhPldWHmsnf758yFfwrJO7v9ZrB91oNa/view)을 재사용한다. ZIP 23,637,249바이트/SHA `fb2a4de030b7d302fd7d8d2c541ca3cc8d1fbe246cf67ef574d812d3ccb6fc8d`, BIN 3,050,707바이트/SHA `38ee3ec74d12adaa9847c507f6fb093c41a4f7a8c5c1cefcd08c3a9629920d27`, gzip sidecar 136개다. 정식 Drive 다운로드→크기/SHA/ZIP CRC→생산 설치기→새 소비 프로필의 실제 Main을 확인했다. 별도 원본/보고서/캡처 업로드와 공유 변경은 없다.

게임 자체 Drive 자동 다운로드는 없다. 기존 퀘스트 팩 UI의 수동 ZIP 설치·재시작에 더해, 아이템 팩은 기존 PR238 생산 설치기 `patch523_monster_drops.install_zip()`로 설치한 검증 폴더를 `--patch523-drop-root=<설치폴더>`로 지정해 실행했다. 퀘스트 ZIP 하나에 이 아이템 팩이 포함됐다고 주장하지 않는다. 현재 Draft 코드와 main/기존 실행본의 설치는 별개다.

## 남은 의존

PR256 공개 `c69b71a66d2f457066591434fefb2001dfbc6885`의 보호 본체 6종·비활성 ID·퀘스트 재료 96004/96014/200698을 기존 대기 146종과 대조했다. 교집합은 0개다. 현재 Main에 보호 소유자가 설치되지 않았고 실제 해당 소지도 없으므로 제작/사용을 fixture로 꾸며 완료했다고 하지 않는다. 제작 인수는 결과 ItemClass가 아닌 원본 ItemCraftID다. 명예 코인 비용·보호 본체·Appellation 저장은 해당 소유자 범위다.

PR247 공개 `bc0ce7215b53ef970a58f13ddbeecf7e6641330c`의 `use_owned_native_return(item_key)` 계약도 읽었다. 실제 기존 보상 239는 57개 스택/57개 퀘스트/총 212개다. 현재 퀘스트 기반 Main에는 이 결과형 API가 없고, 현재 보관 키는 소유자가 받는 정확한 native Normal 소지 계약도 만족하지 않는다. 따라서 입력을 보존한다. 이름만 바꿔 원본 출처를 만들거나 귀환 좌표·효과를 복제하지 않았다. 필요한 것은 설치된 소비자와 명시적인 보관 영수증 입력 어댑터 또는 새 native 수령 공동 트랜잭션 검증이다. 성공 판단은 `ok && saved && consumed==1`이며, handled는 처리 여부다. 전달된 티켓 6종은 현재 대기 146종과 교집합이 없고 별도 티켓 확장팩은 이 환경에 설치하지 않았다.

PR 제목/본문 갱신은 승인 검토에서 거절되어 **미실행**이며 재시도하지 않는다. 낡은 본문의 822/537을 새 코드 결과로 사용하지 않는다. 실행 증거와 현재 수량은 이 문서 및 [consumer-validation.json](consumer-validation.json)에 기록한다. 다른 PR/main 병합·전체/수동 CI·맵 환경 변경·엔진/APK 작업은 수행하지 않았다.
