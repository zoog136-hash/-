## 실제 전역 합성 제한과 교환 범위

기존 CardDrawFusion.configure가 source_merge_out_disabled를 source_merge_blocked에 넣고, spare_count와 실제 fuse 후보가 이를 제외한다. 이 경로를 재사용한다. 단일/일괄 합성, world의 합성 요청 처리, 실제 합성 UI에서 네 종류가 재료로 들어가지 않는 것을 검사했다. UI도 같은 원본 플래그를 반영해 자동 등록과 합성 가능 수량에서 제외하고 보유 수량은 계속 표시한다.

현재 소유자와 호출자를 검사했으며 소비형 카드 swap/exchange 진입점은 없다. 장착/선택은 원본 카드 교환과 같은 동작으로 해석하지 않는다. 새 교환 기능을 만들지 않았다. 향후 통합에서 교환 소비자를 도입하면 실제 같은 안정 ID의 source_swap_out_disabled와 원본 영수증을 그 소비 경계에서도 집행해야 한다.

## 옵션 주입은 별도의 TWILIGHT 보관 정책

**IsNoMergeOut가 옵션 각성 경험치 주입까지 금지한다는 원본 규칙을 주장하지 않는다.** 비용·EXP·등급 정책은 변경하지 않는다. 새 퀘스트 사본의 주입 소비 계약이 확인될 때까지 **새로 생긴 중복 사본만** 보존하는 좁은 호스트 안전 정책을 기록한다.

영수증은 `quest_option_feed_policy=TWILIGHT_host_hold_until_option_owner_verified`와 `quest_option_feed_hold`를 명시한다. 첫 영구 소유 사본은 hold0이고 이후 실제 새 중복 사본은 hold1이다. 기존 자유 중복 수량은 건드리지 않는다. 이 정책은 원본 NoMerge/NoSwap 플래그로부터 자동 추론하지 않는다.

현재 실제 옵션 주입 준비 API `option_awakening_service.prepare_feed`가 명시적 영수증의 보관 수량을 제외한다. native/legacy 목록과 실제 후보 모두 같은 가용 수량을 사용한다. 새 보관 사본만 있을 때 주입은 거부하며 기존 자유 사본2개를 더한 독립 인용 후보에서는 그2개만 소비할 수 있음을 확인했다. 원본 각성 대상의 영구 소유 자체나 금전으로 하는 각성 시도는 이 보관 정책으로 금지하지 않는다. 옵션 UI의 policy_note에도 TWILIGHT 보관 정책과 해당 수량을 표시한다.

## 한 번의 소지·소유·영수증 저장

공개243 `957b8853b2986109b8fa747573cf6d18496f46c4`의 receive_source_card(category,record,receipt)와 source_card_receipts import/export 계약만 좁게 재사용했다. 게시 거절된243의 새8파일이나 별도 탐험 엔진은 사용하지 않았다. 기존 카탈로그·합성/천장·일반 RNG를 유지한다.

실제 선택한 물리 개체는 기존 OWN.proof/prepare_debit/use_state로 원본SHA·Quest/Reward ID·ItemClass·축복·불변 지급 수량·현재 잔량·잠금·완료 관계를 검증한다. 정상 새 지급 소지는 정확한 카탈로그 소지 키와 실제 지급 영수증을 확인한다. 이름을 바꾸거나 임시 라이브 아이템을 지급하지 않는다.

새 CardDrawFusion 후보에 현재 소유를 가져와 원본 고정 카드를 한 번 수령하고, 실제 아이템 차감·카드/중복·원본 입력 증명·사용 영수증·호스트 보관 표시를 한 후보로 저장한다. 확인된 저장 이후에만 라이브 상태를 채택한다. 저장 실패는 모두 보존하며, 저장 후 오류는 실제 기록과 후보를 비교해 한 번의 확정된 거래를 채택한다. 불확실한 파일 결과는 재사용을 막는다.
