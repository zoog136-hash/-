## Changes

## Why so many

Feature work accumulated separate historical branch workflows (crafting, warehouse, shop, monster AI, map rendering and PR122 source previews). Some are one-shot publishing/recovery tools, not normal CI. Broad PR workflows have no paths restriction, while others target individual scripts, art/data or tests. A shared change such as scripts/world.gd can therefore fan out to many independent checks.

A feature SHA on a branch matching push and in an open PR can start both events. PR runs normally use a synthetic merge SHA, so identical source changes do not necessarily have identical github.sha. workflow_dispatch is an additional independent execution, not automatic duplication. Existing concurrency includes event_name or uses event-specific refs, so it does not reliably deduplicate push versus PR. This patch removes the feature-push trigger in dual-event workflows instead of cancelling runs.

Integration executes tools/test_project.py with the complete suite plus loot/combat/regions/crowd rendering. L1J also runs the full suite but first installs synthetic fixtures and performs resource safety/Android APK verification: these environments are not equivalent. Feature workflows such as combat-animation, monster-ai, original-skills and crafting repeat import/boot or selected regression checks and retain specialized render markers/assertions. Their commands must not be dropped merely because test filenames overlap. Existing TWILIGHT_CI_TESTS expressions already narrow several feature jobs on integration-covered PR bases.

## Limits and remaining consolidation

The intentional removed Windows check may require an administrator to remove it from required status checks; protection settings were not changed. Required checks cannot be certified from the available permissions.

Cross-workflow regression merging and new path selectors remain deferred in this draft: required checks and fixture equivalence must be verified first. No new restrictive path filters are introduced, so this change cannot exclude common-engine/resource edits previously selected. A later selector should run all related checks on common engine/assets/data/addons or unknown paths and on diff errors, with always-reported stable check names. Existing narrow filters still require that separate dependency audit.

No CI was dispatched, cancelled, deleted or merged. Open PRs #152–#155 and #157–#158 were observed and not edited.
