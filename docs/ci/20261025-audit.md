## Why so many

Feature work accumulated separate historical branch workflows (crafting, warehouse, shop, monster AI, map rendering and PR122 source previews). Some are one-shot publishing/recovery tools, not normal CI. Broad PR workflows have no paths restriction, while others target individual scripts, art/data or tests. A shared change such as scripts/world.gd can therefore fan out to many independent checks.

A feature SHA on a branch matching push and in an open PR can start both events. PR runs normally use a synthetic merge SHA, so identical source changes do not necessarily have identical github.sha. workflow_dispatch is an additional independent execution, not automatic duplication. Existing concurrency includes event_name or uses event-specific refs, so it does not reliably deduplicate push versus PR. This patch removes the feature-push trigger in dual-event workflows instead of cancelling runs.

Integration executes tools/test_project.py with the complete suite plus loot/combat/regions/crowd rendering. L1J also runs the full suite but first installs synthetic fixtures and performs resource safety/Android APK verification: these environments are not equivalent. Feature workflows such as combat-animation, monster-ai, original-skills and crafting repeat import/boot or selected regression checks and retain specialized render markers/assertions. Their commands must not be dropped merely because test filenames overlap. Existing TWILIGHT_CI_TESTS expressions already narrow several feature jobs on integration-covered PR bases.

## Verified Godot executable cache (2026-10-25 follow-up)

The Linux 4.7.2 official engine executable is stored under a version/OS/architecture locked cache key `twilight-godot-4.7.2-stable-linux-x86_64-engine-v1`. The common `.github/actions/setup-godot-linux` composite action (12 consumer workflows), `godot-validate.yml` and `twilight-integration-validate.yml` now restore via `actions/cache/restore@v4` and only download the official pinned engine when the executable is absent or fails the version check. A verified executable is saved using `actions/cache/save@v4` **only on a trusted main push**; PRs cannot seed a shared default-branch engine cache. Cache misses and cache-service failures retain official download and unchanged test commands, paths and version checks. The full tests, resource integrity checks and Android export jobs remain unchanged.

No `.godot/imported`, untracked third-party resources, per-PR navigation bake output, Android export templates, secrets or large PNG map packs enter this cache. Such outputs are not proven reproducible/portable across PRs and could exceed cache budget. The existing 80-workflow contract audit now permits only this exact verified installer-cache wrapper and the earlier named cancellation-policy exceptions, rejecting any altered test command/check/job/trigger. Local unit contracts cover cached/missed/fallback setup, save eligibility, and unmodified tests. No full CI was dispatched for this [skip ci] change. Cache hits and runtime savings have not yet been measured; main merge and a successful main push are needed to seed the shared cache.


## Pilot: cached imported Godot resources (2026-10-25)

The existing **Godot Validate** workflow now restores `.godot/imported` **and generated `*.import` metadata** using read-only `actions/cache/restore@v4` with pinned version/OS/renderer key `twilight-godot-import-4.7.2-linux-compat-main-v1`. There is intentionally no `restore-keys`: PR runs can only reuse a trusted main cache. The normal full `--headless --import`, texture checks, gameplay tests and failure markers are all **unchanged** and run even on a cache hit. Godot's importer must revalidate changed source assets, rather than assuming reused compiled bytes are correct.

A trusted `main` push writes this cache only after **the full Godot Validate job succeeds**, only if there was no cache hit and the imported output is nonempty and less than **1.5 GiB**. Cache read/write failures are nonfatal and normal imports continue. Cache size is bounded because this repository has large map/image packs; cache limits must not create storage churn. The workflow reports `TWILIGHT_IMPORT_SECONDS`, imported byte size and cache-hit status to compare cold versus warm results. No external original images, source assets, maps, private packs, saves or Android builds are cached. The changed scope is limited to this single validation workflow until cache size, cache hit rate and actual time reduction are measured.

The CI contract validator accepts only four guarded import-cache steps while continuing to prove all earlier Godot test commands are preserved. Local unit assertions cover trusted-main-only write and the narrow cache path. This is a **pilot without a measured speedup yet**. No CI dispatch or main merge was performed; the feature becomes usable after PR #160 merges and a main push successfully seeds the cache.
