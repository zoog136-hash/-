# 아덴·오만·지배 일반 Godot 실행 보정

기준 main은 `a6fc6dec49f4f9a05c1e82df9a4e021b4cbe44ec`이다. 별도 브랜치 `feature/aden-oman-domination-runtime-20261023`에서 작업한다. main, PR #100/#120/#121/#122/#124/#147 브랜치를 수정하거나 자동 병합하지 않았다.

## 실제 문제와 변경

사용자가 문제가 보인 실행본을 **GitHub에서 업데이트한 Godot 프로젝트**라고 확인했다. 10월 18일 구현은 `--png-review` 개인 검수에만 연결되어 일반 게임에는 오만·지배 그림이 나타나지 않았다. 이번 코드는 프로젝트 내부에 검증된 PNG 팩이 있으면 **추가 실행 인수나 환경변수 없이 Main.tscn의 일반 게임과 일반 저장**에서 사용한다.

| 맵 | 변경 | 검증/보류 범위 |
| --- | --- | --- |
| `aden_world` | 현재 Git PNG를 그대로 읽고 그림·충돌·길찾기·배치·미니맵을 동일한 6배 월드 단위로 관리 | 기란 후보 지형 자 6개 중앙값 5.9705748; 6배 반올림 차이 약 0.49%. 전역 원본 통행격자 정합 승인이 아님 |
| `oman_01`~`oman_10` | 원본 101~110 PNG를 기존 RemakeSourceRenderer에 일반 실행으로 연결 | 기존 A3 방향별 통행·청크·시작점·포털·저장 좌표 유지. 전체 그림/장애물 일치는 부분 검수 |
| `domination_summit` | 사용자가 선택한 **111.png**를 기존 게임의 지배 정상에 연결 | 원본 픽셀 좌표의 수동 검수 중앙 구역만 개방. 원본 111 서버 격자와의 전역 대응은 보류. 12862를 대체 사용하지 않음 |

캐릭터 scale=1, 실제 기본 스프라이트 불투명 높이 80px, 기본 수동 이동속도 210px/s(기본 클릭 이동 225px/s), 실제 source/native 발 충돌 원 반경 4px, 카메라 zoom=1을 유지한다. Player.tscn의 기본 캡슐 반경 15와 런타임 발 원 반경 4는 별개다. 측정 시작 장비의 속도 배율 1.1에서 실제 클릭 속도는 247.5px/s이며, 기존 장비·스킬 배율을 유지한다. 스프라이트를 축소하지 않았다. 원본 PNG의 해상도/픽셀을 재생성하거나 확대 저장하지 않는다. 확대 화면의 원본 저해상도는 남아 있다.

PR #147의 head `abc8f4398c2b9133be44e1a77c14a08cf00ca9da`를 직접 비교했다. 그 PR의 아덴 2배는 위 지역 자와 맞지 않으며, registry가 변환 전 spawn을 검사하는 문제도 있었다. 이번에는 실제 field의 변환된 spawn을 검사한다. #147의 별도 에스카로스/알비노 변경을 가져오지 않는다.

## 원본과 좌표 근거

- 실제 현재 아덴: 15,728×7,987px, 107,386,586 bytes, SHA-256 `c0af339cbc2dbba5fb2e65c3c7f01d9467507545d7b91cbb331f5bbd51128730`. main에 이미 허용·분할 저장된 원본을 재구성·검증했다. 재다운로드하지 않았다.
- 10월 18일 확보본은 같은 크기, 107,435,138 bytes, SHA `9ce95ca285f9bee72bab355c5015779122dd354fd26e73d9664a355bf9c86be3`. 두 파일 전체를 동일 판본이라고 단정하지 않는다. 기존 기란 후보 6점 주변 17×17 RGBA 패치만 각각 정확히 일치했다.
- 111.png: 17,694×7,372px, 42,449,419 bytes, SHA `f5c4549298e586d3839246d736b61b6106851af07cde8c5a21522d046ff38f87`. 실제 원본이 로컬에 존재하며 이 파일에서 청크를 만들었다.
- 오만 101~110: 각각 9,216×4,608px. 각 원본 SHA와 기존 격자 SHA를 `data/maps/oman_png_pack.json`, 원본 카탈로그 `data/maps/png_map_sources.json`에 구분해 기록한다.
- [좌표 행렬·오차·지역별 확정 여부](COORDINATES_AND_SCALE.json). 기란 후보 affine의 최대 잔차는 약 4.34 PNG px이며 **확정 고유 원본 기준점은 0개**다. 이 affine을 충돌이나 전체 아덴에 적용하지 않았다. 기존 `aden_png_alignment.json`의 보류 지역을 해제하지 않는다.
- 원본 지도 4의 2,048×1,536 통행격자·768청크·S32와 OriginalMapCoordinates의 48×24, X=(24,-12), Y=(24,12) 투영을 보존한다. PNG 월드와 서버 지형이 같은 판본이라는 증거가 부족한 구역을 강제로 맞추지 않았다. 이번 작업으로 기존 원본 통행 데이터를 재생성하지 않았다.

## 실제 물리 충돌·전경

NativePngField가 기존에는 raster solid cells만 물리화해 사선 기둥의 일부 셀 안쪽 모서리를 놓쳤다. **같은 수동 검증 polygon/circle을 실제 CollisionPolygon2D/CollisionShape2D에도 연결**했다. 격자·실제 물리·수동 검수 도형을 함께 사용하며 플레이어와 몬스터 모두 기존 CharacterBody2D를 유지한다. Godot 원/convex 꼭짓점 접촉은 낮은 FPS에서 4px 발보다 안쪽에서 수렴하는 문제가 있었다. 실제 test_move 접촉 법선으로 접선 이동을 구하고 동일 도형의 4px 발 여유를 확인한 뒤 이동한다. 이 보정은 플레이어·몬스터에 공통 적용하며 별도 가짜 장애물을 만들지 않는다. 검사는 0.1px 부동소수점 허용차만 둔다.

아덴 동쪽 나무는 기존 발 기준점의 수동 국소 원을 줄기 반경 4 원본 px로 구분하고, 수관은 전경으로 옮겼다. 원본 서버 오브젝트와 대조 확정된 줄기는 아니다. `aden_png_display_review.json`에 근거와 보류 상태를 명시했다. 분리 픽셀은 원래 ground에서 한 번 제거하며, 청크 경계에서 나뉜 전경 조각도 원본 픽셀 소유권 중복이 0인지 검사한다. 단일 합성 PNG에서 Water/Structure/Props 전체 원본 레이어가 확보되었다고 주장하지 않는다.

지배 중앙의 수정 기둥 2개와 균열은 PNG를 수동 검수한 충돌이다. 원본 111 서버 affine의 과거 중앙 오차 약 144.76px, p90 약 358.73px 때문에 그 변환을 정식 지형에 적용하지 않았다. 검수 바깥은 닫혀 있다. 흰 지도 뷰어 영역 마스크는 **알파 표시 전용**이며 색으로 충돌을 판정하지 않는다. 일부 원본 뷰어 문자/외곽 정리는 미완료다.

## 기존 게임과 저장

- 일반 Main/World/Player, 이동·변신·공격, 기존 몬스터 DB, 보스 생명/재생 시간, 자동사냥/드랍/HUD 서비스 연결을 유지한다. 전투·아이템 DB/캐릭터 리소스를 수정하지 않았다.
- 지배의 현재 MonsterCatalog 결과인 4개 일반 구역(총 24생명)과 그림 리퍼 1생명을 그대로 재배치한다. 원래 기본 JSON의 max_count와 현재 카탈로그 적용 후 값이 다른 점을 구분한다. 기존 종족·레벨·변형·타이머·보스 키, 안내자와 포털 5개의 목적지를 보존한다.
- 아덴 저장 revision 2026102002(1배), #147의 2026102003(2배)를 2026102301(6배)로 명시 이전한다. 원본 파일의 SHA 검증 백업 후 유효한 위치만 비례 변환하고, 막힌 위치는 안전 시작점으로 보낸다. 같은 파일을 두 번 확대하지 않는다. 알 수 없는 이전 단위는 저장을 보존하고 실패 처리한다.
- 보스의 이전 position/home은 revision에 따라 초기화하지만 HP·생명·재생 대기 시간은 유지한다. 다른 맵으로 가는 target_position은 아덴 배율로 바꾸지 않는다.
- 일반 오만 PNG 저장에 팩 index SHA를 남긴다. 팩 손상/누락 시 지도·진행도·진행 중 전투를 먼저 보존하고 저장 덮어쓰기를 차단한다.

## 전달 상태와 일반 실행 방법

**오만·지배 PNG는 아직 공개 Git에 추가하지 않았다.** main의 기존 공개 허용 기록은 9개 원본에 한정되고 101~111은 포함하지 않는다. 추가 공개 재배포 허용을 요청한 상태다. 허용 전에는 GitHub 코드 업데이트만으로 새 오만·지배 그림이 들어 있다고 보고하지 않는다. 이 브랜치는 개인 팩을 프로젝트에 설치한 상태에서 일반 실행으로 검사했다. 아덴 원본은 이미 main에 포함되어 있다.

개인 팩 `twilight-tower-png-20261023.zip`: 553,535,365 bytes, SHA-256 `ea864f08ce9b725037809ec35dc15621ad6e15e161fce0a3b09be18d00214976`. 360개 오만 바닥 청크+전경 6개, 지배 바닥 47개+전경 1개를 담는다. 공개 코드의 receipt가 index→manifest→414개 텍스처 SHA를 검증한다. 안전 설치기는 두 팩 모두 검증한 후 교체하고 실패하면 기존 설치를 복구한다.

```sh
python3 tools/map_restore/install_tower_png_pack.py /path/to/twilight-tower-png-20261023.zip --project /path/to/TWILIGHT
```

그 다음 Godot 4.7.2에서 해당 프로젝트의 Main.tscn을 실행한다. `--png-review` 또는 환경변수는 필요하지 않다. ZIP은 외부 실행 파일/스크립트를 설치하지 않는다. 개인 팩/실제 화면·영상은 별도 다운로드 산출물이며, 임시 개인 경로가 공개 Git 또는 main에 배포되었다는 의미가 아니다.

## 검사와 한계

실제 공식 엔진 `4.7.2.stable.official.ed1daf0bf`, Linux OpenGL llvmpipe에서 일반 실행을 검사했다. [기계 판독 검증 결과](VALIDATION.json)에 결과와 실패 이력을 기록한다. 실제 1280×720, 1560×720 Linux 창 화면과 Godot MovieWriter 동작 영상은 개인 증거 팩으로 분리한다. Android 실기기 검증은 **NOT_RUN**이며 이번에 APK 빌드 완료를 주장하지 않는다.

필요한 추가 작업은 아덴 전체/기란 마을 건물·출입구·다리의 원본 판본별 고유 기준점 3~5개 이상 확정, S32 오브젝트의 정확한 발/레이어 대조, 검수 바깥 충돌과 전경 확장, 111 서버 격자와 PNG의 같은 판본 대응표, 실제 Android 성능·터치·저장 검사다. 현재의 부분 구역을 전체 복원 완료로 표시하지 않는다.
