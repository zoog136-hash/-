## 카탈로그 연결 결과

기존 게임 카탈로그의 정확한 연결은 보관43/판매9행이었다. 적용팩이 실제 등록 대상으로 선언한 `native_item_ids`/`native_reward_item_ids`와 원본 대상의 교집합만 기존 카탈로그에 연결한다. 등록 축복 상태도 실제 드랍/활성 보상 자료와 PR238의 등록 계약을 사용한다. 원본 자동 표의 행만 보고 아이템을 만들지 않는다.

등록은 정의 조회와 정확한 SourceID 인덱스에만 영향을 준다. 인벤토리·물리 개체·재화·RNG·기존 드랍 후보 풀은 확대하지 않는다. 기존 SourceID/이름 충돌은 덮어쓰지 않는다. 각인 이름과 축복/저주 키를 혼합하지 않으며, 같은 원본ID의 Inven/직접 정의 키를 함께 소지하면 사용자가 정확한 키를 고르도록 한다.

| 범위 | 실제 식별 연결 | 원본 규칙상 처리 가능 |
|---|---:|---:|
|보관|80/84행 (+37)|79행 (기존 TestItem8271 보호)|
|판매|19/25행 (+10)|19행|

원본 보관의 축복ID 배열은 JSON에서 float로 읽히고 실제 ID는 int다. 기존 `Array.has()` 비교가 모든 보관 멤버를 제외하던 문제를 숫자 ID 비교로 수정했다. 강화 주문서137/138/6401/6411의 일반·축복·저주 키12개를 실제 등록 정의로 각각 검사했다. 원본 숫자나 파일 바이트는 변경하지 않았다. 기존 단위 기대값도 실제 `StorageAutoStore` 행에서 독립적으로 계산하도록 보강했다.

다음 네 일반 아이템은 원본 전체 `ItemClass`/한국어 설명에 실제로 정의되어 있지만 지정 적용팩에는 미등록이다. 현재 카탈로그의 유사 이름/같은 숫자ID를 원본 정의로 추정 연결하지 않았다. 후속 공급자 소비 계약과 정확한 현재 의존은 [SUPPLIER_CONTRACT.md](SUPPLIER_CONTRACT.md)를 따른다.

| ItemClassID | 원본 이름 | 남은 의존 |
|---|---|---|
|235|강화 초록 물약 (각인)|정확한 원본 카탈로그 정의·등록|
|237|고급 체력 회복제 (각인)|정확한 원본 카탈로그 정의·등록|
|313|순간이동 주문서 (각인)|정확한 원본 카탈로그 정의·등록|

이 네 행이 보관의 미연결4행이며 판매에는235/385 두 행이 포함된다. 판매의 나머지4개 가상 선택자는 앞선 자체 범주 UI로 연결되어 있고 실제 아이템으로 등록하지 않는다.8271은 TestItem 보호를 유지한다. 원본 보관84행에는 장비 정의가 없으며, 장비는 기존 자체 범주에서 실제 물리 ID·잠금/장착·남김 규칙을 유지한다.

이 브랜치에서 새로 읽기 등록한 정의는 보관/판매 소비용이다. PR238의 사용 효과 실행 코드를 병합하지 않았으므로 `source_automation_catalog_only` 표시를 붙여 이름으로 일반 강화/퀵슬롯 사용으로 빠지지 않게 보호한다. 원본 사용 효과는 미연결로 표시하고 아이템을 소비하지 않는다. 기존에 완전한 실행 모듈이 등록한 정의는 덮어쓰거나 이 표시를 추가하지 않는다.

## 실제 AUTO 실행 연결

게임 AUTO 설정에 기존 원본·정비 화면으로 가는 진입을 추가했다. 그 화면에서 기존 검증된 같은 맵 이동진, 보관/판매 단계, 대기 제한, 도착 후 AUTO 재개 모드를 선택하고 **자동 정비 켜기·대상·비용 확인**을 최종 확인한다. 켜기 자체는 아이템을 처리하거나 걷지 않는다.

실제 기존 `_run_auto_hunt()`가 수동 이동·전투 잠금·기존 상호작용 우선순위 검사를 통과한 뒤 저장된 정비를 소비한다. 메뉴 조작 중에는 시작하지 않는다. `TwilightQuestService.korean_daily_key()`의 기존 한국05시 게임 날짜를 그대로 사용하여, AUTO 중 처리할 등록 대상이 있을 때 게임 날짜당 한 번 실행한다. 별도 로컬 날짜 API·새 스케줄러·준비 브랜치는 적용하지 않았다. 이 동작은 UI/저장에 TWILIGHT 자체 모드로 명시한다.

이동 전에 기존 원자 저장으로 날짜/실행 토큰을 예약한 후, 기존 `find_world_path`와 클릭 보행을 사용한다. 원래 이동진의 맵/리비전/레벨/바닥·충돌·도착/다른 이동진 교차 검사를 재사용한다. 지도 계약이 새 버전으로 바뀌면 유효한 새 경로라도 재확인을 요구한다. 알려지지 않은 NPC 좌표를 만들지 않는다.

도착 시 기존 단일 정비 payload에서 보관→판매와 완료 토큰/날짜를 함께 저장하고 기존 이동진을 이용한다. 실제 원본 매입가는 유지한다. 현 로컬 이동진/보관 API의 비용은0이며 실행 전 화면에서 비용0과 예상 판매 수입·대상·재개 모드를 표시한다. 원본 M 귀환/NPC 비용으로 주장하지 않는다.

자동 설정은 대상·남길 수량·가격·원본 모드가 바뀌면 꺼진다. 자체 범주 변경도 같은 승인 범위를 해제한다. 선택한 스택의 도착 당시 수량을 처리하되 남길 수량을 유지하며 새 장비 ID는 추가하지 않는다. 재접속 후 AUTO를 직접 켜야 하고, 이미 진행 중이던 예약은 추가 확인 없이 재실행하지 않는다. 같은 게임 날짜의 중복 시작, 역행 시계, 예약/최종 저장 실패는 아이템·재화 차감/지급을 반복하지 않는다. 끄기는 자기 예약과 자기 경로를 해제한다. 사용자 설정의 알 수 없는 확장 필드는 보존한다.

## 검증과 남은 경계

실제 Main/OpenGL UI33검사에서 실제 적용팩 등록, 지급/RNG/드랍 풀 불변, 별도 축복 키 선택·보관, 사용 효과 보호, 원본1000단가 정산, 실제 AUTO 버튼→보행→이동진 도착→보관/판매→선택된 사냥 재개, 게임 날짜 중복 방지, 켜기/끄기/취소·비용·모드·작은 화면과 재접속을 확인했다. 격리된 테스트 소지품만 사용했다.

등록40·자동 실행32·원본652·기존 거래37·정비32·범주39검사 및 실제 Main/현재맵/저장32검사가 통과했다. 자동 실행 검사는 날짜 경계, float 복원 후 설정 지문, 예약·거래 writer 실패, 진행 중 재접속, 모드/범위 변경, 지도 리비전과 시계 역행을 검사한다. Godot4.7.2·기존 실제 맵·파생 import cache와 이전 stage 한정 설정을 유지한다. 원격 전체/수동 CI는 실행하지 않았고 `[skip ci]`를 유지한다.

native M의 스케줄 활성·정확한 NPC 도착 좌표는 계속 미연결이다. 현재 실행 증거는 검증된 TWILIGHT 로컬 이동진과 기존 가방/창고 서비스 소비자다. 미등록4개 정의, 전체 원작 동등성, 기기/실제 오디오와 원격 필수 CI는 완료로 보고하지 않는다. 자세한 최신 코드·캡처 해시와 결과는 `registry_automatic_validation.json`에 있다.
