# 원본 네 대상의 공급자 소비 계약

앞선 `534d5f2a`의 미연결235/237/313/385는 **원본 정의 부재가 아니라 지정 드랍 적용팩과 현재 소비 카탈로그의 미등록**이다. 정상 보유 원본 전체 ZIP의 `ItemClass`와 `DescData_Korean`을 직접 대조해 네 정의와 실제 표시 이름을 확인했다. 내부 `Name`을 표시 이름으로 쓰거나 일반 스택을 각인 스택으로 치환하지 않는다.

## 전체 원본 대조

기존 컴파일러로 원본 ZIP25,031,173B의 고정 SHA256·전체 CRC를 검증하고 관련9개 표 전체를 읽었다. `ItemClass`34,743행, `ItemCategory`78행, `ItemEquipSlot`3,523행, 한국어 설명298,319행, `Grade`10행, `ItemBlessCode`5행, `ConstantData`490행과 **보관84행·판매25행·대상 정의80개 전체 관계**가 이미 설치한 불변 규칙팩과 일치했다. 원본/적용팩 바이트와 원본 수치는 그대로다. 전체 ZIP의 모든 파일이 실행 모듈로 구현됐다는 뜻은 아니다.

## 소비 계약과 현재 의존

PR247 `9b2cb076e4c1ce1ab19fef040784138b89779e0d`의 `scripts/shop/source523_npc_consumables.gd`와 시작 등록/거래 코드를 읽기 전용 대조했다. 공급자는313/385의 정확한 각인 이름, `source=twilight-shop523-consumable`, 정수 `source523_shop_item_id`, 기존 소모품 종류·슬롯·등급과 명시적인 원본 스택 보존 출처로 **일반 축복ID1 스택**을 등록한다. 이 기록에는 `sourceId`가 없으므로 UI에서 공급자 ID를 표시하도록 연결했다. 기록 자체나 공급자의 사용 효과·설명은 수정하지 않는다.

보관/판매 소비자는 위 계약과 **현재 카탈로그에 유일하게 등록된 같은 기록 객체**만 읽는다. 분리된 세이브 개체의 복사 메타데이터·소지품 이름 문자열은 공급자 등록 근거가 되지 않는다. 잘못된 ID·출처·종류·등급·각인 이름, 축복/저주·분수 ID, 모순되는 추가 ID, 물리 개체 오버라이드와 중복 이름은 거부한다. 스택 키는 공급자 원문 그대로 유지하며 일반 아이템·네이티브 축복/저주 키와 합치지 않는다. 기존 인벤토리 저장 형식을 새 출처 인증 형식으로 마이그레이션하지 않는다.

PR238 `6634d3acf3eb75e513125f3fa535170e83ab70dd`의 네이티브 등록 코드도 읽기 전용 확인했다.235/237/313/385가 그 공급자의 카탈로그에 정확한 `m523:item:<ID>[:bless:<상태>]`, 표시 이름·스냅샷·ID·등급·축복 상태로 등록되면 기존 소비 경로가 읽는다. 범용 카탈로그·효과·구매/드랍 공급을 중복 구현하거나 다른 PR을 병합하지 않았다.

현재 일반 플레이의 남은 공급 의존은235/237/313/385다.313/385는 PR247 등록 소비 계약까지 연결했고235/237 및 네이티브 변형은 PR238의 실제 등록/해당 런타임을 기다린다. 공급자가 미설치이면 UI에 **원본 정의 확인 · 공급자 카탈로그 등록 대기**와 ID를 표시한다. 판매의 나머지4행은 가상 선택자이며 실제 아이템으로 만들지 않는다. 기존 자체 장비 범주 UI는 그대로다.

235/385의 확인된 원본 매입가 정책은 아직 없다. 기존 설정 가능한 자체값과 출처 표시를 유지하고 `Cost`를 검증된 매입가로 새로 주장하지 않는다.313/237는 원본 자동 매입 대상이 아니다. 네 행의 보관 허용은 축복ID1이며 다른 상태를 일반으로 바꾸지 않는다. 잠금·남길 수량·설정 지문·원자 저장과 기존 정비의 토큰/날짜/재접속 보호를 유지한다.

## 실행 검증과 전달

`inventory_supplier523_contract_test.gd`72검사는 네 네이티브 ID×축복3상태, 공급자313/385 등록/출처·중복·축복 거부, 미등록 세이브 정보 거부, 남길 수량·잠금·정산·저장 실패·재진입을 확인한다. `inventory_supplier523_main_test.gd`20검사는 실제 Main/OpenGL에 공급자 기록 fixture를 명시적으로 대입해 보관84/판매25 전체 목록, 정확한 공급자 ID 선택, 취소·보관·판매 확인창, 자체 가격, 실제 디스크 저장 실패·재로드를 확인한다. 일반 플레이 공급 완료와 구분한다.

최신 원본652·등록40·자동 실행32검사도 통과했다. 현재 Main/현재맵·저장 게이트 결과와 최종 코드/캡처 해시는 `supplier_contract_validation.json`에 기록한다. `registry_automatic_validation.json`의897검사는 이전 `534d5f2a` 시점 증거다.
