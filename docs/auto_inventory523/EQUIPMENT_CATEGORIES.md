# 523 가상 선택자와 TWILIGHT 현재 장비 ID 선택

기존 PR251·브랜치·환경에서 `14201ea7` 이후 이어간 독립 기능이다. 원본 native M 스케줄/NPC 좌표는 재조사하거나 병합하지 않는다. 원본과 개인 규칙 ZIP은 변경하지 않으며 새 팩 다운로드·업로드도 하지 않는다.

## 확인한 원본과 미확인 조건

원본 ZIP25,031,173bytes, SHA256 `d5192c3c735ff95c6b181bf2d4d77448d8b562fdb28dbd43f897fa4eae1f4832`을 읽기 전용으로 확인했다. `ItemClass`, `ConstantData`, 설명, `MerchantAutoSell`을 대조하고 나머지 비엔진 JSON의 ID 참조도 확인했다. 기존 `AUTO_INVENTORY523.md`·원본 감사·거래 코드와 공개 자료를 확인했다. APK/XAPK·외부 게임 엔진은 탐색·전송·분석하지 않았다.

| ID | 원본 표시 | 원본 ConstantData 이름 |
|---|---|---|
|45011|일반 장비|AutoSaleItemCommonTradable|
|45021|일반 장비 (각인)|AutoSaleItemCommon|
|45031|고급 장비|AutoSaleItemRareTradable|
|45041|고급 장비 (각인)|AutoSaleItemRare|

네 항목은 TestItem=true, Sprite0, Cost0이며 보관·버리기·삭제·개인거래 불가다. 원본 표의 분류 표시를 실제 소지 아이템으로 만들지 않는다. 각인 표기와 축복 상태를 같은 조건으로 해석하지 않는다. 다른 테이블의 같은 숫자 ID는 같은 ItemClass 참조로 간주하지 않았다.

원본 이름·상수와 선택→카트→확인 도움말은 확인했지만 슬롯 포함 범위, 강화/속성/감정 조건, 개별 장비별 NPC 매입 가능 집합은 확인하지 못했다. 공개 검색에서도 완전한 필터를 확인하지 못했다. [공식2024-09-25 업데이트](https://lineagem.plaync.com/board/update/view?articleId=66f31338a6acf62e167e4e3c)의 자동 판매 설정 언급은 기능 존재의 보조 근거일 뿐 장비 필터 근거로 사용하지 않는다. 다른 게임·일반 공략·무관한 거래소 자료는 적용하지 않았다.

`tools/audit_equipment_category523.py`가 원본 바이트/CRC, 네 ID의 이름·상수·가상 정의를 검증한다. 공개 감사 요약은 `equipment_category_source_audit.json`이며 원문 테이블은 Git에 복사하지 않는다.

## 사용자 흐름

메뉴 → 판매 → 원본·정비 → 네 가상 표시 중 하나 → **TWILIGHT 자체 범주 · 현재 장비 ID 직접 선택**.

1. **자체 범주 선택 사용**을 직접 켠다. 최초 사용은 꺼져 있고 선택 ID도0개다.
2. 등급, 정확한 장비 슬롯, 각인·보호 표기 보기, 강화 상한(기본+0, 자체 설정0~20)을 선택한다. 슬롯은 최초에 미선택이다. 원본 표시의 등급/각인 이름은 초기 필터 안내에만 사용한다. 사용자가 변경한 조건은 원본 조건이라고 표시하지 않는다.
3. 현재 소지한 장비의 **정확한 물리 ID**를 체크한다. 조건에 맞아도 자동 체크하지 않고 새로 습득한 같은 이름의 장비도 추가하지 않는다. 각 ID 수량은1개다.
4. 원본 ID 전용 자동 모드가 켜져 있다면, 자체 범주 사용을 위해 그 모드를 해제할지 별도로 선택해야 한다. 카트에도 해제 사실을 표시하고 최종 확인이 성공할 때만 저장한다.
5. **선택 ID·조건 저장·판매 안 함**은 미리보기와 최종 확인 후 대상 설정만 저장한다. 또는 **전체 판매 카트 확인** → 취소/최종 판매를 선택한다. 기존 별도 자동 판매 대상도 카트에 함께 표시하며 원래 남길 수량을 유지한다.

자체 범주는 한 번에 한 조건 묶음이다. 확인해 저장한 새 묶음은 이전 자체 범주 ID만 교체한다. 별도 수동 등록 ID는 덮어쓰지 않으며 해당 ID를 범주에서 선택할 수 없다. 해제는 자체 범주가 소유한 대상만 제거한다. 기존 자동 담기/로컬 정비도 등록된 정확한 ID만 사용하며 원본 M 분류의 동적 전체 선택으로 확대하지 않는다.

각인·귀속·거래제한 표기는 현재 이름/명시적 플래그를 읽는 **TWILIGHT 보기 조건**이다. 원본 IsTradable을 NPC 매입 허가로 새로 해석하지 않는다. 기존 각인·귀속·잠금·장착·퀘스트·거래 보호를 유지하므로 각인 분류에 보호 항목이 보여도 판매는 거절한다. 가격은 기존 TWILIGHT 등급/해당 ID 강화 기준이며 확인된 원본 매입가라고 표시하지 않는다.

## 저장·검증 경계

선택은 기존 `inventory_automation` version1의 선택적 `equipment_category` 필드에 들어간다. 이전 저장에는 필드가 없어도 정상이다. 필드의 버전·타입·등급·슬롯·상한·중복 ID·지문이 잘못되면 실제 로드를 거절하고 디스크를 보호한다. 새 범주를 해제해도 알 수 없는 확장 필드와 별도 등록 규칙은 보존한다.

미리보기는 상태를 바꾸지 않는다. 조건/카트/아이템 지문/가격/잠금 변경은 다시 확인해야 하며, 설정 활성화와 최종 판매 모두 원자 writer 성공 전에 공개하지 않는다. 범주 변경은 이전 정비 예약을 해제한다. 실제 판매 시 소진된 ID와 범주 선택을 같은 payload에서 제거해 재접속/중복 확인으로 재지급하지 않는다. 개별 장비의 레벨·속성·커스텀 기록을 다른 ID로 대체하지 않는다.

최종 결과는 `equipment_category_validation.json`에 기록한다. 단위39검사와 실제 Main/OpenGL UI30검사에서 현재 실제 도감 장비와 물리 ID를 사용한다. UI에서는 가상 항목 진입, 터치 선택, 취소, 별도 모드 해제 동의, 실제 설정/판매 writer 실패 시 라이브·디스크 보존, 잠금 변경, 재접속, 새 장비 미선택, 수량/가격, 별도 남김 규칙 유지, 작은 화면, 손상 namespace 보호를 검사한다. 실제 사용자 세이브는 사용하지 않는다.

환경은 기존 Godot4.7.2·현재 실제 맵·동일 파생 import cache를 유지한다. 추가 캡처/감사 로그는 LOCAL_ONLY이고 새 외부 업로드는 하지 않는다. 기존 원본 보존/적용 규칙 ZIP의 Drive ID와 바이트·SHA·비공유 권한은 `delivery.json` 그대로다. 원격 CI는 `[skip ci]`, 수동 CI·다른 PR/main 병합은 하지 않는다.
