## 재현한 문제

1. `tools/test_project.py`가 실패 RESULT와 `_OK`를 같이 받으면 통과시켰다. 실제 subprocess로 `CASE_OK` + `CASE_RESULT {"failures":["reproduced"]}`를 출력하면 기존 실행기는 exit 0, passed 3/3을 기록했다.
2. `CASE_FAILED`와 `_OK`, 잘못된 JSON RESULT와 `_OK`도 같은 거짓 통과를 만들었다. SKIP과 실패 RESULT 조합은 건너뜀으로 잘못 분류했다. 단순 문자열 우선순위를 오류 우선 판정으로 바꿨다.
3. 없는 Godot 경로는 FileNotFoundError로 중단되어 summary.json을 남기지 않았다. 이제 import 실패와 나머지 미실행 항목을 기록한다. 원시 로그의 비 UTF-8 바이트도 전체 증거를 버리지 않고 대체 문자로 보존한다.
4. 제한 시간이 지난 부모만 종료되고 자식 프로세스는 계속 실행됐다. Linux 실제 subprocess 검사에서 기존 자식이 살아 있는 상태(S)로 남는 것을 확인했다. 새 세션의 프로세스 그룹을 종료하여 같은 그룹 자식까지 정리한다. 이미 분리된 새 세션의 자식까지 모두 추적한다고 주장하지 않는다.
5. `original_turn_undead_rewards_test.gd`가 삭제된 `world.quest_kills`를 대입·조회했다. 세 참조를 제거하고 경험치·아데나·실제 사망·바닥 드랍·중복 보상 차단·저장/로드 검사는 그대로 보존했다. 퀘스트 기능을 복구하지 않았다.

## 실행한 검증

Python 실행기 검사는 실제 Python subprocess와 제어된 출력 프로그램을 사용한다. 이 프로그램은 판정/종료/저장 경로 격리의 테스트 더블이며 Godot 엔진 또는 게임 테스트를 대신하는 것이 아니다.

- 기준 실행기 blob `6e3d64506bafa182c31ff40eeb83175f224c3a55`와 받은 소스의 Git blob 해시 일치 확인.
- 거짓 통과/거짓 SKIP 4사례 및 없는 실행 파일의 증거 누락을 수정 전 재현.
- 수정 전 자식 프로세스 잔존 검사 FAIL, 수정 후 같은 검사 PASS.
- 수정 후 실행기 회귀 검사 16개 PASS. 컨테이너 도구의 실행 제한 때문에 8개씩 두 묶음으로 실행했으며 전체 Godot suite를 실행한 숫자가 아니다.
- 정상 통과, 실제 SKIP, 비정상 종료, 실패 RESULT, malformed RESULT, 성공 마커 부재, import 중단, 없는 실행 파일, 비 UTF-8 로그, 매 실행별 임시 저장 경로, timeout 부분 로그, 자식 프로세스 종료 포함.
- 수정된 턴 언데드 검사의 check 호출 수 21개 보존(함수 정의 포함). 실제 엔진 통과는 미확인.
