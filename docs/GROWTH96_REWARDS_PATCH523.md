# 96레벨 성장 보상과 유일의 증표 등록

Main의 전체 메뉴에서 **96레벨 보상·증표**를 엽니다. 처음에는 개인 보관 중인 검증된 523 정의 ZIP을 선택하고 설치를 확인합니다. 정의 파일을 읽거나 설치하는 것만으로 아이템이나 수령 기록을 만들지 않습니다. 원본 파일, 상세 변환 감사, 아트와 사용자 저장은 공개 Git에 포함하지 않습니다.

성장 지점 71개와 보상 연결 269개를 전부 읽습니다. 이 중 96레벨 10~90%의 9개 지점에는 보상 36개가 있습니다. 각 지점은 변신·마법인형·성물 영웅 카드 상자와 유일의 증표 I를 각각 3개씩 지급합니다. 실제 레벨과 해당 레벨의 경험치 비율을 확인하며, 선택과 확인을 거쳐 수령합니다. 높은 레벨에서는 미수령 지점의 보상을 받을 수 있습니다.

보상 선언의 버전은 0·1·2입니다. 상수 2와 같은 행만 고르면 신규 96레벨의 Version 0이 사라집니다. TWILIGHT는 지점별 최신 가용 선언을 기본 정책으로 사용합니다. 메뉴에서 버전 상한 0·1·2 또는 수령 보류를 선택할 수 있습니다. 이는 서버의 미확정 버전 선택 규칙을 복원했다는 뜻이 아닙니다. 기존 영수증이 있는 지점은 그 버전을 유지하며, 중복 수령과 서로 충돌하는 버전 기록의 추가 수령을 거부합니다. 기존 기록을 초기화하지 않습니다.

유일의 증표 I는 서로 다른 등록 요건 63개를 거쳐 컬렉션 8개와 보너스 슬롯 16개에 연결됩니다. 등록 한 번마다 실제 보유 증표 1개를 소비하며, 해당 컬렉션의 모든 요건을 등록해야 효과를 얻습니다. 필요한 증표 수는 컬렉션별로 3·5·6·7·9·9·12·12개입니다. 96레벨의 9개 지점에서 얻는 증표는 총 27개이므로 모든 선택지의 63개 등록을 자동으로 완성하지 않습니다. 등록은 96레벨부터 가능하며, 레벨이 낮아지면 기록을 유지하고 효과만 비활성화합니다.

고정 명중 3종과 치명타 대미지 3종을 기존 전투 계산에 연결합니다. PVP 추가 대미지 3종에는 기존 TWILIGHT의 오프라인 PVE 전환 정책을 적용합니다. 나머지 비율 효과 7개는 원문 수치와 대상을 보존하고 기본 실행에서는 보류합니다. 사용자가 **TWILIGHT 자체 추정 추가**를 확인하면 기존 문양 전투 모델의 대미지 감소 효율과 채널별 무시 계산으로 실행합니다. 서로 다른 PVP 비율 보너스 두 개는 각각 보존합니다. 대상군 14의 구성과 원작 공식은 확인되지 않았으므로, 상태 이상 적중 증폭은 이 선택에서만 현재 기절·침묵·홀드·공포 명중의 5% 배율로 계산합니다. 이 모델은 원작 서버 공식이 아닙니다.

보상 아이템 17종은 원본 ID를 가진 별도의 보유 키를 사용합니다. 같은 이름의 기존 Inven 아이템과 합치지 않습니다. 원본의 거래·창고·삭제·드롭·무게·사용 레벨·스택 제한 값은 유지합니다. 현재 원본의 창고 보관 금지를 실제 창고 경로와 목록에 적용하고, 무게 0을 일반 소모품의 기본 무게로 바꾸지 않습니다. 사용자가 잠근 증표는 등록에 소비하지 않습니다. 스택 수량은 기존 인벤토리의 총 보유량 표현을 사용하며, 새 슬롯 제한이나 스택 서비스를 만들지 않습니다.

원문의 다른 공급·소비 참조도 감사에 남깁니다. 성장 보상 외의 보상 공급, 아이템 보너스, 제작 입출력, 기존 증표 컬렉션, 가방 출력과 몬스터 드롭의 형식화된 아이템 참조를 대조합니다. 이 기능이 다른 증표의 컬렉션이나 제작 서비스를 새로 구현한다는 뜻은 아닙니다. 원본 카드 뽑기 목록은 비어 있고, 기존 카드 공급 계약의 6개 뽑기권은 이번 상자와 다른 품목입니다. 동일성을 입증하지 않은 상자를 기존 뽑기권으로 바꾸거나 새 카드 공급 서비스를 만들지 않습니다. 따라서 상자는 실제 보유 아이템으로 저장하되 개봉하지 않습니다. 기존 카드 획득·등록과 관련 PR의 공급 계약은 보존합니다.

수령·등록·정책 변경은 재확인한 요청과 revision으로 계산하고, 기존 전체 저장의 원자 쓰기가 성공한 뒤 보유량과 효과를 적용합니다. 취소, 부족, 중복, 잠금, 오래된 요청과 쓰기 실패는 보유량을 변경하지 않습니다. 손상된 저장 구조와 원본에 맞지 않는 영수증은 저장 덮어쓰기를 차단합니다. 정의를 다시 설치해도 손상된 저장을 복구했다고 표시하지 않습니다. 기존 퀘스트와 즉시 완료 기능, 카드 보유, 장비와 다른 저장 영역은 유지합니다.

## 검증 방법

Godot 4.7.2와 현재 source-map 팩이 필요합니다. 원본 ZIP은 바이트 수, SHA-256과 모든 ZIP 항목의 CRC를 검사합니다. 같은 원본을 다시 다운로드하거나 아트를 생성하지 않습니다. 전용 심화 보고서는 이번 환경에서 받지 못했으며 원문을 직접 대조했습니다.

```bash
python3 tools/audit_growth96_source.py --source /private/patch523.zip --output /private/growth-audit.json
python3 tools/ci_core.py --root . --stage /scratch/growth-main --godot /path/to/godot-4.7.2 --logs /scratch/growth-logs --prepare-only
TWILIGHT_SOURCE_MAP_PACK=/private/current-map python3 tools/test_growth96.py --source /private/patch523.zip --project /scratch/growth-main --godot /path/to/godot-4.7.2 --logs /scratch/growth-checks
```

`--render`는 현재 디스플레이에서 실제 OpenGL 화면을 캡처합니다. 모든 검사는 명시적인 격리 프로필을 사용하며 사용자 저장을 읽지 않습니다. 전체 269개 보상은 버전별 실행으로, 63개 등록과 16개 효과는 전수 규칙 검사로 확인합니다. 63개를 한 번에 등록하는 검사에는 별도로 표시한 합성 보유량을 사용합니다. 실제 Main 검사는 달성 조건 fixture에서 정상 UI로 받은 증표 3개만 소비합니다. 정상 메뉴, 설치 확인·취소, 수령·등록 확인·취소, 부족·중복·잠금, 쓰기 실패 원복, 손상 저장 보호, 기존 상태 보존, 실제 전투 소비자와 별도 프로세스 재접속을 검사합니다. 전체 원문 감사와 실제 실행 검사는 서로 다른 증거입니다.

Android 실기, 원작 서버 공식의 동등성, 미확정 상자 개봉과 다른 증표 컬렉션은 이 검사의 완료 범위가 아닙니다. 전체 원격 CI를 수동 실행하거나 다른 PR을 병합하지 않습니다.

등록 시 아이템 소비와 컬렉션 완성 보너스는 [공식 아이템 컬렉션 안내](https://lineagem.plaync.com/guidebook/view?title=%EC%95%84%EC%9D%B4%ED%85%9C+%EC%BB%AC%EB%A0%89%EC%85%98), 신규 레벨 보상은 [공식 업데이트 안내](https://lineagem.plaync.com/board/update/view?articleId=6ab2d738fa34c1011d6278ab)와 대조했습니다. 해당 안내는 미공개 서버 공식을 제공하지 않습니다.
