# 523 무기 숙련 연결 — Draft

기준 main: `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`. 작업 시작 시 열린 PR 218/222/224/228/230/231/232와 대조했고 숙련 구현은 없었다. 다른 PR을 병합하지 않는다.

## 실제 연결

- Main의 `weapon_mastery` 서비스와 메뉴의 **무기 숙련** 화면. 무기 선택, 표 기준 성장 단계/다음 누적점수, 보유/적용 옵션, 원본 재설정·포인트 구매 비용, 현재 직업의 목표 무기별 옵션 미리보기를 표시한다.
- 15무기/120성장행/540옵션/36전환그룹을 참조한다. ActualType→BaseType으로 정규화하며 임의의 비슷한 무기 매핑은 없다.
- 숙련치는 정수 문자열로 저장하고 signed64 범위를 검사한다. 지급은 `credit_confirmed_points(actual_weapon, amount_string, receipt_id)`로 기존 Main 원자적 저장을 거친다. 원본에 없는 처치당 숙련치 환산/지급률은 추가하지 않았다.
- 색상 네 슬롯과 BonusView Slot1/2를 독립적으로 보존한다. 소유 색상 잠금 버튼은 실제 세이브를 갱신한다. 레벨 미달의 보유 옵션은 유지하지만 능력치에는 적용하지 않는다. 잠금도 현재 레벨로 차단하지 않는다.
- 근거리/원거리/마법 대미지, 근거리/원거리 명중, HP/MP, MR의 정확한 기존 소비자에만 적용한다. PvP를 PvE로 변환하지 않으며 미확정 퍼센트/리덕션/매칭 활성 효과는 적용하지 않는다.
- 점수 지급/잠금/확인된 재설정·클래스 교체 결과는 plan→stale 검사→Main 저장→성공 시 UI 갱신 순서로 처리한다. 저장 실패는 숙련 상태와 기존 파일을 보존한다. 지급/서비스 영수증 재사용을 거부한다.
- 팩 없이도 기존 게임은 시작한다. 숙련 세이브 네임스페이스는 그대로 보존하며 비활성화한다. 팩 사용 중 손상된 숙련 상태를 불러오면 기존 상태와 파일을 보호한다.

## 교체 경계

`plan_class_change`는 원본 29개 직업/목표무기 목록을 검사한다. 옵션은 획득한 레벨까지의 prefix로 선택하며 목표 기존 옵션을 교체한다. 그룹과 색상/수치는 유지하고 목표무기 행에서 BonusID/BonusType을 새로 조회하며 잠금은 초기화한다. 원래 숙련치/옵션은 비운다. 목표 레벨보다 높은 옵션은 계속 소유한다.

서버가 확정한 도착 누적점수를 명시적으로 받아야 한다. 단순 레벨 복사나 미확정 상한·반올림을 넣지 않는다. 옵션 미선택 시 목표의 기존 옵션이 있는 경로는 처리 근거가 부족해 거부한다. 클래스 교체와 독립 숙련 서비스의 비용표를 합치지 않는다. 추가비용 재화를 Gem으로 추정하지 않는다.

`server_choice`/`plan_server_import`는 서비스가 확정한 비교 결과를 입력받는다. 높은 상태 하나만 유지하며 동률은 출발 상태를 선택한다. 점수를 합산하지 않는다. 두 서버 저장의 원자적 이전은 로컬 Main에서 실행하지 않는다.

## 미완료 실행 경로와 화면 표시

- 일반 플레이에서 자동으로 숙련치를 얻는 환산식/획득 조건은 미확정이다. 현재는 확인된 원시점수 지급 API만 연결되어 있다.
- 실제 인벤토리의 원본 숙련 재료 매핑과 구매 횟수 초기화 규약이 없어 **포인트 구매** 버튼은 사유와 함께 비활성화한다.
- 네 색상 슬롯과 옵션 Slot1/2의 결합 및 잠금별 재추첨 범위가 미확정이므로 **재설정** 버튼은 비활성화한다. 무잠금의 확인된 결과 적용 API/원본 비용 견적은 있다. 잠금 재설정은 거부한다.
- 서버 도착점수 환산·추가비용 재화·실제 온라인 서비스 결제가 미확정이므로 **교체 실행** 버튼은 비활성화한다. 목표 옵션 미리보기와 확인된 결과 적용 API는 연결했다.
- 색상 매칭 보너스는 목표 Step+Grade로 조회하지만, 실제 활성 조건과 중첩이 미확정이므로 전투에 적용하지 않는다.
- 원작 UI/아트 동등성 및 Android 실기기 검증은 수행하지 않았다. 이 PR은 무기 숙련 전체 플레이 완료가 아니다.

Library 정식 materialize를 통해 소비 환경의 실제 바이트/전체 ZIP CRC를 확인했다. 접근 거부 우회나 외부 원본의 공개 Git 커밋은 하지 않았다.

원본 표/리소스는 PR에 넣지 않는다. 제작기는 source ZIP SHA를 고정하고 CRC·행 고유성·성장 임계치·36×15 동일 수치/확률 대응·버킷 확률 합계·29목적지를 검증한다. 출력은 저장소 밖에 원자적으로 게시한다. 별도 팩의 각 표에는 원본 member/SHA/행 수를 남긴다. 공개 리소스 장부를 승격하지 않는다.
