## 실제 게임에서 가능한 작업

메뉴 → **무기 숙련**에서 무기를 선택한다. 누적점수/원본 임계치 기준 레벨, 보유·적용 옵션, 종류·수치 네 슬롯과 색상 잠금, 실제 비용과 보유 재화를 표시한다. 장착 무기와 달성 레벨에 맞는 옵션만 적용한다. 교체로 현재 레벨보다 높은 옵션을 소유해도 삭제하지 않는다.

1. **일반 명중 성장**: 기존 일반 공격의 명중 판정 이후 장착 무기에 점수를 지급한다. 빗나감·스킬·추가 타격·미지원/맨손 공격은 지급하지 않는다. 투사체 발사 후 무기가 바뀌면 잘못된 무기에 지급하지 않는다. 기존 impact 중복 방지와 조용한 저장 주기를 사용하며, 매 명중마다 금융 영수증을 만들지 않는다. 명중당 점수는 아래 자체 설정이다.
2. **숙련치 구매**: 기존 Inven 도감의 ID117544·이름·재료 종류를 함께 검증한 상급 축복의 가루400개를 실제 차감해 선택 무기에250,000점을 지급한다. 원본 Count1~5 비용행과 무기 통합 하루5회 제한을 사용한다. 실제 잠긴 재료·개체 소유권이 모호한 스택은 거부한다. 일일 시각은 아래 자체 설정이다. 총 구매 수량과 금융 영수증을 보존하며 날짜 역행은 새 주기를 만들지 않는다. 이전 첫 주기 영수증은 로드 시 현재 주기에 연결하고 이후 일반 저장에 보존한다.
3. **레벨 옵션 획득**: 달성한 미보유 레벨의 두 옵션 수치와 네 색상을 원본 가중치로 추첨해 저장한다. 네 필드는 옵션1 종류/수치, 옵션2 종류/수치다. 동일 레벨 재획득은 거부한다. 일부만 남은 구형 보유 상태는 자동으로 덮어쓰지 않는다. 최초 비용은 아래 자체 설정이다.
4. **옵션 재설정**: 모든 보유 레벨의 잠기지 않은 필드를 변경한다. 종류 필드의 BonusType은 원본240개 bucket 모두 고정이며 색상만 변한다. 수치 필드는 대응 Slot1/2의 옵션 그룹과 자기 색상을 재추첨한다. 수치 필드 잠금은 그룹·수치·색상을 함께 유지한다. 종류 필드 잠금은 그 색상을 유지한다. 잠금0개는 원본 아데나1,000,000, 잠금이 있으면 원본 LockSlotCount에 대응하는 다이아 비용을 차감한다. 티켓 대체 지불은 구현하지 않았다. 전체 잠금은 거부한다. 부분 보유가 섞이면 기본 자체 정책은 그 레벨을 그대로 보존하고 완전한 레벨만 재설정한다. 이때 실제 변경 범위의 잠금 수로 원본 비용행을 조회한다. 엄격한 block_weapon 모드도 지원한다. 현재 레벨보다 높은 정상 보유 옵션은 보존하고 변경할 수 있다.
5. **매칭 보너스**: 정상 보유한 레벨의 네 색상이 같고 숙련 레벨을 만족하면 원본 Step+Grade 보너스를 적용한다. 같은 BonusID라도 서로 다른 달성 레벨이면 각각 한 번씩 더한다. 그린 두 레벨은 HP40, 그린/블루 한 레벨씩은 HP20/MP20이 된다. 부분 보유·레벨 미달·다른 장착 무기는 적용하지 않는다. 재설정/교체/재접속 시 원래 색상과 옵션에서 다시 계산하며 별도의 중복 지급 상태를 저장하지 않는다.
6. **로컬 숙련 교체**: 현재 직업의 원본 허용 목표와 실제 보유한 연속1~N레벨 prefix를 선택한다. 원시 누적 정수점수를 정확히 합산한다. 그룹·색상·수치를 유지하고 목표 무기의 BonusID/BonusType을 새로 조회하며 잠금은 초기화한다. 출발 점수·옵션을 비우고 목표 옵션을 선택 범위로 대체한다. 실제 내부 다이아 기본800 + 독립 숙련 교체 레벨 비용을 차감한다. 공식 상품 안내에 맞춰 반복 실행할 수 있다. 교체마다 직전 세이브의 SHA와 같은 독립 백업을 먼저 보존한다. 점수 전용 교체의 기존 목표 옵션 처리만 자체 정책으로 구분한다. 기본 preserve_existing은 목표의 옵션·색상·잠금을 모두 보존하고 출발 점수/옵션을 비우며 실제 내부 기본 비용만 차감한다. 확인창과 거래 영수증에 자체 동작을 명시한다. clear_existing 또는 block_unverified로 설정할 수 있다.

7. **부분 옵션 복구**: 유효한 기존 부분 저장은 로드할 때 바꾸지 않는다. 이미 한 옵션과 네 색상이 있는 레벨에서 누락한 다른 옵션의 원본 결과가 단 하나의100% 행으로 확정될 때만 명시적 자체 복구를 제공한다. 알려진 값·색상·잠금·불투명 메타데이터·점수·RNG는 그대로 보존하며 재추첨하지 않는다. 변동값/색상/잠금이나 통째로 없는 레벨은 추정하지 않는다. 복구 전에 기존 파일 SHA와 같은 별도 백업을 만들고 자체 복구 영수증을 남긴다. 기본0아데나이며 미리보기 전용 정책을 선택할 수 있다.
8. **단독플레이 전투 적용**: 기존 TWILIGHT의 PvP 수치→PvE, 정수 리덕션 무시→추가 피해 규칙을 숙련의 같은 타입 소비자에 연결한다. 원본 수치와 이름은 유지하고 UI에 변환 규칙을 붙인다. 퍼센트 무시는 기존 피해 증폭 소비자를 같은 공격 종류에만 적용하는 자체 정책이다. 기존 합산·0~300% 상한·반올림·대상 수정·흡수 순서를 유지한다. 일반 성공 피해 경로를 우회하는 직접 발동 피해는 기존 범위를 유지한다. 표시만 하는 모드도 선택할 수 있다.

일반 진행은 기존 짧은 지연 저장을 사용한다. 구매·획득·잠금·재설정·교체·복구는 실제 HUD 확인/이벤트 → 재검사 → 자원·난수·상태를 함께 기존 Main 원자 저장 → 화면·능력치 갱신으로 처리한다. 확인창 중 일반 명중으로 추가된 점수는 최신 상태에서 계획을 다시 만들어 보존한다. 다른 구매·잠금·옵션 변경이 있으면 오래된 확인은 거부한다. 취소·쓰기 전 실패는 재화·상태·난수·기존 파일을 보존한다. 쓰기 뒤 후속 오류는 실제 대상 payload와 대조해 이미 저장된 결과를 반영하고, 재로드 전 재실행을 막는다.

## 정확한 남은 범위

- 매칭 보너스의 HP/MP/MR·무기별 피해와 숙련의 PvP/정수 무시를 기존 단독플레이 소비자에 연결했다. 퍼센트 무시의 실제 원작 계산식은 미확정이라 기존 증폭 소비자에 연결한 자체 정책으로 구분한다. 원작 전투 수식 동등성을 주장하지 않는다.
- 점수 전용 교체의 목표 옵션 처리는 공식 문구가 명시하지 않아 자체 정책이다. 기본값은 기존 목표 보존이며 원본 행/확정 비용/사용자 규칙은 바꾸지 않는다. 자체 정책을 원작 복원 완료로 주장하지 않는다.
- 독립 상품의 기간 경계가 불분명한 시작/종료 연도, 월드 던전·서버 선택 대기·카드 확인 진행 상태는 거부한다. 실제 온라인 상품·계정 서버 동등성을 주장하지 않는다.
- 점수는 signed64 정수 문자열로 보존하고 overflow를 거부한다. 서버 이전은 별도 높은 상태 선택/동률 출발 우선 계획이며, 비교를 확인한 서비스 호출만 받는다. 로컬 단독 저장으로 두 서버 이전을 실행하지 않는다.
- 같은 저장의 클래스 변경은 숙련 네임스페이스를 유지한다. base_save_path는 일반/원본맵/성장 lab/full-card 시험 데이터를 의도적으로 분리한다. 계정·서버 식별자와 공유 권한 모델이 없으므로 이들을 임의로 같은 계정으로 합치지 않았다. 독립 세이브 간 공유와 실제 두 서버 이전은 구현하지 않았다. 최신 공식 서버 이전의 높은 값/동률 출발 우선·낮은 구매 시도 횟수 유지 규칙은 조사 기록에 구분한다.
- 원본 팩이 없으면 기능을 끄고 저장의 원래 네임스페이스를 그대로 보존한다. 손상된 상태는 덮어쓰기를 막고 복구 기능으로 우회하지 않는다. 원본만으로 확정할 수 없는 부분 값·색상·잠금은 보존하고 재추첨/복구를 거부한다. 완전한 레벨은 독립적으로 계속 사용할 수 있다.
- Android·전체 장시간 사냥·원작 UI/서버 동등성은 미검증이다. 숙련 전체 복원 완료를 주장하지 않는다.

## 별도 팩과 재현

두 입력을 Library 정식 materialize한 실제 바이트·SHA와 ZIP CRC로 확인했다. 이 변경에서 제작기를 강화해 다시 만든 결과도 같은 실행 팩 SHA다. 원본 행·픽셀을 공개하지 않고 기존 Library 파일 version1을 그대로 사용한다.

| 입력 | 바이트 | SHA256 |
| --- | ---: | --- |
| 누적523 content | 25,031,173 | `d5192c3c735ff95c6b181bf2d4d77448d8b562fdb28dbd43f897fa4eae1f4832` |
| 전환 심층 자료 | 122,889 | `bf2cf2a42dc7e9fdae9dcacd5b3fc45a1d8162c8b66a358f3a1fb2232b89be04` |
| 실행 숙련 팩 | 235,676 | `671fd9b307182e0ed8b8789124ea5710aa766d3de20c74df381455abf2bd9d6b` |

- [현재 실제 적용팩 JSON](https://drive.google.com/file/d/1bEKoW1Mn0EkSWebc51XTlyl_UCZpy6F5/view?usp=drivesdk): private Drive의 [PR234 적용팩 폴더](https://drive.google.com/drive/folders/1Kyz1MdusaL6Iz37dD1WhbHscbQD2TWns)에 보관한다. 파일명은 mastery523.operations.private.v1.json이며 위235,676B/SHA와 같다. 현재 코드가 쓰는 모든 숙련 표는 이 정확한 파일에 이미 있으므로 코드 변경 때문에 다른 팩 버전을 만들지 않았다.
- [원본 보존 ZIP](https://drive.google.com/file/d/1EJGI2VV4u4P2yNlrMAlp0H2U28jjUH6K/view?usp=drivesdk): 별도의02_원본소스_보존 폴더에 이미 있던25,031,173B 사본을 재사용했다. 새로 중복 업로드하지 않았다. 제작기는 이 ZIP을 입력으로 사용한다.
- 새 소비 폴더로 두 파일을 각각 정식 Drive raw fetch하여 실제 SHA를 대조했다. 원본 ZIP은1075개 member CRC가 통과했고, 적용 JSON은 schema/해시가 통과했다. 새로 받은 ZIP으로 재빌드한 결과도 적용 JSON과 같은SHA다.
- 실제 적용 폴더는 /workspace/mastery-drive-consumer/application 이며 생산 CLI의 두 인자로 지정한다. 이 Drive 다운로드 사본으로 실제 Main 자동 로드·메뉴·저장·재접속8검사가 통과했다. 코드/기존 실제 리소스 staging과 현재 맵 팩은 같은 환경의 기존 검증물을 재사용했으므로 새 머신 전체 복원이나 전체 게임 리소스 설치로 계산하지 않는다.
- Drive 폴더/파일은 owner만 있는 비공유 상태를 읽어 확인했고 공유 권한을 바꾸지 않았다. Drive 보관이 자동 게임 적용은 아니다. 원본 백업과 적용 파일, 이전 Library version1 보존, 로컬 증거의 상태·링크·해시는 mastery523_delivery.json에 구분한다. 별도 감사자료/캡처/엔진/APK/XAPK를 새로 업로드하지 않았다.
- [이전 Library 보존 사본 version1](https://chatgpt.com/api/library/files/libfile_944097ef82488191a07a44e05d4873fd/download)도 같은235,676B/SHA로 보존되었다. 이번 최신 인계 검증은 새 Drive 다운로드에 근거한다. 공개 리소스 장부를 전체 전달 완료로 승격하지 않았다.

python3 tools/mastery/build_mastery523_pack.py /private/content523.zip /private/mastery523.operations.private.v1.json
godot --path . -- --mastery523-pack=/private/mastery523.operations.private.v1.json --mastery523-sha=671fd9b307182e0ed8b8789124ea5710aa766d3de20c74df381455abf2bd9d6b
