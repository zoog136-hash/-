# TWILIGHT 스킬 제외 옵션 구현·보류 감사 (2026-10-08)

## 기준 / 안전장치
- 이 브랜치는 `codex/non-skill-options-20261008`이고 PR #9 위에 쌓인다. **main·아스트라 맵 수정 없음**.
- 이전 옵션 PR #6(장비) → #7(도감) → #8(원작 기본옵션) → #9(HP/MP 발동) 이후 순차 통합을 목표로 한다.
- 신규 고유 발동(디스펠, 홀드, 집행 등)·각성·컬렉션·축복의 전투 효과는 사용자 지시로 보류한다.
- 각인 분류는 유지, 저주·손상/비손상은 게임 내부 옵션 설명 및 UI에서 제거한다.
- 과거 PvP 옵션 수치는 성물/인형/소모품에서 PvE로 전환한다. 원작 출처 데이터는 별도 PR/문서에서 복구 가능하다.

## 코드 반영한 것
1. **MP 증가** — `지식의 티셔츠` 등의 `MP +N` / `Max MP +N` 및 typed `mpFlat`을 _effective_max_mp()에 적용하고, 동일 typed·설명 값 중복 적용 방지. UI와 저장 후 장착 상태도 반영.
2. **강화 개체 분리** — `item_instances`에 `unique_id, name, level` 저장. 동일 아이템의 각 물리 복사본이 다른 강화 단계 보유 가능. 강화 UI에서 ID별 선택/성공·실패·파괴를 개체별 처리. 이전 `enhancement_levels` 저장 데이터는 최초 변환 시 유지하며 새 저장은 개별 `item_instances`에 기록.
3. **강화 능력치** — NC 공식 기본 무기 +1당 타격 +1 / 명중 +1, +10부터 타격 추가 증가폭 +2; 일반 방어구 +1당 AC -1. 검증된 반지·룸티스 귀걸이의 강화표는 종류별 분리. 모르는 장신구는 일괄 가상 스탯을 부여하지 않으며 정확한 개별 강화표 수집 대기.
4. **리덕션 무시** — 데이터상 `대미지 리덕션 무시` 수치는 방어 무시 판정 대신 동량 **추가 피해**로 적용. typed 및 설명에 중복 기재된 경우 중복 합산 방지.
5. **대형/소형** — 몬스터 명시 크기 필드가 있으면 우선 사용; 없으면 신체 유형/몹 이름 기반 분류(거대·골렘·드래곤 등), **보스여서 무조건 대형인 임시 로직 삭제**. 무기 21/13 같은 수치는 목표 크기 판정에 맞게 공격 계산에 반영.
6. **무게** — DB별 무게와 인벤 수량을 반영, CON·인형과 강화 반지의 소지 한도 증가 반영, 과적 시 속도 패널티. 캐릭터 UI의 `current_weight`/`max_weight` 키를 엔진과 맞춰 게이지 표시. 100% 초과 시 게이지는 꽉 차고 표시 수치는 실제 비율.
7. **PVP→PVE** — 보존된 PVP 리덕션/근거리 대미지/소모품 피해 감소를 PVE 계산으로 이동. 현재 PvP 전투 시스템 없음.
8. **저주/무기 손상** — 게임 로드 시 게임 DB·상세도감의 설명에서 손상 옵션/저주 표시 삭제. 각인·축복 상태는 유지(축복 특수효과는 아직 적용하지 않음).

**주의:** 상세 도감 `data/catalog_v19.json`에는 아이템이 2,129개 있으나 개별 특수 소비품의 구조화된 발동 필드/작동 검증은 완료되지 않았다. 위 분류 중 일부는 실제 도감에 해당 소모품이 있는지 추가 매칭이 필요하다. 지원되는 것은 주로 `heal`과 `지속 시간` 등 정확히 파싱 가능한 설명뿐이며, **소모품 전체 구현 완료로 표시하면 안 된다.**

## 기타 아직 미완료
- 변신 413, 마법인형 166, 성물 144 및 장비 2,129개 상세 DB에 대한 **원작 개별 옵션 전수 대조**.
- 인형·성물의 **고유 발동 주문 효과** (사용자 보류).
- 일부 이름/종류에 맞는 **장신구 강화표, 특수 방어구 MR 증가, 축복 강화 효과** 확인/구현.
- 크기 명시 필드가 없는 일부 로컬 생성 몬스터는 **신체명 휴리스틱**이므로 원작 몬스터 도감의 소형/대형 크기 전수 검증은 아직 필요하다.
- 저장 호환은 단위 테스트 검증 범위. 오래된 사용자 세이브의 모든 예외/복수 슬롯 실데이터 장기 플레이 검증은 별도.
- **각성·컬렉션·축복 부여 전투 효과** (사용자 보류).
- 주의: 현재 작업 PR은 main 미병합. 기능 브랜치 검증 성공이 배포 완료를 의미하지 않는다.
