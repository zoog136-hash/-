# TWILIGHT — 모든 장비 강화의 개체별 적용

기준: `main` da5141bb... 위의 소모품 PR #11 기반 독립 브랜치 `feature/per-instance-all-enchantments-20261008`.

## 저장 원칙

- 이전 `inventory[item_name] = count`는 기존 드랍 및 상점 호환을 위한 **수량**으로 유지.
- 실물 장비 하나당 `item_instances[instance_id] = { name, level, element, element_level }` 하나를 부여. 동명 장비도 `instance_id`가 다름.
- 도감에 없는 동적 생성 장비는 `record` 복사본도 개체 데이터에 저장하여 저장/재시작 후 소실되지 않도록 처리.
- `next_item_instance_id`는 자동 증가, 장착/강화/저장 시 변경되지 않음. 강화 실패로 장비 소실 시에도 기존 ID는 재사용하지 않음.
- 사용자에게 선택된 장비 식별 문자열은 `<item_name>@@@<instance_id>`. 인벤토리/강화 UI에서 선택한 문자열을 그대로 사용한다.

## 전용 적용 항목

- 일반 무기/갑옷/장신구 마법 주문서, 축복받은 강화 주문서, 장인의 강화 주문서, 오림/축복받은 오림 주문서: 대상 강화 레벨은 물리 ID만 수정하며 다른 복제본 강화·장착 상태는 그대로 유지.
- 속성 강화 주문서: `element`, `element_level`은 **무기 인스턴스에만 저장**, 장착 무기 `instance_id`로만 공격 속성과 별개인 속성 채널/추가 대미지 계산.
- 실패로 장비 소실: 선택된 인스턴스 ID 하나만 삭제, `inventory[name]`은 1 감소. 다른 복제본 및 장착된 다른 장비는 영향을 받지 않음.
- 저장/불러오기: 물리 ID, 강화 레벨, 속성, 장착 슬롯의 instance_id 보존.
- 기존 세이브: 이름 기준 `enhancement_levels`는 마이그레이션 시 기존 장비 수량에 상속하되, 이후 획득한 추가 개체는 기본 +0 생성.
- 이전 소모품 세이브의 이름 기준 속성 데이터는 같은 이름 장비 **한 개**의 ID에만 이전 (이전 버전이 개체 식별자를 저장하지 않아 어떤 실물인지 특정할 수 없음).

## UI

- 실제 게임 `scripts/hud.gd`: 동일 이름의 장비도 각각 한 행으로 나열, 강화 단계/속성/장착 여부/고유 ID 표시. 강화 모달에서 고유 ID를 선택·전달.
- 대체 인벤토리 UI `scripts/ui/lineage_inventory_ui.gd`도 각각 한 칸으로 표시하고 선택한 ID를 그대로 장착 이벤트에 전달.
