# 터치 입력과 지역 랜드마크 보완

기준: GitHub `zoog136-hash/-` main `f53f7fb8db878221e909737f802ec9e4d69ba663`.
기존 25개 맵, 지형/충돌/포탈/저장 데이터와 기존 smoke test를 유지했다.

## 수정한 입력 문제

조이스틱에서 손가락을 바깥으로 끌면 GUI가 전달한 **로컬 좌표**를 다시 화면 좌표로
판단해 변환했다. 오른쪽/아래쪽 이동이 위쪽이나 대각선으로 틀어질 수 있었다.
이제 GUI 좌표를 그대로 사용하므로 캡처된 손가락은 조이스틱 밖에서도 같은 방향을 유지한다.

화면 숨김, 창/앱 포커스 상실, 앱 일시 중지, 터치 취소와 컨트롤 크기 변경 시
포인터 소유권과 이동 벡터를 해제한다. 실제 마우스와 터치/에뮬레이션 이벤트가 섞여도
다른 포인터가 현재 이동 입력을 가져가거나 끊지 않는다. 8방향 스냅과 데드존은 유지한다.

`tests/input_routing_test.gd`는 `Viewport.push_input`으로 실제 GUI 전달 경로를 거친다.
이동 setter만 직접 호출하는 검사로 입력 변환을 우회하지 않는다.

- 1280×720 / 1920×1080 / 960×540 / 1560×720과 서로 다른 UI 배율에서 8방향 검사
- 조이스틱 밖 드래그·해제, 두 번째 손가락 공격, 포인터 소유권 및 HUD 입력 소비
- 취소·숨김·포커스 상실·일시 중지 후 해제와 실제 물리 이동/정지
- PC 마우스 조작 및 마우스/터치 혼합 입력

수정 전 재현 검사 394개 중 **114개 실패**. 수정 후 혼합 입력과 물리 이동까지 확장한
**399개 검사 통과**. 입력 오류 재현은 엔진에서 수행했으며 Android 실기기 검증을 대신하지 않는다.

## 지역 아트

`FieldLandmark`의 정적 도형에 기존 `terrain.png` 석재 영역을 공유해 적용했다.
새 이미지 생성, 대용량 아틀라스 추가나 외부 게임 자산 추출은 하지 않았다.

| 종류 | 보완 |
|---|---|
| 제단 | 석재 단층/받침, 돌 이음새, 각인, 촛불과 중심 문양 |
| 성문 | 아치형 쐐기돌, 기둥 줄눈, 받침과 모서리 명암 |
| 수정 | 면별 명암 변화, 반사선/균열과 암석 받침 |
| 기념 기둥·묘비 | 석재 표면, 받침, 균열과 조각 문양 |
| 깃발 | 접힌 천 명암, 테두리, 문장과 금속 봉 |
| 횃불·포자 | 화로/다층 불꽃과 버섯형 포자를 구분 |
| 계단·룬·잔해 | 디딤판/줄눈, 바닥 원근 고리, 돌 모서리 |

소품마다 매 프레임 실행하는 스크립트·조명·파티클을 추가하지 않는다.
장식 유형에 맞는 크기로 가림 처리를 계산하고, 투명도가 이미 목표값이면 반복 대입을 피한다.

## 검증과 성능 측정

Godot 4.7.2 로컬 검사 **17/17 단계 통과**: import, Main 부팅, 기존 smoke test 11개,
아덴 1,452항목, 전체 지역 5,834항목, 포탈/카메라 244항목, 새 입력 399항목.

`tests/capture_regions.gd`는 GL 디스플레이에서 실제 게임 화면을 저장한다.
입구/사냥터 28장, 랜드마크 5장, 실제 자동사냥 4장으로 총 **37장**을 요구한다.
이미지 저장 실패나 캡처 누락도 검사 실패로 처리한다.

정지 화면의 렌더링 측정과 실제 자동사냥 측정은 구분한다. 자동사냥 측정은 아덴·오만 10층·
알비노 4구역·신념 4층에서 각 30프레임 준비 후 180프레임을 기록한다. 몬스터 AI,
이동·충돌·전투·HUD·청크 스트리밍이 작동하며, 시작 체력은 해당 캐릭터의 정상 최대값으로 복원한다.
`performance.json`에는 어댑터, 프레임 제한, 프레임 간격 중앙값/95백분위,
process/physics 시간, draw call 최고값, 활성 몬스터, 이동 거리와 경험치 변화를 기록한다.

```bash
python3 tools/test_project.py --godot /path/to/godot
godot --audio-driver Dummy --path . --script res://tests/capture_regions.gd
```

GitHub Actions의 `twilight-world-review-<commit>` artifact에 캡처·검사 로그·성능 JSON이 들어간다.
CI의 Linux 소프트웨어 GL 수치는 Android 실기기 FPS·발열·배터리 측정값이 아니다.
모바일 60 FPS는 목표이며, 실제 기기 검증과 상용 수준 아트의 최종 마감은 계속 필요하다.
