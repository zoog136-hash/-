## 게임 연결과 호환성

- **일반 게임:** 검증된 개인 팩 설치 시 `yahee_temple`(야히의신전), `balrog_temple`(발록의 시전)을 지역 선택에 등록한다. 기존 25개 영속 ID + 신전 2개 = 27개다. 일반 캐릭터 저장·재진입·아덴 귀환이 동작한다. 팩이 없거나 손상되면 저장을 보존한다.
- **알비노·에스카로스 PNG 모드:** `--native-png-maps`로 명시적으로 선택한다. 기존 25개 ID를 유지하고 `escaros_world`와 신전 2개를 추가한다. 등록 28개·메뉴 22개를 검증한다. 별도 `user://twilight_native_png_save.json`을 사용하며 일반 저장을 덮어쓰지 않는다.
- 에스카로스는 99777 전체를 **하나의 필드**로 사용한다. 기존 escaros_01~05 요청은 PNG 모드에서 같은 필드로 연결한다. 공식 안내 그림과 비교해 협곡·평원·성내 1~3구역을 같은 필드의 지리 영역으로 표시한다. 옛 스폰 영역과의 좌표 변환은 확정하지 않았다. 안내 그림은 런타임 지형을 대신하지 않는다.
- PNG 모드의 알비노 진입·메뉴·포털은 1~3구역이다. 3구역 다음은 기존 신념의 탑이다. 기존 albino_04 정의·저장·NPC·몬스터·퀘스트 참조를 삭제하지 않고 PNG 모드의 직접 진입만 3구역으로 안내한다.
- 몬스터·보스·아이템·스킬·보상·AI·밸런스 DB와 기존 배치 파일은 수정하지 않았다. 옛 배치와 새 PNG의 대응 근거가 없어 알비노·에스카로스 PNG 모드의 몬스터는 미연결이다. 신전에 몬스터·보스·드롭을 만들지 않았다. 일반 게임의 기존 맵·스폰과 보스 생명·쿨다운은 보존한다.
- `PlayableField`의 길찾기와 동일 격자로 물리 충돌을 구성한다. 수동 검수 바닥·장애물 외의 영역은 닫혀 있다. PNG 알파는 **투명 영역 배제**에만 쓰며 불투명 색으로 통행을 추정하지 않는다. 이 검수는 모든 벽·물·절벽의 전수 정합을 뜻하지 않는다.
- 원본 해상도 배경 193청크 + 팩에 저장된 야히 조각상 전경 1개를 사용한다. 코드측 검수 데이터로 6맵의 돌기둥·버섯·오벨리스크·대형 조각상 등 전경 6개를 추가 분리한다. 원본 청크를 디코딩할 때 선택 픽셀만 배경에서 제거하고 발 위치 Y-sort로 표시하므로 v5 팩은 바뀌지 않는다. 추가 72,151픽셀의 단일 소유권·청크 재합성 RGBA·실제 앞뒤 가림을 검증했다. 나머지 전경은 미분리다.
- 텍스처는 최대 1024×1024이고 화면 밖 청크를 해제한다. 대형 PNG 전체를 GPU에 올리지 않는다. 미니맵만 축소 overview다. 원본 캐릭터 크기·애니메이션·이동 속도를 유지한다.
- 기존 생성기를 임시 체크아웃에서 알비노·에스카로스에 재실행해 PNG 설정의 바이트 보존을 검사한다. 인증 JSON은 `.gitattributes`로 Windows 줄바꿈 변환도 금지한다.

## 개인 팩 설치

공개 저장소에는 PNG·분할·스크린샷·ZIP을 넣지 않는다. v5 ZIP은 274,172,103바이트이며 SHA-256은 `2bc0a2463ef7448a8b16b890911175d3da03f2d992dcbcaa18cfd7563c310122`이다. 100MB 전송 제한 때문에 90MiB / 90MiB / 85,428,423바이트의 세 조각으로 나눴다. 조각 SHA와 재조립 SHA는 `data/maps/native_png_archive.json`에 있다.

현재 로컬 ZIP·조각·복원본은 `/workspace/twilight-private/`에 있다. 원본 네 파일은 기존 승인된 비공개 소스에 보존되어 있다. **v5 팩 세 조각을 사용자 승인 후 연결된 My Drive 루트에 비공개로 전달했다.** 세 원격 파일의 크기·비공개 상태를 읽고 실제로 다시 다운로드해 조각 SHA, 재조립 ZIP SHA/CRC, 193청크·전경·분할 디코딩을 검증했다. 원격 복원본의 깨끗한 clone에서 Main의 일반 신전 이동 37검사도 재통과했다. 비공개 링크는 사용자에게 직접 전달했으며 공개 Git에는 넣지 않는다.

세 조각을 같은 개인 폴더에 받은 뒤:

```bash
python3 tools/map_restore/install_native_png_pack.py --parts-dir /private/downloads --destination /private/twilight-native-pack
TWILIGHT_NATIVE_PNG_PACK=/private/twilight-native-pack godot --path .
# 기존 알비노·에스카로스의 별도 PNG 모드:
TWILIGHT_NATIVE_PNG_PACK=/private/twilight-native-pack godot --path . -- --native-png-maps --native-png-map=albino_01
```

설치기는 모든 조각·ZIP SHA, CRC, index pin, 193개 청크·전경·분할의 디코딩과 해시를 검사한 후 새 비공개 폴더에 설치한다. 기존 폴더나 공개 체크아웃으로 덮어쓰기를 거부한다. 재생성은 확보한 실제 원본으로 실행한다:

```bash
python3 tools/map_restore/build_native_png_maps.py --sources /private/originals --output /private/new-native-pack
python3 tools/map_restore/review_native_png_geometry.py --sources /private/originals --pack /private/new-native-pack --output /private/review
```

## 후속 지형·전경 검수

`native_png_review.json`은 전달된 v5의 원본 PNG/기본 plan SHA에 묶인 코드측 보완이다. 다른 원본·기본 plan이나 1024px 초과 전경을 지정하면 맵 교체 전에 거부한다. 원본 판정/전체 정합 완료로 승격하지 않는다. 새 검수본을 설치할 때 원본 팩을 다시 전송하지 않아도 된다.

- 6개 추가 전경은 실제 Main에서 픽셀 소유권·배경 재조립·발 위치 앞뒤 가림을 검증했다. 2구역 돌기둥은 두 청크에 걸쳐도 중복되지 않는다.
- 실제 받침대 위치를 대조해 추가 충돌 5개와 야히 대형 조각상 충돌 1개를 보정했다.
- 실제 통행 격자 **1,015,688칸**을 물리 도형과 전수 비교: 불일치·중복 0. 세로로 이어지는 같은 행을 합쳐 도형 **4,738 → 3,674개**로 줄였다. 외곽 벽 4개씩은 별도 보존한다. 이 수치는 원작 통행 속성과의 일치 증거가 아니다.
- 과도한 줌 아웃에서는 필요한 모든 청크의 픽셀 수를 먼저 계산하고 카메라 배율을 제한한다. 메모리 상한 때문에 보이는 배경 일부를 생략하지 않는다. 극단 줌 스트레스 검사에서 최대 PNG RGBA 약 88.013MiB이며 전체/Android 프로세스 메모리가 아니다.
- 지형 검수 revision/해시가 바뀐 저장은 진행·인벤토리·보스 상태를 복원하되 픽셀 위치는 검수 진입점으로 옮긴다. 원본 팩이 사라진 저장은 계속 덮어쓰지 않는다.
- 연결된 A3 분석보고서와 667종 원본 매칭표도 네 PNG의 서버 ID·충돌/좌표 대응을 미확정으로 기록한다. 원본 통행·좌표 보정 자료가 추가되지 않은 상태에서 기존 스폰을 임의 이동시키지 않는다.
