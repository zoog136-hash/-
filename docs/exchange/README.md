# 거래소 — 대표 서버 실측 고정 스냅샷

현재 [운영 스냅샷](../../data/exchange/frozen_snapshot.json)은 `captured` 상태의 **실제 관측 1,506행**이다. 사용자 변경 지시에 따라 데포로쥬01(`server:1`)의 장비·소모품을 우선 수집하고 일부 재료만 포함했다. 범위는 `representative_server`, `approximate=true`, `complete=false`이며 단일 시점의 전수 자료나 고유 매물 수로 확정한 자료는 아니다.

[대표 서버 선정·수집·누락·검증 보고서](REPRESENTATIVE_SERVER_20261112.md)가 현재 상태를 설명한다. [이전 재개 기록](CONTINUATION_20261112.md)은 전 서버 수집 지시 당시의 과거 증거로 보존한다. 최신 main `b488fb3`의 변경을 통합했다.

## 포함 범위

| 공식 카테고리 | 포함 관측행 |
| --- | ---: |
| 1 무기 | 253 |
| 11 방어구 | 224 |

| 41 소모품 | 704 |
| 51 기타 — 가죽 재료 샘플 | 10 |

원본 아이템 ID는 127종, 서버·아이템 ID·강화값 조합은 221개다. 이 수는 구매 가능 상품 수를 뜻하지 않는다. 원본 지급 조건을 확인하지 못한 상품은 표시하되 구매를 잠근다. 스킬카드 카테고리 31과 나머지 재료·미조회 매물의 포함을 주장하지 않는다.

## 게임 동작

- 전체 메뉴의 **거래소**에서 대표 범위와 부분 수집 상태, 상품 검색, 강화값, 묶음당 수량·가격, 현재/초기 재고를 표시한다. 구매 내용 확인과 취소를 거쳐 결제한다.
- 실행 중 네트워크 조회나 시세 갱신은 없다. 설치된 한 파일의 실제 `salePrice`와 `quantity`를 사용하며 평균·추정 가격이나 묶음 쪼개기를 적용하지 않는다.
- 각 관측행은 `initial_bundles=1`이다. 같은 수량·가격의 행도 개별 관측으로 유지한다. 행 식별자는 원본 매물 ID가 아니라 URL·원응답 SHA·행 번호에 기반한 관측 식별자다.
- 재고는 매일 **한국시간 05:00**에 관측된 초기 묶음 수로 돌아간다. 일자 계산은 `floor((UTC unix + 14400) / 86400)`이다. 열린 화면은 다음 1초 갱신 때, 종료된 앱은 다음 조회·구매 때 적용한다. 가격·품목·묶음 크기는 바꾸지 않는다.
- 원본 523 `ItemClass` ID·이름·정의와 정확히 연결된 일반형(`blessedType=1`)만 구매 경로를 연다. 매핑된 일반 장비는 관측 강화값을 원본 공급자에 전달해 물리 개체와 영수증에 보존한다. 축복·저주·속성·미해석 변형, 기간·서버 조건 미확인, 지원되지 않는 공급 품목은 잠근다.
- 다이아·원본 개체·소비 재고는 기존 상점의 동일 원자 저장에 반영한다. 저장 실패 시 라이브 재화를 유지하며 응답이 불확실하면 재로드 전 재거래를 막는다. 탐색만으로 저장하지 않는다. 첫 거래 이후 스냅샷 SHA가 바뀌면 구매를 잠가 기존 보유와 재고를 보존한다.

구매에는 기존 원본 523 정의 설치가 필요하다. 미설치 상태를 임의의 구 아이템으로 대체하지 않는다. 원본 ZIP·파생 정의 팩·캐시·시험 저장·인증정보는 공개 파일에 포함하지 않는다.

## 데이터와 한계

[빌드 보고서](../../evidence/exchange/representative-capture-20261112/build_report.json)는 받은 stock **1,521행 중 1,506행 포함**, 속성 강화 표현을 정확한 일반 장비로 확정하지 못한 **15행 제외**를 기록한다. 미조회·샘플링·시간초과로 받지 못한 행의 수는 이 15행에 포함하지 않으며 추정하지 않는다.

서버 선정은 30월드의 첫 서버와 선두 월드의 나머지 9서버, 총 **39서버 표본**을 비교했다. 데포로쥬01의 상품 그룹 지표는 `1,570 - 공유 월드 432 = 1,138`로 표본 중 최대였다. 이는 시각이 다른 카탈로그 총량의 차이이며 300서버 전체의 실매물 묶음 수 최다를 확정한 결과는 아니다.

고유 매물 ID나 원자적 스냅샷 토큰을 확보하지 못했다. 페이지 위치 이동에 따른 누락·중복 가능성과 처음 두 stock 페이지만 수집한 그룹이 남아 있다. 같은 값이 다시 나타난 추가 547행은 제거하지 않았다. 자세한 범위와 원응답 근거는 현재 보고서를 따른다.

추가 관측은 검토용 작성 작업이며 현재 운영 스냅샷을 자동으로 바꾸지 않는다. 실제 전송 시간초과는 관측 모드에서 실패 근거와 생략 범위를 남긴다. 403·429·리디렉션·잘못된 개체 정체와 무결성 오류는 공유 중단한다. 검증기는 증거 계약을 검사하지만 원자적 전수 수집을 만들어 주지는 않는다.

```sh
python3 tools/exchange/import_snapshot.py --validate-only data/exchange/frozen_snapshot.json
TWILIGHT_SOURCE_MAP_PACK=/path/to/prepared-map-inputs python3 tools/exchange/run_checks.py --stage /tmp/new-exchange-stage --godot /path/to/Godot4.7.2 --logs /tmp/exchange-checks
```

원본 정의를 사용하는 실제 구매 검사는 격리된 시험 지갑·저장 경로에서 별도로 실행한다. 실제 서비스 계정의 매매는 수행하지 않는다.

## 검증 상태

이 문서 갱신 시점에 구현 계약 **94개**, 실제 Main 탐색 **12개**, Main 저장 보존 **33개**, 원본 일반 강화 장비 시험 **29개**, Python 거래소 **85개**, core 도구 **10개**, 현재 리소스 검사(추적 파일 **20개**)가 완료된 근거다. 최종 1,506행 설치본의 집중 검사 3/3과 실제 운영 경로의 원본 구매·원자 저장·재로드 23개도 통과했다. 이 시험은 격리 지갑만 사용하고 실제 운영 상품·coverage를 합성 데이터로 대체하지 않았다. [검증 영수증](evidence/representative-20261112/validation.json)에 범위를 기록했다. 최종 게시 커밋의 원격 CI는 PR에서 별도 확인한다.

추가 집중 CI는 `Focused exchange runtime checks`이며 기존 필수 `Core runtime, save preservation and resource paths`와 `Verify committed assets, manifest SHA, and delivery status`를 유지한다. GPU·Android 실기기, 전체 역사 기능 suite, 원작 아트 전체 전달·시각 동등성은 이 검증의 완료 범위에 포함하지 않는다.
