# Original NPC portrait receiver

The UI receiver now accepts the image270 owner's source-backed
`NpcClass.IllustAssetID→AssetView` role from public
`7eb2594fbed2d9d78e030d4bea3f6954cf5fd40b`. This is a new UI-owned adapter ABI,
not a recovered original-client function signature. No tests, execution,
rendering or CI were run. Actual dialogue portrait display is unconfirmed.

## Registration and authoritative current dialogue

Register the existing context producer269 and image consumer270 callbacks:

```gdscript
hud.bind_original_npc_dialogue_portrait(context_provider, image_provider)
```

The HUD stores them across source-controller replacement. If a native
conversation is already open, it reuses the same current dialogue model and
NPC/node selection; no next choice is selected. Otherwise normal existing
`open_npc_dialogue` / `source_dialogue_resolved` calls consume the registration.
Text, close and eligible next-only paths continue without a portrait.

The context callback receives the **actual current owner's** `(npc_id:String,
node_id:String)` and returns:

```text
{ ok:true, npc_id:<same>, node_id:<same>,
  npc_class_id:<positive TYPE_INT authoritative mobile NpcClass.ID>,
  source_basis:<nonempty texture-free Dictionary from the real producer> }
```

The installed source-NPC dialogue registry currently uses L1J identities and
does not establish this current523 NpcClass relation. The producer must supply
an actual relation or its own unavailable result. UI does not derive a mobile
ID from names, local strings, actor Sprite IDs, DescIDs or coincident numbers.
It does not treat a positive integer alone as canonical-table validation.

The image callback receives `(context:Dictionary, source_target:Dictionary)`.
It uses the existing image resolver and returns its descriptor plus these exact
identity/role echoes:

```text
{ npc_class_id:<same current mobile ID>, role:"NpcClass.IllustAssetID",
  route:"source523_images", status:"original_linked",
  original_bytes_unchanged:true, texture:<existing original Texture2D>,
  provenance:<existing original pixel provenance>, source_status:<owner status> }
```

Asset joins, original NpcClass row/IllustAssetID validation, exclusions, format,
byte/hash checks and texture decoding stay with the image owner. This UI adapter
normalizes that successful descriptor in the same manner as existing native
item-image consumers; it performs no second asset/NPC lookup. Missing identity,
wrong role, absent pixels, CSB and AnimatedTexture remain portrait-only blocks.
In particular no CSB root→Sprite registration or loop policy is manufactured.
