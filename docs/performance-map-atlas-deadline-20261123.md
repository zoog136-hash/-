# 원본 지도 아틀라스 대기와 프레임 지연

기준은 이전 지도 작업의 로컬 커밋 `a25ea96`이다. 이 커밋에서 보고한 279 → 284ms는 서로 다른 실행에서 얻은 아덴 첫 표시의 렌더러 콜백 최댓값이었다. 이번에는 그 시나리오를 `a25ea96`와 수정 코드에서 반복하고, 각 실행에서 가장 느린 `_process_step()`의 세부 작업을 같은 프레임 안에서 비교했다.

## 원인과 수정

`_pending_tiles_ready()`는 캐시된 아틀라스 ID 목록에서 첫 미완료 요청을 만나면 중단했다. `prefetch()` 자체가 요청을 제출하므로 이후 ID는 나중 프레임까지 큐에 오르지 않을 수 있었다. 3초가 지난 화면 블록은 `_block_commands()`에서 `texture_for()`를 호출했다. 이 경로는 디코딩 작업이 있으면 그 작업을 기다리고, 없으면 원본 읽기와 TI2 디코딩을 콜백에서 직접 수행했다. 전체 목록을 제출하는 변경만 시험했을 때도 이미 제출한 작업을 메인 스레드에서 기다리는 시간이 남았다.

실제 원본 지도용 팩에서는 미완료 아틀라스가 디코딩 작업이나 작업 대기를 메인 스레드에서 시작하지 않는다. 재시도 때 아틀라스 요청을 모두 제안하며 기존 워커 상한과 ID별 중복 방지를 사용한다. 완료된 텍스처는 기존 캐시에서 사용한다. 파일의 읽기·검증 실패도 완료 상태로 돌려주므로 손상된 타일이 블록 전체를 계속 대기시키지 않는다. 기록된 실패는 다음 요청 묶음에서 다시 확인할 수 있다. SHA 검증, TI2 해석, 타일 순서·픽셀 데이터 및 S32 충돌 코드는 건드리지 않았다. 백그라운드 로더를 쓰지 않는 리뷰·시험 팩은 기존 동기 경로를 유지한다.

## 재생과 측정 방법

Godot 4.7.2 Linux Compatibility, Mesa llvmpipe, 900×540 뷰포트. 같은 로컬 원본 S32·TI2 팩을 사용했다. Land 4 기란 고정(140회), 같은 아덴 이동 경로(기존 목적지 및 보간), Land 0 전환(140회), Land 4 복귀(140회) 순서다. 프레임은 기존 18ms 타이머와 `_process_step(0.034)` 호출을 사용했다. 각 실행은 별도 프로세스이며 팩의 디스크 메타데이터 캐시를 재사용했다. 콜백 측정에서 파일 매니페스트 설정 및 캡처를 제외했다.

세부 시간은 콜백을 호출하기 직전에 지우고, 가장 긴 콜백의 값을 보존했다. 아틀라스 인라인 구간에는 파일 읽기·SHA 검사와 디코딩이 포함된다. `ImageTexture.create_from_image`는 CPU에서 제출하는 시간을 재며, 독립 GPU 타이머나 완료 펜스를 사용하지 않았다. 충돌 갱신은 호출이 발생할 때만 측정했다. S32 조회는 콜백에서 호출된 청크 조회·대기를, 워커 완료 반영은 별도 설치 구간을 잰다. 동시에 실행되는 워커의 전체 CPU 시간을 이 수치에 더하지 않았다.

수정 전 아덴 첫 표시의 각 최장 콜백은 아틀라스 25 / 25 / 24개를 인라인으로 디코딩했다. 이들이 기존 279/284ms와 같은 종류의 지도 지연으로 재현됐다. 이전 실행의 전체 세부 기록은 없어 그 두 프레임을 역산하지 않았다. 수정 후 첫 표시의 가장 긴 41.4ms 콜백에는 아틀라스 완료 반영 16.08ms와 블록 노드 반영 20.10ms가 포함됐다. 전자에 텍스처 제출이 포함되므로 중복 합산하지 않는다. Land 0처럼 원래 인라인 병목이 없던 구간은 이 표에서 속도 개선이 관측되지 않았다.

비교한 네 장면의 최종 픽셀 SHA-256은 여섯 실행 모두 일치했다. 각 Land에서 시험한 우회 경로 36개의 좌표열 SHA-256도 전후 모두 일치했다. 이번 시험은 장면 완료 화면을 비교했다. 로딩 중 개별 블록의 첫 표시 시간 및 GPU 실행·Android 기기 성능은 측정하지 않았다.

회귀 검증은 TI2 캐시·작업 중복·손상 파일 복구 104개, 지도 작업 큐 36개, S32 충돌 규칙 47개, 지도 표시 보호 136개, Main 저장·재로드 33개를 통과했다. 리소스 무결성의 현행 `check_no_legacy_resources.py` 검사도 통과했다. 이전 지침에 적힌 `check_resource_integrity.py`는 이 버전에 없다.
