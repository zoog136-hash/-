# 현재523 캐릭터 부착물 전수 감사

이 후속 브랜치는 main `b488fb367ac5dcf359861294581e32abeeb26c82`에서 시작했다.

복구된525 클라이언트 정적 분석은 523 실행 실측과 구분한다. 보호된523 EXE/DLL의
정적 표면만으로 픽셀 연산식을 확인했다고 주장하지 않는다.

반복104는 이523 원문에서 같은 값만 반복한다. 따라서 last 대 OR 수정은 원본 계약의 교정이며,
이 데이터에서 달라진 픽셀이 관찰됐다는 주장이 아니다. legacy reader의 캐릭터 closure
3,397노드 표본에서는 부모/자식 action 충돌이 없었다. 전체3,582노드 검증으로 확대하지 않으며,
compiler 교정 역시 사진의 원인으로 단정하지 않는다.

복구525 정적 근거에서 최종 순서는 SP2 cell depth 오름차순·동일 depth의 unsigned identity 내림차순이다.
현재 renderer는 각 파일을 평탄화한 프레임으로 그리므로 파일 사이 cell의 교차 정렬까지 재현하지 않는다.
101/105 원문 순서나 Godot z_index를 원작 최종 픽셀 순서와 동일하다고 보고하지 않는다.
`ref.type`은 depth이며 opacity가 아니다. 임의 알파 조절·오프셋·축척 수치는 추가하지 않았다.
기존 compiler의 header alias를 통한101/105 상속·보조 레이어 재귀 확장,
101 마지막 값/105 최초 map 적용, 첫 null 이후 clothes prefix 중단도 원작 계약과 차이가 남는다.
전수 감사 도구는 이 차이를 드러내지만 기존 팩의 활성 조건을 임의 재작성하지 않는다.

부착물 소비 경로도 직업·변신·무기 동작·인형/유물 주/보조 슬롯·각성 aura·스킬·장비
invoke·아이템·NPC·소환수까지 조사했다. 비공개 목록에는 생성 호출, ID 연결, z 순서,
위치/offset, alpha/blend, 표시·정리 조건을 각 경로별로 기록했다.
추가 미완료 항목은 보조 슬롯의 실패한 binding/aura 재시도 억제,
숫자 LightRadius를 사용하는 자체 제작 수동광의 원작 픽셀 근거,
자체 제작 소환수의 source-only 경로, 제한된 각성12연결과 Type48 전체 소비 연결이다.
기존 아이템 효과의 ItemClass 전달 누락도 기록했지만, 보류된 원본 물약 효과 복원은 하지 않았다.
이 후보들을 사진 속 광채·실루엣이라고 단정하거나 원본 레이어를 지워 숨기지 않았다.

## 검사와 실제 확인의 구분

현재523 물리 목록은 630 DAT, SP2 74,656파일/16,260 ID다. 기존508과 같은622 DAT는
현행 manifest의 SHA-1·크기가 일치하고 바뀐/추가8 DAT는 현행 원본으로 검증했다.
이 목록 확인이 74,656파일의 픽셀 재렌더를 뜻하지 않는다.

캐릭터101/105 선언관계 target의 물리 범위는18,141파일/835,301,290 bytes다.
로컬에서 실제 원본을 읽은 범위는64 target,690 SP2,59,174프레임이다.
Godot4.7.2 CPU 디코드·프레임 범위·원점·RGBA 해시 검사60,555개가 통과했다.
빈4,728프레임도 보존했다. 프레임별 offset/bounds·소스/픽셀 SHA와 재현 코드는 비공개 감사 묶음에 있다.

남은17,451파일을 새로 확보하려면 추가306 DAT의 외부 ZIP deflate payload
3,309,778,250 bytes를 내려받아야 한다. 해당 다운로드와 전수 픽셀 재렌더는 수행하지 않았다.
이 추가 확보 분모는18,141파일에 한정되며 조건부139 target과 미승격 Type48 후보는 별도다.
조건부139 target도 별도 가용성 목록으로 남겼고 실제 전체 렌더를 주장하지 않는다.

회귀 검사는 실제 production host/JSON bank 경로를 사용하되 테스트 texel·테이블 경계는 합성 입력이다.
월드 좌표·토큰·NPC·속성 소유자 검사는 수정 전 코드에서 실패함을 확인했다.
필수 Core gate에 새6개 Godot 검사와 전수 parser/selector Python 검사를 추가했다.
기존 #418의 OpenGL 합성 검사도 함께 유지한다. GPU 결과는 CI 실행 영수증을 참조한다.

사용자 사진의 황백색 광채·검은 실루엣은 실제 픽셀을 확인했다. HUD의 ‘황혼의 사신’은
직업 이름이므로 활성 변신/부착물 ID를 사진만으로 특정할 수 없다.
사진 현상의 정확한 원인·수정 전후 동일 장면·Android 실기기는 미검증이다.
강제 종료/크래시 조사는 이 작업에서 다루지 않는다.

## 재현 및 전달

공개 코드에는 원본 아트를 넣지 않는다. 비공개 감사 묶음은 원문 전체 census,
캐릭터별 종류/ID/순서/조건/매핑, 실제 가용성·offset·해시, 실행 로그 및 버전 근거를 포함한다.
원본 SPR·DAT·SP2·EXE와 사용자 사진 자체는 감사 결과 ZIP에 포함하지 않는다.
최종 commit·CI 결과와 비공개 감사 묶음의 전달 상태는 별도 완료 영수증에 기록한다.

`AGENTS.md`가 지정한 `tools/check_resource_integrity.py`는 현재 main에 없다.
현행 필수 workflow의 `tools/check_no_legacy_resources.py`와 해당 테스트를 실행하며,
없는 검사 명령을 통과했다고 보고하지 않는다.
