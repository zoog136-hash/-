# 출석·패스·룰렛·용옥·성배·일반 시련 연결

기능 실행기와 화면을 분리했습니다. 기존 자체 Godot 폼과 HUD의 **출석·패스·생활** 진입부는 게임에서 제거했습니다. 원본 UI 담당이 아래 인터페이스를 연결하기 전까지 이 기능의 설치·선택·확인·청구 화면은 제공되지 않습니다. 기존 기능의 자동 진행·소지 효과·공동 저장 계약은 유지합니다.

비공개 공통523 ZIP의 설치기는 고정 크기·SHA와 1,065표의 목록을 확인하며, 표를 사용할 때 원본 해시를 검사합니다. 기존 `source.install_zip(path)`와 재시작 계약을 보존하지만 대체 파일 선택 화면은 만들지 않습니다. 원본 JSON·이미지·보고서는 이 PR에 포함하지 않습니다. 기존 팩을 재사용하고 별도 리소스 팩을 만들지 않습니다.

최초 작업 기준은 main `f4cc0138613a6c98898c57d479b5247a849b96ab`이며, PR264 통합 기준은 main `00b84cfe19c05e01d30208384bf7fbcc4ae6bbf2`입니다. 로컬 후속 `e416679053baa012d4fe06e3a3cd475775e81821`을 백업 참조에 보존하고 기존 브랜치에서 통합했습니다. 기존 PR264의 자체 폼은 원본 UI가 아니었습니다. 해당 코드와 당시 화면 검사는 `tests/audits/`의 역사적 검사 자료로 보존하며 게임 코드에서는 불러오지 않습니다. 전체 원본 UI 적용은 미완입니다. 세공·제련·연금·장비 세트·발동 스킬 교체는 최신 사용자 지시에 따라 이번 PR에서 제외했습니다. 오림·시련의 탑, 일반 퀘스트와 다른 진행 PR을 복제하지 않습니다. 혈맹·공성·펫·투기장·지구라트는 제외합니다.

## 원본 UI 연결 계약

원본 메뉴 ID·시련 UI 키·아이템 ID에서 데이터와 액션·중첩 선택·확인·저장으로 이어지는 비시각 호출자를 추가했습니다. [호출자 ABI와 실제 확보 범위](UNCONFIRMED523_SOURCE_UI_ABI.md)를 따릅니다. CSB 로더·렌더러·대체 화면은 추가하지 않았습니다.

World의 `unconfirmed523` 실행기가 제공하는 `page(section)`은 표시용 데이터이며, `execute(section, request, revision, fingerprint)`는 확인한 거래를 기존 원자 저장기로 실행합니다. 영역은 `events`, `jade_grail`, `challenge`입니다. 화면은 표시 시 읽은 `state.revision`과 `fingerprint()`를 확인 시 다시 전달해야 합니다. 취소는 실행기를 호출하지 않습니다. 선택 보상과 개체 ID를 화면 쪽에서 임의로 대체하지 않습니다.

원본 UI는 `bind_presentation(callable)`로 영역 문자열 하나를 받는 콜백을 등록할 수 있습니다. `request_presentation(section)`은 해당 콜백의 Dictionary 응답을 반환합니다. 화면이 열렸다는 응답은 거래·저장 성공 증명이 아니며 청구에는 별도 `execute()` 결과가 필요합니다. `bind_presentation(Callable())`로 해제하며 이 연결은 세이브에 들어가지 않습니다. 기본 상태에는 등록된 콜백이 없고 `presentation_unavailable` 오류를 반환합니다. 자체 폼으로 우회하지 않습니다.

원본 UI가 없더라도 이 소비기가 인식한 보유 아이템의 `try_use()`는 handled를 유지하며 재료·재화·난수·진행을 변경하지 않습니다. 다른 아이템 소비기로 넘어가지 않게 하기 위한 계약입니다. 준비 보상·공동 영수증 ABI, 저장 스키마와 World의 효과·진행 연결은 화면과 독립적으로 유지합니다. 과거 자체 폼 캡처는 원본 UI 실행 증거가 아닙니다.

분리 후 Godot 4.7.2의 실제 Main 검사 114개, 별도 프로세스 재시작 51개, 기존 Core 47개, 공동 소유권·원본 소비·UI 연결 경계 Host 153개가 통과했습니다. 기존 인벤토리와 퀵 아이템 사용 경로에서도 UI 미연결 시 차감·저장 변경이 없음을 확인했습니다. World·원본 표·세 도메인·정책·공동 소비 ABI는 공개 `65f559cf`와 같고, HUD는 main `00b84cfe`와 같습니다. 이전 자체 폼의 시각·확인창 단언은 역사적 검사로 보존했으며 이번 기능 검사나 원본 UI 승인으로 집계하지 않습니다. 원격 CI·원본 UI 시각 동등성은 검사하지 않았습니다.

## 연결한 소비 경로

- 출석 버전·서버별 대안 보상·일일 청구 이력을 구분합니다. 같은 날짜의 서버별 행을 모두 지급하지 않습니다.
- 패스별 구매·프리미엄 권한·경험치·단계·시즌·청구를 저장합니다. 동시에 존재하는 시즌을 유지합니다. 패스 전용 목표는 실제 처치·축복 소비·제작·강화 등의 이벤트를 사용하며 일반 퀘스트를 다시 구현하지 않습니다.
- 보유한 원본 LuckyBag과 선택·복합 보상 아이템을 소비합니다. 보상을 직접 선택하며 원본 축복·강화 변형을 유지합니다. 연출용 룰렛 표를 획득 확률로 사용하지 않습니다.
- 최종 보상이 있는 18개 풀을 전수 대조했습니다. 누적 실행기는 실제 개체를 한 개씩 소비하고 7번째 추가 보상·완료 이력을 같은 거래로 준비합니다. 한 개를 7회 충전으로 취급하지 않습니다. 다만 현재 유일하게 상자 자체의 시험용·만료 조건을 통과하는 8951도 원본 후보 8961이 TestItem이므로 개봉 전체를 거절합니다. 원본 10시간 간격·7회·최종 8361 ×4는 보존하고, 7회 완료·재시작 로직의 시험용 그래프 검증을 원본 개봉 성공으로 표시하지 않습니다. 현재 원본 18개 풀 중 끝까지 개봉 가능한 풀은 0개입니다.
- 선택·복합 상자의 표시 필터와 삭제 시각 연장 금지는 엄격한 원본 메타데이터로 처리합니다. 수명이 있는 상자는 신규 정상 지급 시 취득·만료 시각을 기록하고 정확한 보유 개체로 소비합니다. 취득 시각이 없는 옛 개체의 수명은 임의로 복원하지 않습니다.
- 원본 용옥 12종의 기간과 자격을 읽고 기존 아인하사드 서비스의 단일 만료 시각을 사용합니다. 원본에 보존된 12종은 현재 날짜에 시험용 또는 과거 만료 조건에 해당합니다. 이 조건을 해제하지 않으며, 기존 월정액 용옥 구매 경로는 유지합니다.
- 축복된 성배의 실제 개체별 은총·교체, 소지 효과, 동일 등급·접두 조건의 세트 효과를 연결합니다. 기본 은총과 추가 절대 은총을 구분하며 BonusID 0의 세트 자격도 유지합니다.
- 일반 시련 `Challenge` 69개를 읽고 원본 활성 상태인 6개만 실행 대상으로 삼습니다. 기존 `TrialTower`와 별개입니다. 현재 맵에서 실제 처치로 진행하는 모드는 명시적인 TWILIGHT 대체 호스트이며 원본 던전 지형 복원이 아닙니다. 완료 보상과 플레이 중 추가 보상을 구분합니다.

비용·원본 ID 소유권·개체 잠금·취소·중복 확인·저장 실패를 검사합니다. 진행·재화·보상·추첨 상태를 기존 World 저장기에 한 번에 기록한 뒤 적용합니다. 손상 저장과 팩 누락 시 기존 진행을 보존합니다. 일반 몬스터 드롭의 바닥 습득 경로를 변경하지 않습니다.
보유 LuckyBag의 보상 제한은 개봉과 표시 데이터에서 같은 읽기 전용 검사를 사용합니다. 시험용·만료 보상이 포함되면 사유와 실행 불가 상태를 반환하며, 데이터를 읽는 동안 선택·추첨·소유권은 바뀌지 않습니다. 실제 원본 화면의 표시는 UI 담당의 연결이 필요합니다.

## 확인된 규칙과 자체 정책

원본 표의 수치·서버·등급·슬롯·기간·후보를 유지합니다. `data/unconfirmed523/twilight_policy.json`의 다음 값은 **조절 가능한 TWILIGHT 추정**입니다.

- `luckybag_random_mode=source_weights`: 원본 후보와 원시 가중치를 사용한 한 번의 가중 추첨입니다. 서버의 추첨 횟수·미명명 결과를 복원했다는 뜻이 아닙니다.
- `random_reward_weight_mode=equal_estimate`: 원본에 후보만 있고 확률이 없는 RandomReward를 동일 가중치로 실행합니다. 공식 확률이 아닙니다.
- `attendance_blessing_base=200`: 원본의 수량 0인 출석 축복 보상에 기존 TWILIGHT 레벨별 충전 배수를 적용합니다. 원작의 내부 축복 수식이 아닙니다.
- `luckybag_final_scope=source_item`, `luckybag_final_completion=once`: 이 실행기에서 관측한 동일 원본 아이템의 소비를 합산하고 한 번 완료합니다. 원본 서버의 과거 개봉 이력·초기값·리셋 범위는 확인되지 않았습니다. 명시적 풀별 정책을 둘 수 있지만 확인된 8951의 7회 임계값과 원본 사용 간격은 바꾸지 않습니다.
- `conditional_percent_mode=percentage_points_estimate`: 성배의 공격 종류별·PvP 리덕션 무시를 기존 전투기의 감소 예산에서 한 번만 차감합니다. PvP 감소는 실제 PvP 표식이 있는 공격에만 적용합니다. 원본 서버 계산 순서를 복원한 수식이 아니며 `disabled`로 끌 수 있습니다.
- `undead_damage_mode=uniform_1_to_max_estimate`: 실제 언데드 대상의 근거리·원거리 타격에 원본 최대값까지 1 이상 균등 추첨합니다. 원본은 최대값을 명시하며 이 분포·계산 순서는 자체 추정입니다. 마법·일반 대상에는 적용하지 않으며 `disabled`로 끌 수 있습니다.
- 시간대 미지정 원문 일정은 실행 장치의 로컬 시간대를 기본으로 해석합니다. `time_policy.utc_offset_minutes`로 고정할 수 있습니다. 절대 Unix 만료 시각에 시간대를 다시 더하지 않습니다.

구독 종류와 보호 버프 사이의 서버 디스패치, 성배 2/4세트 누적, 현재 맵 시련 호스트도 명시적인 자체 정책입니다. 원본에 없는 선언을 다른 이름·숫자 ID와 임의로 연결하지 않습니다.

## 남은 범위

원본 던전 지형·서버·멀티플레이, 시험용·만료 또는 최종 보상 임계값이 확인되지 않은 상자, 범위 밖 보상·특수 소비, 모든 원본 아이템의 자연 공급·사용·연출은 완료 범위가 아닙니다. 미지원 보상을 가진 청구와 상자는 소유·청구 상태를 보존하고 실행을 거절합니다. 성장 패스는 해당 원본 퀘스트 완료 ID가 없으면 잠김을 유지합니다. 카드 소유권·합성 및 원본 카드 룰렛 연출은 기존 카드 담당 범위이며, 여기서 연결한 추첨은 보유 상자와 선택·복합 보상의 소비 경로입니다. 기존 오림의 원본 캐릭터·스킬·맵도 이 PR에서 복원하지 않습니다.

Reward 36,038행의 구조 검사를 기능별 도달 경로와 따로 집계했습니다. 출석·패스·일반 시련의 보상 경로에는 새 범용 보상 엔진이 필요한 종류가 없었습니다. 보상 없음(NoReward)은 정상 빈 결과로 처리합니다. 혈맹·일반 퀘스트의 버프·퀵슬롯·유료 보상 강화, 시험용 상자의 복합 반복 추첨을 이번 기능으로 재구현하지 않습니다. 전체 리졸버 검사에서 지원 결과가 증가한 것은 15개 NoReward이며, 검사 문맥에서 해석된 결과 수를 현재 캐릭터의 청구 가능 수나 자연 획득 수로 표시하지 않습니다.
