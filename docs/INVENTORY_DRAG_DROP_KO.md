# 가방에서 끌어서 바닥에 내려놓기

## 동작

1. 가방(UI 애드온의 원본 Inventory 창 또는 TWILIGHT 가방)에서 아이템을 길게 누르거나 끌어 창 밖 필드에 놓는다. 입력은 `pointer_transfer.gd`의 네이티브 ScreenTouch/ScreenDrag 경로(마우스 에뮬레이션 미사용)이며, 놓는 지점이 HUD·원본 창 위면 아무 일도 하지 않는다.
2. `inventory_ground_transfer.quote`가 아무것도 바꾸지 않고 검사한다: 보유 수량, 잠금, 장착 여부, 기존 `droppable`/`quest_item`, 그리고 원본 523 아이템의 **ItemClass.IsDroppable**.
3. 확인창이 열린다(이 시점까지 가방·바닥 변화 없음).
   - UI 애드온이 있으면 원본 팝업: 2개 이상 묶음은 `UI/CommonUi/Common_Calculator.csb`(0~9·MAX·←·−/+·취소/확인, 기본 1) → `UI/CommonUi/Common_MessageBox_Dissolution.csb`("<이름> <수량>개를 바닥에 내려놓으시겠습니까?", 원본 슬롯에 아이템 그림). 1개면 메시지 상자만.
   - 애드온이 없으면 TWILIGHT 확인창(묶음이면 수량 칸).
   - 팝업이 열린 동안 아래 필드·가방·퀵슬롯은 터치를 받지 않는다(전체 화면 차단 층 + `original_source_pointer_capture_blocked`).
4. 확인하면 `inventory_ground_transfer.drop(world, 참조, 위치, 수량)`이 옮긴다. 플레이어 위치(끈 방향 최대 96px, 갈 수 없는 곳이면 발밑)에 바닥 아이템이 생기고 원본 바닥 그림·등급 빛기둥으로 표시된다. 자동 줍기는 플레이어가 내려놓은 것을 줍지 않으며, 직접 선택해 다시 주울 수 있다.

## 수량

| 가방 아이템 | 한 번에 내려놓는 양 |
| --- | --- |
| 이름 기준 묶음(물리 개체 없음) | 1~보유 수량, 바닥 기록 1개(수량 N) |
| 원본 물리 수량 묶음(`source_native_stack_receipt`, 줍기·지급마다 생기는 실제 소유 개체) | 1~잔량. 기존 분할(partition) 장부로 N개짜리 자식 개체를 만들어 바닥 기록 1개(수량 N)로 저장. 저장 검사·줍기·유효시간 소멸이 "바닥 수량 = 그 개체 잔량"을 확인 (`current523_native_stack.gd`) |
| 장비 등 고유 개체, 각성서·카드 화폐 분할 | 1 |

## 원본 규칙과 근사

- 리니지M 원본에는 플레이어가 가방에서 바닥으로 버리는 규칙이 없다. 원본 데이터에서 쓰는 것은 ItemClass.IsDroppable 하나다(비테스트 30,398종 중 13,801종이 false). IsTradable·IsDeletable은 거래·삭제 규칙이라 바닥 이동에는 쓰지 않는다(근사).
- 확인/수량 팝업은 원본의 공용 계산기·메시지 상자를 재사용한 근사이며 문구는 TWILIGHT가 채운다.
- 바닥 유지 시간은 기존 규칙(600초) 그대로이며 저장 시각 기준으로 지나면 사라진다.
- 원본 523 필드(`m523_land_<LandID>`)의 바닥도 저장·복원된다(이전에는 원본 필드에서 내려놓기를 막았고, 불러오기에서 그 지도의 바닥 기록을 버렸다).
