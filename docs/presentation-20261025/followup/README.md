# PR157 추가 최적화와 메뉴 상세 상태

기준은 PR157 `95cfb271`, 원격 main은 다시 확인한 `cba19558`이다. 전체 CI는 사용자 지시로 계속 보류한다.

## 구현과 실제 효과

- **첫 지역 진입:** 같은 지도 구성 중 중첩 스폰 구역이 반복하는 안전지역 판정만 임시 3상태 배열로 재사용한다. 구성 완료 후 폐기하며 지도 간 캐시하지 않는다. 실제 Main 에스카로스 진입 4.979→3.150초. 별도 동등성 검사에서 아덴/에스카로스의 데이터·준비된 구역·스폰 후보 배열 순서·solid runs·도달성·서명이 같았다. 에스카로스 안전 판정 138,685→21,916회. 아덴은 반복이 적어 실질적 향상 없음.
- **첫 경로 그래프:** 0/1 도달성 배열의 1만 native 검색하고 공간을 미리 예약한다. 같은 필드 101.117→60.131ms. 모든 21,811개 노드 ID·좌표·연결 순서가 같았다.
- **도달 불가 AUTO:** 기존 불변 native 경로 그래프 안에서 정확한 시작/목표 좌표의 실패만 최대128개 보관한다. 움직임은 즉시 재검사하고 지도 재구성은 캐시를 버린다. 범용 시간제 지연이나 동적 문 지도에 실패 캐시를 넣지 않았다. 같은 두 섬/24대상/60회 선택 fixture의 중앙 CPU시간 126.619→0.071ms, p95 128.732→0.090ms. 첫 실패는191.922→191.177ms로 개선되지 않았다. 이는 실제 selector를 사용하는 합성 경로 microbenchmark이며 게임 전체 프레임/Android 측정이 아니다. 중간 그래프만 캐시한 7.262ms 결과도 `unreachable-graph-only.*`에 보존한다.
- **메뉴:** 장착·선택·잠금 상태, hover/pressed 선택 테두리, 작은 화면 긴 이름과 5행 가격표, 천단위 수치·우정렬, 터치용 구매 불가 사유와 잔액 동기화를 기존 인벤토리/상점에 연결했다. 실제 Main 전후12PNG와 최종37검사, runner31단언을 보존한다. 가격·거래·ID·원화 규칙은 변경하지 않았다.

## 제한과 소유 경계

첫120전투 프레임은 p99 316.023→266.664ms였지만 최대333.713→351.771ms로 악화했다. 각 실행의 AI instance-ID 위상이 달라 동일 전투 결과의 인과 비교로 해석하지 않는다. 첫 전투 전체 끊김은 **미해결**이며 Android 실기·GPU 메모리·장기 세션도 미검증이다. 이는 인증/환경 때문에 코드 작업 자체가 거절된 상태가 아니라, 추가 원인 분리가 필요한 남은 성능 문제다.

지역 구성의 다중 폴리곤 반복 변환도 확인했으나 PR155 `5a10f0c8`가 이미 해당 캐시를 구현하고 있어 가져오거나 중복 제작하지 않았다. PR155의 floor raster 훅과 사용하지 않는 snapshot 생략도 보존했다. 이번 `PlayableField.configure` 수정은 별도의 스폰 안전 판정 루프뿐이다. Native path 연결과 route graph는 해당 PR HEAD의 원본과 동일함을 먼저 확인한 뒤 수정했다. PR122/152/153/154/155 전용 자산·원화·애니메이션·기능은 미이식·미변경이다.

## 재현

실패 탐색 기준 스크립트는 `git show 95cfb271:scripts/maps/native_png_route_graph.gd > /tmp/pr157-route-before.gd`로 추출한다. 같은 Godot4.7.2에서 `tests/benchmark_unreachable_auto.gd`를 headless로 실행하며 `TWILIGHT_ROUTE_SCRIPT`가 이 파일을 가리키면 기준, 생략하면 현재 구현이다. 출력은 `TWILIGHT_AUTO_OUTPUT`에 저장한다. 정상 사용자 저장과 분리한 XDG_DATA_HOME을 지정한다. 상세 진입/첫 전투 재현과 계측 오버헤드는 위 entry-cost 문서에 있다.
