# 원본523 제작·장비 가공 연결

기준 main: `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`. 열린 PR218/222/224/228/230/231/232를 먼저 대조했고 이 기능과 중복되는 제작 PR은 없었다. 다른 PR을 병합하지 않았다. 별도 코드 체크아웃과 `feature/patch523-crafting-equipment-20261104` 브랜치를 사용한다.

## 적용 범위

기존414개 TWILIGHT 제작식과 상점 가격·강화 확률·각성 비용은 그대로 둔다. 별도 private 규칙 파일을 설치하면 기존 제작 화면에 `원본523` 제작식159개가 추가된다. 원본 ItemClass ID와 현재 Inven 카탈로그 ID뿐 아니라 한국어 DescID/IdentifiedDescID 이름까지 일치해야 활성화한다. 인벤토리 재료의 실제 ID 연결도 실행 직전에 다시 검사한다.

예: 인장 상자8개→일반+3인장, 같은 종류·+3~+8·일반 인장2개→같은 단계 축복 인장1개. 물리 장비의 강화·축복 상태, 장착·잠금, 무게, 아데나와 재료 수량을 검사한다. 원본 출력의 강화·축복을 새 물리 ID에 기록하며 입력 상태와 속성·제련 효과를 복사하지 않는다. 원본의 제련 소실 팝업이 있는 제작만 알려진 제련 상태를 소비할 수 있고 확인창에도 경고한다. 알 수 없는 인스턴스 옵션은 보호한다.

거래는 별도 사본에서 만들고 실제 Main의 저장이 성공한 뒤 메모리에 반영한다. 저장 거부 시 재료·장비·지갑·카운터·제작 기록과 기존 저장 바이트를 보존한다. 기존 세이브를 강제로 새 원본 ID로 바꾸지 않는다.

축복 수호/회복 인장의 정확한 BlessCode2·해당 단계 행에서 기존 엔진에 대응되는7종(근/원거리 명중·대미지, 일반 리덕션, 물약 고정/비율 회복)을 연결한다. 기존 카탈로그+0 능력을 한 번 빼서 강화 증가분을 저장한다. 낮은 강화 단계를 누적하지 않는다. 이 증가분은 물리 장비 record에 저장돼 팩 없이 세이브를 다시 읽어도 유지된다. 경험치·아인하사드 절약·스턴 내성·물약 쿨타임은 조회만 지원한다. 원본0을 Normal1로 바꾸지 않으며 일반 인장의 원본0 매칭은 미확정으로 남긴다.

## 실제 화면 경로

기존 메뉴의 제작 장인→`원본523` 검색→결과 강화/축복·조건·정확한 사용 가능 수량 확인→제작 실행→확인창→저장 후 결과 표시. 제작 화면과 기존 강화 화면의 `원본 강화 정보` 버튼은 보유 물리 ID와 주문서를 선택하는 정보 화면으로 이어진다. 원본 확률·원본 비용값/재료량과 단계 효과를 표시하고 적용된 효과와 참고만 가능한 효과를 구분한다. 기존 강화 실행 화면으로 돌아가는 버튼도 있다.

이 정보 화면은 확률 강화 실행부를 교체하지 않는다. 원본 비용표의 통화, ConsumeAmount0, TargetBlessCode0, 현재/결과 단계 해석, SideEffect 감소량 및 축복 점프 활성 조건은 확정하지 못했으므로 원본 수치로 실제 지갑이나 추첨을 바꾸지 않는다.

## private 파일과 실행

공개 diff에는 코드·검사·이 문서만 들어간다. 원문 행·분석 ZIP·이미지와 런타임 규칙 JSON은 Git에 넣지 않는다. 규칙 파일은 별도 Library에 보관하고 정식 materialization으로 다른 소비 폴더에 다시 내려받아 동일 SHA를 확인했다.

- 파일: `patch523-equipment-rules.json`,29177663bytes.
- SHA256: `7bb9110f40bc7261781bfdab59a3ec15237be209c2826ebc932c62774efe4610`.
- 현재 카탈로그 바이트 SHA도 소비 시 확인한다. 해시/구조/카탈로그가 다르거나 파일이 없으면 거부한다. 실패한 교체는 마지막 정상 레지스트리를 보존한다.

```sh
python3 tools/equipment/build_patch523_rules.py \
  --content /private/current523/content \
  --catalog data/catalog_v19.json \
  --output /private/patch523-equipment-rules.json

TWILIGHT_PATCH523_EQUIPMENT_RULES=/private/patch523-equipment-rules.json \
TWILIGHT_PATCH523_EQUIPMENT_SHA256=7bb9110f40bc7261781bfdab59a3ec15237be209c2826ebc932c62774efe4610 \
godot --path .
```

팩 경로/해시를 명시해 시작해야 활성화한다. GUI 팩 설치기는 이번 범위에 포함하지 않는다. 없어도 기존 제작/강화와 세이브는 유지한다.

## 원문 증거와 보류

제공된 누적523 ZIP의 SHA256은 `d5192c3c735ff95c6b181bf2d4d77448d8b562fdb28dbd43f897fa4eae1f4832`이며 전체 ZIP CRC를 검사했다. 장비 심층 ZIP은 `ed26d0f3e48c58f60c403e8a526d5786139476dcbd716c7f029365425d8e4b85`, 인장 심층 ZIP은 `e55db3ae269d5d73bdc902c924d65da5a9d94f3fb74f26016f683d6682246c08`이다. 모두 Library에서 정식 materialization한 실제 파일을 읽었다.

컴파일러는24개 현재 표의 바이트 SHA를 고정한다. 제작 입력46254행, 출력30384행, 뷰1653행, 제한16462행을 전부 private 원문 조회에 보존한다. 뷰는1650개의 고유 제작 ID다. 확정 단일 결과·고유 재료 슬롯·현재 ID 연결·넓은 유효 기간·미해결 서버/플레이어 조건 부재 등의 보수적 조건을 모두 만족하는159개만 실행한다.

나머지는 무작위/복수 결과389, 카탈로그 미매핑/중복187, 후보 슬롯356, 통화 상태1, 서버/플레이어 조건490, 아이템 조건32, 물리 슬롯10, 기간/시간26개의 고유 제작 ID로 분리한다. 여러 후보를 모두 소비하거나 임의 선택하지 않는다. 64개 속성 귀걸이 변환은 원문 상태 후보를 보존하며 선택 의미가 미확정이라 실행하지 않는다. 뷰 없는261764/261774도 무제한 보장 강화로 노출하지 않는다.

수호·회복 인장161효과와 일반/보호 경로의 exact raw 확률·소비량, BonusType2022/8352 및 축복별 그룹 연결을 조회한다. Bm 확률723행을 게임 전체 강화 확률로 확대하지 않는다. 다중 장착 그룹, 슬롯 개방, 창고의 조건값, 제련·발동 훅 전체 실행은 미완료다.

## 검증

Godot4.7.2(`ed1daf0bf`)를 사용했다. 개별 사용자/XDG 프로필과 실제 현재 맵의 정확한 Git 팩을 사용하며 사용자 세이브를 읽거나 덮어쓰지 않았다. 초기 UI 검사에서 기존 검증 스테이지가 현재 원본 배치 NPC의 portrait를 제외한 오류를 발견했다. 스테이징에 실제 현재 맵의17개 명시적 원본 ID를 포함하도록 고쳤고83개/15081235bytes의 기존 Git 리소스를 추가했다. 합성 이미지나 오류 무시로 통과시키지 않았다.

검증 결과는 PR 설명과 최종 SHA 보고를 함께 참고한다. 원격 CI는 사용자 지시에 따라 수동 실행/재실행하지 않으며 커밋에 `[skip ci]`를 사용한다. 통합 후 전체 기능·과거 맵·전체 원본/실기기 검증은 별도다. 이 PR은 전체 원본 리소스 복원 완료가 아니다. 기존 `--source-dir` 검사는 과거 a1.zip 부재로 실패했고 현재 제공된523 ZIP3개는 별도로 SHA/CRC를 확인했다.
