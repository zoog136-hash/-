## 복구한 상태와 복구하지 못한 상태

- 재개 기준은 실제 GitHub main의 마지막 저장 커밋이다. 별도 PR #80의 S32 파서 `parse()`를 재사용하되 해당 브랜치나 파일을 수정하지 않았다.
- 이전 맵 Work의 무응답 원인: **확인 불가**. 별도 리소스 Work인 PR #80의 파일 전송 실패 및 환경 연결 끊김 기록은 이 맵 Work의 중단 원인으로 단정하지 않는다.
- 열린 PR #59(스킬), #76(맵 캡처·AUTO 진단), #80(전체 리소스 통합)의 원격 SHA 및 변경 경로를 확인했다. 실시간의 다른 Work 미커밋 내용은 열람할 수 없으므로 공동 수정 파일을 피했다. `scripts/world.gd`, 캐릭터·몬스터·스킬·UI·저장 코드와 기존 검사 파일은 변경하지 않았다.
- 이번 환경의 16개 첨부는 실제로 읽었다. `a2(1).zip`은 전달 실패로 읽거나 사용하지 못했다. 분할 자료를 그 파일의 완전한 복원본이라고 주장하지 않는다.

## 재개하여 저장한 실제 코드

1. 원본 맵 경로 탐색: 기존 BFS는 탐색 예산을 만나면 아직 큐에 있는 목표도 검사하지 않고 종료했다. 2개 노드 예산에서 인접 8방향이 모두 실패했고, 열린 129×129 격자의 56칸 경로도 기본 예산에서 실패했다. 직접 연결과 원본 8방향 규칙을 유지하는 제한된 A*로 수정했다. 저장한 칸은 예산 소진 후에도 탐색한다.
2. 원본 좌표: NaN·무한대·특이/비정상 역변환을 거부하고, 역변환 결과의 범위를 확인한 뒤 정수 좌표로 바꾼다. 구성 실패 뒤 이전 좌표를 사용할 수 없게 유지한다. 원점·투영은 호출자가 명시해야 하며 실게임 보정값을 추측하지 않는다.
3. 원본 지도 카탈로그: 전체 자료를 전용 경로에서 읽는다. SHA-256·정확한 바이트 수·ID·크기·원점·원본 판본을 확인한다. 다른 판본 및 원점 미확인 격자는 A3 규칙으로 이동시키지 않는다. 기존 미니맵·월드 충돌·세이브를 자동 교체하지 않는다.
4. 전체 복구 도구: ZIP 및 중첩 ZIP/7z를 읽고, 원본 변형을 CSV에 각각 보존한다. 원본 .map의 열 우선 바이트는 행 우선으로 변환하며 .txt는 원래의 행 순서를 보존한다. 잘못된 값·길이·형식을 임의로 보정하지 않는다. 압축된 실행 파일과 SQL은 실행하지 않는다.
5. 보고서의 CSV는 `.gdignore`로 Godot 번역 가져오기에서 제외한다. 원본 맵 격자는 FileAccess로 직접 읽으므로 데이터 검사를 유지한다.

## 마지막 저장 지점과 다음 재개 절차

현재 브랜치 HEAD와 `recovery-checkpoint.json`, 네 개 `MAP_*` 보고서, `source-catalog-validation.json`, 원본 데이터 팩이 재개 지점이다. main 및 다른 Draft PR은 그대로 보존한다.

1. GitHub에서 위 브랜치 HEAD를 확인하고, main이 새로 변경됐다면 현재 패치를 보존한 채 변경 범위를 먼저 비교한다.
2. 기존 프로젝트 루트에 복구 데이터 팩의 `data/l1j/recovered_maps/`를 복원한다. 같은 자료의 전체 스캔을 반복할 필요는 없다.
3. 필요한 경우 다음 원본 검사만 실행한다.

```sh
Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script res://tests/validate_recovered_map_catalog.gd
```

4. 다음 자료가 필요하다: 원본 타일 ID와 일치하는 시각 타일 팩, 누락 첨부 `a2(1).zip`, 현재 리니지M 판본/원본 맵 ID 대응, 원작 NPC·포털/층 연결·동적 문 배치.
5. 자료를 확보하면 맵별 투영과 픽셀 원점을 원본 배경에 맞춰 확인한 다음 기존 플레이 필드 렌더러·경로·NPC·층 이동·저장에 연결하고 전체 검사를 수행한다. 376개 다른 판본의 규칙 및 234개 미확인 원점을 먼저 확정한다.

더 진행하지 못한 이유는 **배경 타일 팩 및 판본/좌표/배치 대응의 부재**다. 해당 입력 없이 원작과 같은 전체 맵을 구현할 수 없으므로 이번에 가능한 코드 수정·자료 복구·검증을 저장하고 실행을 종료한다. 원인 불명의 이전 무응답을 추측하거나 원본 전체 복원을 완료했다고 보고하지 않는다.
