# 아이템 등급 복구 — 2026-10-26

## 원인과 확인 범위

기존 `catalog_v19.json`은 아이템 등급을 잘못 변환했다. 원본 `quality=3`을 일반, `quality=4`를 희귀, `quality=5`를 일반으로 저장했다. 결과적으로 원본 2,129개 도감에 영웅·전설이 하나도 없었다. 기존 `catalog_grade_policy.gd`는 이미지 파일명의 hero/legend 토큰으로 장비 32개만 임시 보정하고 있었다.

2026-10-26에 [원본 Inven 아이템 DB](https://lineagem.inven.co.kr/db/item/)의 공개 카테고리 페이지 40개에 있는 `lineagemDbItem`의 `data-props.items`를 읽었다. 기존 2,129개 `sourceId`와 이름이 모두 일치했다. 이름이나 그림으로 등급을 추측하지 않았고 신규 원본 4개는 추가하지 않았다. Inven 데이터의 직접 대조이며 NC 공식 데이터와 별도로 교차 확인했다는 의미는 아니다.

## 변경

- 도감 **1,060개** 수정: 일반→희귀 391개, 희귀→영웅 366개, 일반→전설 303개. 잘못된 기존 값은 `grade_original`에 보존한다.
- 전체 도감에 원본 `sourceQuality`를 보존한다. 확정 가능한 1,912개는 `grade_evidence=inven_item_quality`, 나머지 217개는 `inven_item_quality_unmapped`다. 명시적인 원본 quality를 이미지 파일명으로 덮어쓰지 않는다.
- 게임플레이 DB는 이름과 슬롯이 유일하게 일치하는 76개만 연결한다. 그중 실제 등급이 다른 **33개**를 수정한다. 원본 ID를 `grade_source_id`로만 기록해, 기존 자체 스탯을 원본 수치로 교체하지 않는다.
- 기존 장착·가방·창고의 저장 레코드는 로드 시 한 번 등급만 동기화한다. 원본 ID가 있으면 ID·이름·슬롯 모두 일치해야 하며, 잘못된 ID를 같은 이름으로 대신 연결하지 않는다. ID 없는 레거시 장비는 위 76개 검증된 이름·슬롯에만 연결한다. 개체 ID, 강화, 속성, 축복, 수치, 수량은 그대로 둔다.
- 저장된 바닥 아이템도 복구 시 검사한다. 일반 몬스터 드랍은 최신 드랍 DB의 등급을 사용한다. 직접 내려놓은 장비는 `item_record`와 `physical_item.data.record`를 동일 정책으로 보정하고, 뷰 생성 전에 외부 `grade`와 맞춘다. 습득 후에도 옛 등급이 되살아나지 않는다. 원본 입력 스냅샷, 바닥 ID·위치·맵·생성/만료 시각·수량·물리적 소유권은 변경하지 않는다.
- 등급 수정으로 실제 제작 검증이 실패하던 기존 **27개 제작식**의 비법서 등급 조건을 결과물 등급과 맞췄다. 기존 제작식의 아데나·비법서 외 재료·수량은 유지한다. 희귀 미만으로 내려간 결과물에는 희귀 이상 비법서 조건을 제거했다.
- 수정 단검이 고급에서 희귀로 정정되어, 기존 모든 희귀 이상 장비 제작 정책에 맞는 자체 제작식 1개를 기존 희귀 단검 제작식과 동일한 조건으로 추가했다. 이는 TWILIGHT 자체 밸런스이며 원작 제작식으로 취급하지 않는다.
- 몬스터별 아이템 목록, 등급별 드랍 확률, 드랍 횟수는 변경하지 않는다. 아이템이 올바른 등급의 드랍 선택에 참여한다.

예시: [군터의 단도](https://lineagem.inven.co.kr/db/item/176582)는 도감 일반/게임플레이 신화에서 전설로, [수정 단검](https://lineagem.inven.co.kr/db/item/423)은 도감 일반/게임플레이 고급에서 희귀로 정정했다. [마법 방어 투구](https://lineagem.inven.co.kr/db/item/256)는 게임플레이 희귀에서 원본 일반로 정정했다.
