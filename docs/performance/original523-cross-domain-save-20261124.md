## 실제로 바꾼 퀘스트

기존 지급 계획에는 `Exp / Item / NoReward / QuickSlotReg / Quest` 등은 있었지만 `Einasad` 처리가 없어 원본 38개의 퀘스트 보상을 거절했다. 원본 38관계 모두 RewardTypeID=5, RewardGetTimeTypeID=2, 기본 강화 유형 1, 클래스 0, 비혈맹/비즉시 사용이다. 참조 클래스 7049(9개), 1859(29개). 실제 **표시 수량은 30(1), 50(1), 100(23), 200(7), 300(1), 500(3), 5,000(2)**. 다른 종류 보상이 같이 있는 퀘스트 14개, MinLevel 999인 퀘스트 5개. 38개 전부를 실제 캐릭터로 받았다는 뜻이 아니다.

이제 축복과 완료 기록을 같은 파일 교체로 확정한 뒤에만 잔액을 갱신한다. UI에는 원본 수량이 보인다. 오프라인 정책은 **전액 수용할 수 없으면 완료 처리하지 않고 사용 후 다시 받기**다. 원본 서버의 초과분 처리가 밝혀졌다는 뜻이 아니다. 기존 기간 제거·즉시 완료 사용자 정책 및 원본 클래스/레벨/일일 횟수는 유지했다.

실제 원본팩 Main **58/58**: 레벨 1 거절, 레벨 60 테스트 캐릭터에서 75391 ‘몽환의 카네이션 선물’ +200, 80958 ‘아인하사드의 계절’ +500, 78343 +50. 78353 +30은 같은 배치에서 잔여 한도 부족 시 미수령으로 남았다. 디스크 실패 전 파일/잔액 보존, 파일 교체 후 오류 반환 시 실제 저장 검증, 기간 내 중복 방지, 재로드 확인. 원본 38행은 각 지급 계획까지 별도 확인했다.

## XP Hero와 저장 설계

기존에 제공된 XP Hero mod 표기 27.0.0 APK를 설치·실행하지 않고 ZIP으로만 재확인했다. 193,056,556바이트의 SHA-256은 `0a6e034f04821218f20b156020d9635ce46fc07d2a97ad1e9761aaab614f443d`. IL2CPP 메타데이터 19,756,888바이트에서 `ReserveSave` 문자열을 확인했다. 과거 정적 호출 분석은 골드/EXP가 저장을 예약하고 기존 예약이 있으면 새 코루틴을 만들지 않는 흐름을 기록했다. 심볼 존재만으로 이 흐름 전체를 재입증한 것은 아니다. 공식판, 저장 파일 레이아웃, 부분 저장, 비동기 I/O와 시간은 미확인이다.

TWILIGHT도 평범한 요청 100개를 한 번에 합쳤다. 이를 아이템/강화/잔액 같은 동기 거래에 확대하지 않았다. 대신 실제 **비동기 저장→완료**에서 동기 체크포인트에만 있던 안전한 소유권 계약을 연결했다. 워커가 만든 파일용 투영은 읽기 전용으로 직렬화하고, 완료 루프에는 봉인된 계정과 따로 반영할 필드 세 개만 남긴다. 이전에는 완료 시 SHA를 다시 읽어 두 번째 읽기 사이에 바뀐 외부 파일 해시에 옛 봉투가 결합될 수 있었고, 큰 봉투를 메인에서 복제했다. 이제 파일 일치 검사를 건너뛰는 것이 아니라 **검사한 바로 그 SHA**로 완성된 워커 전용 봉투를 넘긴다. 다음 저장 전 SHA가 다르면 종전처럼 재검증한다. 일반 소비자는 여전히 독립 사본.

## 같은 프로세스, v2 2캐릭터 3,100 실물 계정 (PC)

실제 파일, 별도 두 경로, 같은 이전 SHA와 같은 변경된 골드. 종전 worker→완료를 보존한 대조군과 세계의 현재 worker→완료를 순서 번갈아 8쌍(예열 1쌍 제외). 두 캐릭터/현재 금액/최종 파일 SHA가 매 회차 일치, 검사 **56/56**. 워커 시간에는 완료 폴링이 포함된다. 준비해 둔 스냅숏으로 시작하며 게임의 스냅숏 생성 시간과 폰 플래시 시간 측정은 아니다.
