# 원본 UI44 카드 창: 노드별 전체 규칙 순회 제거

기준 Android 523.848 JSON(06:03:20Z)은 UI 작업을 기록하지만, 16~100ms 각 프레임에 원인을 붙이지 않는다. 아래는 이 로그의 프레임 개선량이 아니라 **원본 코드/데이터를 읽고 현재 실행 경로에서 별도로 측정한 결과**다.

- 실제 경로: HUD `present_card_reveal` → `try_open_overlay_window("card_gacha_result", ...)` → 원본 `BM_Gacha.csb` → `source_main_window_kit._bind`. 동일한 공용 경로를 선택 보상과 지갑 재화 창도 쓴다. 자체 대체 화면이나 별개 창 구현은 바꾸지 않았다.
- 이전 트리 사본 축소와 다르다. 기존에는 노드마다 모든 패턴을 최대 두 번 훑었다. 3장 (53규칙), 10장 (114규칙). 이제 한 번의 바인딩에서만 규칙을 마지막 경로 이름별로 모아 중첩 원본 프로젝트까지 공유한다. 이름만으로 결정하지 않고 원래 **전체 접미사 일치**를 다시 확인한다. 제외가 최우선이고 그 외 일치 규칙은 기존 입력 순서대로 덮는다. 다음 창까지 들고 있지 않으므로 지난 콜백/텍스트가 섞이지 않는다.
- 영역/이름/중첩 프로젝트 체인, 버튼 핸들러·바인드 인수·삽입 순서와 표시/제외값을 같은 창 객체에서 이전 구현과 대조. 실제 UI44에서 보상 선택·재화·3장·10장 원본 결합이 동일하다. 카드 지급, 원본 그림, 확률, 저장, 재생 지연, 화면 항목 수 변경 없음.
- Godot 4.7.2 PC headless, 실제 UI44 pack.open (SHA-256 `5263d92594e8f44248ad799d6b56ba7816fc5f30bdc4ead0bafaf0bf2dd0b94c`), 디스크 원본 레코드 사용. 구/신을 교대로 한 프로세스에서 같은 팩과 카드 목록으로 비교. 전체 열기는 사용자가 보기 전에 실행하는 창의 동기 open()을 포함한다. 양쪽 동일하게 첫 예열 후 매회 선택 영역 캐시만 무효화. 측정 후 모두 뒤집기/등급 효과도 확인. 실제 소유 카드의 초상 DB/Android 표시 시간은 측정하지 않았다. 루트 바인딩 단독 타이머와 전체 창 타이머는 서로 더할 수 없다.

**이전 중앙값 / 최대 → 변경 중앙값 / 최대, ms.** 3·10장은 각 8쌍, 보상·재화는 16쌍. 첫 탐색도 포함하며 단계별 최대는 더 나빠진 경우가 있다.

실제 UI44 전후 대조 본검사와 독립 재실행 각 **97/97**. 추가 실제 팩 회귀: 카드 뽑기 **31/31**, 선택 보상 **16/16**, 재화 정보 **14/14**.

16ms 달성이나 Android의 지연 해결을 뜻하지 않는다. 원본 10장 창 자체가 여전히 수백 ms다. 보상/재화는 바인딩 단계만 측정했고 창 전체의 속도를 추정하지 않았다.
