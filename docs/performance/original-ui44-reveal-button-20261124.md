# 16ms 예산: 원본 카드의 ‘모두 확인’ 버튼

대상은 523.848 폰의 카드 끊김 보고다. 06:03:20Z JSON에는 각 16~100ms 프레임의 원인이 없으므로 이 버튼을 그 프레임들의 원인이라고 단정하지 않았다. 원본 523 UI44와 현재 실행 코드를 직접 대조했다. 이전 접미사 규칙 인덱스 변경은 창을 여는 단계였고, 이번 변경은 **열린 창에서 사용자가 카드를 뒤집는 단계**다.

## 비교 원리와 실제 수정

- OpenRA의 [Widget.Initialize / RenderBounds](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Game/Widgets/Widget.cs#L265-L299)는 초기화 때 결정한 위젯의 영역을 인스턴스로부터 얻는다. [WidgetLoader](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Game/Widgets/WidgetLoader.cs)는 선언으로부터 새 위젯을 만든다. TWILIGHT에서는 열린 카드마다 연출을 넣을 패널을 **이미 찾아 놓고도** `_node_size`가 같은 원본 파일을 다시 읽고 역직렬화했다. 위젯의 가변 표시 크기를 복사한 것이 아니라, 해당 인스턴스가 보유한 원본 자료에서 정확한 패널 오프셋의 작성 크기를 얻도록 바꿨다.
- 경로: `renewal_hud.present_card_reveal` → `_present_original_gacha` → 카드 하나/모두 확인 → `_play_card_effect` → 실제 `CardRevealStage.play_result_cell`. 동일한 도우미를 원본 합성 결과도 쓴다. 원본 장면·오프셋·Panel 분류가 맞지 않으면 기존 주인에게 돌려보낸다. 9분할 패널의 보정된 크기를 원본 작성 크기로 오인하지 않는다. 새 캐시·선행 로딩·부팅 비용·프레임 분할·지급/저장 로직 변경 없음.
- 비교 후보도 버렸다. [OpenTTD의 변경 영역 처리](https://docs.openttd.org/source/de/da1/gfx_8cpp_source#l01456)처럼 화면에 나오기 전 자식 색 전파를 묶는 실험은 3단계 fixture 방문 50→15, 실창 결과도 같았지만 3장 실제 창 열기에서 중앙 173.44→174.97ms, 최대 208.04→336.48ms였으므로 포함하지 않았다. XP Hero 27.0.0 비공식 제공판의 이전 정적 `ReserveSave` 대조는 일반 저장 예약에 관한 것으로, 카드 렌더 성능의 증거로 사용하지 않았다. 다른 게임의 실행 속도나 Android 수치는 측정하지 않았다.

- 패널 원본 재읽기 **1장 1→0회, 10장 10→0회**, 전 회차 동일. 이미 가진 화면의 자료를 재사용해 터치 지연을 줄였고, 회전/등급 연출을 줄이거나 결과를 다음 프레임으로 넘기지 않았다.
- 혼합 조건은 영웅/희귀/신화 카드명 fixture와 원본 UI44(초상/후보 없음). 원본 조건은 실제 523 `BuffCard#12231 매직 솔져`와 `AssetView#191631` / `Image/BuffCard/MagicSoldier.png`(SHA-256 `9915d6c1433ddc91fe15f977027342c175776d4a8f58310e26b724e51d50725d`). 1장 또는 동일 카드 10장과 회전 후보 1장 모두 실제 텍스처 연결 확인. 다른 원본 영웅 초상 10가지 또는 후보 16종의 비용은 별도다.
- 창 열기는 이번에 바꾸지 않은 대조군이다. 오픈 시간 편차를 이번 수정의 이득이나 퇴행으로 해석하지 않는다. 버튼→모든 연출 준비는 동기 `open_all`이 실제 모든 카드 회전 위젯을 만든 뒤 반환할 때까지의 벽시계; 다음 엔진 프레임은 거기서 처음 `process_frame`까지 포함한다. Linux CPU는 해당 메인 스레드의 scheduler 통계(`/proc/thread-self/schedstat`); 코어 스케줄링 집계 단위 때문에 짧은 표본은 수 ms 해상도다. GPU 표시/실기기 터치→화면 지연·폰 p95는 아니다. 16ms는 여전히 미달이다.
- 카드 수, 중복 터치 방지, 원본 패널 구도/위치·등급별 회전/확정 시간·화면 상태를 확인했다. 최종 실제 매직 솔져 한 장은 타이머를 당기지 않고 끝까지 기다려 원본 얼굴이 보이고 회전 위젯이 제거되는 것까지 검사한다. 지연 단축을 위해 연출의 의도된 초 단위 시간을 생략하지 않았다.

최종 실팩 매직 솔져 검사 **810/810**, 일반 CI fixture **4/4**, 기존 원본 UI44 회귀는 카드 뽑기 **31/31**, 합성 결과 **17/17** 통과.
