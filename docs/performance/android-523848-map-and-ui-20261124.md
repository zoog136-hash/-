## 1. 이동·자동사냥: 원본 S32의 좌우 바닥을 같은 셀에서 계산

실제 경로: 지도 스트리밍 → `_chunk_job/_decode_chunk` → `_install_chunk` → 기존 레이어/공간 인덱스. 정렬된 64×64 S32에서 좌우 타일 8,192개의 좌표·종류·참조용 임시 배열 네 개를 없앴다. 바닥 전체의 범위 판단은 한 번, 같은 셀의 원본 좌우 절반은 한 기준 좌표에서 계산한다. 덮개·오브젝트·정적 스프라이트 꼬리는 기존 경로 그대로다. 유효하지 않거나 정렬되지 않은 좌표의 원래 경로를 보존한다. 시야 축소, 프리로드 이동, 타일·충돌 생략 없음.

원본 Map/303 세 파일의 SHA 확인. 파일별 4,873 / 11,566 / 9,645개 오브젝트 파트 포함. 게임의 파일명 위치 후보와 고정 투영을 사용하여 워커 함수 전체(섹션 디코드→버킷)를 전후 교차 12쌍씩 두 번 측정, 각 1쌍 예열 제외. 파일 IO, 텍스처 업로드, 폰 프레임은 이 타이머 밖이다. 양쪽 레이어 값과 삽입 순서·버킷·꼬리·클립/장식 수가 매 회차 바이트 단위로 동일. 비정렬·음수·분수 축·범위 밖·무효 투영 포함 **98/98**. 아래는 **기존 중앙/최대 → 변경 중앙/최대, ms**.

## 2. 실제 원본 카드·가방·지도 창: 캐시 미스의 선택 영역만 보관

경로: 원본 창 바인딩 → `sprite_scene.configure_nodes/configure` → pack의 요청 레코드 → `source_node_scope.select`. 기존 #877의 중복 바인딩 읽기 억제와 달리 **같은 레코드를 한 번 읽은 뒤**에 어떤 구조를 복사하는지를 바꿨다. 디스크가 새로 역직렬화한 객체라면 남긴 노드/타임라인을 다시 복사하지 않는다. 원본 매니페스트를 직접 사용하는 경우에는 읽기 전용으로 투영하고 선택 결과만 분리한다. 전체 장면, 부분 허용 목록, 애니메이션 트랙, 캐시 히트의 독립 사본 및 크기 제한은 그대로다. 에셋 신규 제작/뽑기 결과/등급/애니메이션 규칙 변경 없음.

배포 UI44 매니페스트 SHA `5263d92594e8f44248ad799d6b56ba7816fc5f30bdc4ead0bafaf0bf2dd0b94c`. 실제 pack.open()과 104,034,368바이트 레코드 캐시를 이용했다. 전후 모두 같은 디스크 레코드 1회 읽기를 포함하며, 매번 순서가 보존된 동일한 출력 바이트를 확인했다(각 **115/115**). 각 12쌍, 첫 예열 한 쌍 제외.

카드(25개)와 가방 슬롯(5개)은 두 반복에서 중앙값이 내려갔다. 지역정보는 10개, 미니맵은 2개 노드. 미니맵 중앙값은 한 번 나빠졌다. **전체 꼬리 개선은 확인하지 못했다.** 카드 부분화 변경 쪽 최대가 109.510ms까지 튀었으며 원인은 확정할 수 없다.

**실제 카드 창 열기 A/B (헤드리스 PC):** 동일한 원본팩·3장(영웅/희귀/신화)으로 전후 창을 교대로 열고, 뒤집은 뒤 정확히 2장의 등급 효과와 배치 결과의 동일성을 확인. 기존·변경 코드 양쪽 모두 텍스처 예열 후 매 회 선택 영역 캐시를 비운 조건이다. 원본 창의 동기 `open()` 전체(측정 후 뒤집기/닫기), 각 8쌍, 2회. 첫 비교 **153.000 / 535.541 → 125.796 / 169.548ms**, 재실행 **154.332 / 170.800 → 150.369 / 162.454ms**. 첫 비교만 인용하면 이득을 과장한다. 전체 창은 16ms와 거리가 멀며 화면 표시까지 걸리는 시간·보통의 연속 캐시 히트·Android GPU 측정은 아니다. 별도 실제 팩 장착 회귀: **31/31**, 1/3/8장 각각 닫힌 카드 배치·뒤집기·등급 효과 확인.
