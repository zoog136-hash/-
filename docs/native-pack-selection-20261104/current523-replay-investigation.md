# 현행523 재생 재조사

기존 환경·브랜치·draft PR #236에서 조사했다. 실행 코드 기준은 `8268d6a07e8eecb57678a3975b8bb22881b3305f`이며, 이번 후속 변경은 조사 기록이다. 확인되지 않은 재생 기능을 추가하거나 팩 보호를 해제하지 않는다.

## 원문 재검사 결과

사용자가 제공한 기존 비공개 Drive 사본만 사용했다. Library의 실패한 전송은 재시도하지 않았다. 패키지 안의 코드는 실행하지 않고 표준 ZIP 및 시스템 `libbrotlidec`로 별도 검사했다.

| 검사 | 실제 결과 | 입증 범위 |
| --- | --- | --- |
| checkpoint 01~04의 DAT 69개 | 756,348,371 bytes. 실제 크기·SHA-1·SHA-256과 증거 레코드 및 현행523 매니페스트 기대값 일치 | 원문 동일성 |
| DAT 내부 전체 ZIP 항목 | 10,338개 모두 `.sp2`, method 0, 암호화 없음. 전체 CRC와 TOC 일치 | 컨테이너 무결성. 추가 PNG나 SPR 텍스트 없음 |
| 그중 선택한 원문 | 561개가 증거 레코드 및 기존 989개 레지스트리와 일치 | 선택한 물리 파일 동일성 |
| 기존 SP2 원문 989개 | 표준 Brotli 스트리밍 전체 입력 소모·종료 989/989 성공. 출력 198,552,018 bytes. 모두 첫 바이트 `FE` | 표준 압축 스트림. 출력 길이·해시는 앞서 보존한 바이트와 일치 |
| 제공 ZIP 6개 | CRC와 내부 package manifest의 크기·SHA 전수 일치 | 연결 묶음, 정정 묶음, checkpoint 4개의 원문 검증 |

집계·원본 ZIP 해시는 [current523-source-audit.json](current523-source-audit.json)에 기록했다. 과거 `a1.zip` 장부의 접근 실패는 별개다. 최신523 원문이 손상됐거나 확보되지 않았다는 결론으로 사용하지 않는다.

## 픽셀 해석과 공개 구현

현재 원문 인계 자료는 후보 문법의 EOF 989개, 후보 프레임 17,115개와 비빈 17,054개의 half-open 범위 일치를 기록한다. grouped RLE의 범위가 어긋난 반례 72개도 있다. 이는 후보 모델에 대한 원문 제약이며 내부 픽셀 순서·RGB·alpha·재생 시점의 M 클라이언트 확인은 아니다. 외곽 범위가 같고 내부 픽셀이 다른 후보도 가능하다는 정정을 유지한다.

공개 PakViewer의 고정 커밋 `fbad69239e3e3c12ec18dfc7722bed284be093cc`에 M용이라고 표시된 SP2 코드가 있지만, 제3자 변환기의 구현이다. 공개된 원본 M 엔진으로 분류하지 않는다. 해당 코드는 palette marker 1을 3색으로 고정하고 일부 방향값만 특별 처리하며, inclusive 크기와 grouped RLE를 사용한다. 원문 조사에서 보존한 1/3색 후보 구분 및 commandwise 범위 제약을 대신할 수 없다. [공개 SP2 구현](https://github.com/tony1223/PakViewer/blob/fbad69239e3e3c12ec18dfc7722bed284be093cc/src/Lin.Helper.Core/Sprite/L1SP2.cs).

RGB565 변환 도우미는 불투명 alpha를 출력한다. 이 사실은 실제 M의 shadow/sc/mu 합성식을 입증하지 않는다. PC 타일의 밝기 기반 alpha·색 보정이나 screen형 LUT를 M 원본 표시 규칙으로 가져오지 않는다. [공개 색 변환 도우미](https://github.com/tony1223/PakViewer/blob/fbad69239e3e3c12ec18dfc7722bed284be093cc/src/Lin.Helper.Core/Image/ImageConverter.cs), [PC 타일 처리 코드](https://github.com/tony1223/PakViewer/blob/fbad69239e3e3c12ec18dfc7722bed284be093cc/src/Lin.Helper.Core/Tile/L1Til.cs).

palette marker 1의 1색/3색 전체 구조 후보 검사 및 누적 u16 block reference wrap 지식은 버리지 않는다. 다만 이번 989개 자료에는 첫 참조 32768 이상이나 제어단어 1024의 실물 사례가 없으므로 그 경계의 실물 검증 완료로 표시하지 않는다. 과거 예제 하나가 전부를 지원한다고 간주하지 않는다.

기존 저장 집계와 별도로, 저장소 해독기를 불러오지 않은 새 direct-byte 후보 모델 검사도 989개 EOF와 위 17,115/17,054/61 집계를 재현했다. 구체적으로 `3442-0.sp2`~`3446-0.sp2` 및 `29306-0.sp2`의 marker 1은 1색 후보로 구조가 맞고, `21554-0.sp2`는 3색 후보다. 저장 마스크 3의 `10557-0.sp2`와 `7232-0.sp2`는 두 비트 그룹 후보로 끝까지 읽히며 공개 구현의 단순 그룹 수 3과 다르다. 989개 모두에서 index 0 샘플이 존재하므로 index 0을 임의 투명색으로 지우지 않는다. 이 추가 검사는 문법 모델의 반례를 구체화하며 실제 화면·색·합성 의미를 검증한 것은 아니다.

## 소비 경로 대조

현재 `Player.set_transform_visual()`은 원문 소비자 설정이 성공하면 Catalog의 프레임 생성 경로에 들어가기 전에 반환한다. `_update_visual()`도 그 경로에서 `motion.apply()`를 호출하지 않고 별도 원문 노드를 진행한다. 원문 노드가 표시되면 `GroundShadow`와 `PlayerActionFX`를 숨긴다. 따라서 그 경로에 Catalog 배율·절차 흔들기·추가 그림자를 새로 적용할 필요는 없다. 이 코드 검사는 523 소비자 연결이나 실물523 화면 승인과 다르다.

기존 base508 호환 정책에는 PC/호스트 기본 FPS, attr8/128 합성 후보, 제한된 기르타스/할파스 관찰이 명시돼 있다. 이 사용자 호환 기능을 수정하지 않으며, 523의 근거로 승격하지 않는다. source_snapshot 검사와 base508/523 분리를 유지한다.

과거 transform267/393의 run alias 및 idle 순서는 최신523의 SPR 선언을 직접 읽어 대조하기 전까지 역사적 참고다. alias 자체 SP2가 없다고 결손을 생성하지 않고 body/shadow/clothes의 상속·override와 Walk/Run을 구분한다. `36 FPS`, `:2`, attr8/128을 이 자료만으로 523 확정값으로 사용하지 않는다.

## 남은 구체적 입력과 재개 순서

이번 조사에서 **새로 확인된 M523 SP2 재생 사례는 0개**다. 기존 확정 PNG 2종의 설정 화면 표시는 유지된다. 원문 989개를 해석 완료나 캐릭터·몬스터·이펙트 활성화로 표시하지 않는다.

현재 로컬 자료에는 M 엔진 실행파일/소스 또는 같은 현행 프레임에 대한 확인된 M 출력이 없다. 공식 Drive 검색에서도 해당 APK/XAPK는 확인하지 못했다. Library 메타데이터에는 사용자 원본 `LineageM_KR12_1.10.20.xapk` 및 `리니지M_1.10.20a_APKPure.apk` 등이 확인되지만, 파일 바이트를 읽거나 그 안의 엔진을 검사한 상태가 아니다. 앞서 실패한 Library 전송을 다른 경로로 재시도하지 않는다.

정상 수신 가능한 사용자 원본 APK/XAPK 사본이 같은 작업 환경에 정식 전달되면, 먼저 패키지·서명·엔진 파일의 원문 해시와 빌드/지역/버전 관계를 확인해야 한다. 파일명만으로 현행523과 일치한다고 가정하지 않는다. 이어서 실제 SP2 읽기·palette/픽셀·alpha·좌표·프레임 주소 처리와 SPR clock/alias/방향 dispatch를 확인한다. 이를 뒷받침하는 정확한 M 프레임·방향·동작 출력 또는 공개 M 구현 근거가 있는 사례부터 private pack에 연결하고 실제 Main/UI·재진입·저장 실패 검사를 진행한다.

표준 압축 검증이나 픽셀 후보 일치만으로 이 단계를 건너뛰지 않는다. 확률·재화 값의 자체 구현 허용은 이 픽셀·좌표·충돌·활성 조건에 적용하지 않는다. 이번 조사에는 원본·세이브 변경, 원본 이미지 업로드, main/다른 PR 병합, CI 실행이 없다.
