큰 PNG의 대부분은 통행 금지 영역이므로 순간이동은 전체 캔버스 무작위 추측 대신 실제 검수 바닥 후보에서 목적지를 찾는다. 유효 목적지가 없거나 귀환 팩을 읽지 못하면 주문 비용과 소비 아이템을 차감하지 않는다.

기존 PR #137 진입 전용 배치(revision 2026102001, 계획 SHA `6dddc9772b9b1605a0aeaaa1b3a52e6ae88aa99ecb7d3e9b4ddd9946fdb83da4`)의 저장은 검증된 현재 팩으로만 이전한다. 원래 저장의 실제 바이트를 SHA별 백업으로 보존한 뒤 좌표만 새 진입점으로 옮긴다. 진행·장비·컬렉션과 보스 HP/대기 시간은 보존한다. 알려지지 않은 계획 해시나 손상된 팩/백업은 기존과 같이 로드를 거절하며 원래 저장을 덮어쓰지 않는다.

이 다섯 ID는 기존 ID를 재사용한다. 전체 지형의 벽·물·문·가구 검수는 **미완료**다. 미검수 구역은 통행을 닫아 둔다. 신규 팩의 전경 가림 복원과 원래 서버의 몬스터/보스 좌표 대응도 미완료다. 이번 배치는 검수한 바닥에 새로 정의한 로컬 사냥 구역이다. DB, 기존 지역 JSON, 종별 수치/보상/드롭, 애니메이션은 바꾸지 않았다. 과거 전투 지형을 사용하려면 `--legacy-map-layouts`, 아덴·신념만 과거 지형으로 되돌리려면 `--legacy-aden-faith-layouts`로 실행한다. 사용자 병합 요청의 범위는 이번 배치이며 전체 맵 복원 완료를 뜻하지 않는다.

검증된 팩을 설치하면 일반 실행에서 해당 5개 ID에 PNG가 연결된다. 팩이 없으면 기존 맵을 유지한다. PNG 저장에는 **지역별 팩 계획 해시**를 기록한다. 팩 누락/변경으로 저장 복원이 불가능하면 저장을 덮어쓰지 않는다. 기존 저장의 다른 레이아웃 좌표는 검수 진입점으로 이전하고 캐릭터 진행 데이터는 보존한다. `--native-png-maps`는 기존과 같이 별도의 검증 저장 공간을 사용한다.

## 재설치

사용자가 2026-10-20 재배포 권한을 확인하고 Git 업로드를 명시적으로 요청했다. 앞선 비공개 보관 지시를 변경한 범위에서 실제 원본 9개와 새 5맵 청크를 Git에 포함한다. 제3자에게 더 넓은 라이선스를 부여한다고 주장하지 않는다. 사용자 Drive 원본 폴더에는 `Aden.png`, `13398.png`, `13401.png`, `13417.png`, `13472.png`가 있다. 변환 팩은 `TWILIGHT-Aden-Faith-PNG-20261020-private-v1.zip.part001`~`003`이며 합본/조각 해시는 `data/maps/aden_faith_png_archive.json`에 있다. 2026-10-20 사용자 지정 비공개 My Drive 최상위 폴더에 3조각을 업로드했다. 세 파일의 비공개 상태·지정 부모 폴더·크기 확인 후 실제 재다운로드 바이트의 조각/합본 SHA와 ZIP CRC 및 176개 청크 디코딩·설치를 검증했다. 개인 폴더와 파일 ID는 공개하지 않는다.

이 Drive ZIP은 revision 2026102001의 **과거 백업**이다. 이번 2026102002의 배치/통행 메타데이터는 Git에 있다. 오래된 ZIP을 현재 계획과 같은 팩이라고 설치하거나 해시 검사를 생략하지 않는다. 현재 실행에는 아래 Git 번들을 사용한다.

현재 Git checkout에는 `external_map_packs/aden_faith_png_v1/`의 실제 이미지와 최신 메타데이터가 있으므로 PC/Android Godot 편집기에서 별도 Drive 설치 없이 자동 탐색한다. 이 경로는 사용자 승인으로 Git에 추적되며 일반 clone에서도 자동 탐색한다. 설치된 APK는 앱의 `user://aden_faith_png_maps/`를 사용한다. Android 앱 데이터 접근/설치 절차 및 실기 성능은 이 환경에서 검증하지 못했다.

원본 5개로 재생성할 경우 기존 13474 소스는 필요 없다:

```sh
python3 tools/map_restore/build_native_png_maps.py \
  --sources /private/originals \
  --plan data/maps/aden_faith_png_plan.json \
  --output /private/new-aden-faith-pack
python3 tools/map_restore/verify_native_png_pack.py \
  --pack /private/new-aden-faith-pack --plan data/maps/aden_faith_png_plan.json
```

검증 팩은 원본 배율 1:1, 최대 1024px 청크 176개다. 검수 바닥/충돌 계획을 바꾸면 계획 해시와 팩을 함께 재생성해야 한다. 기존 v5 6맵 팩은 바이트를 바꾸지 않는다. `build_world_regions.py` 재생성으로 두 PNG 팩의 정의가 덮어써지지 않는지 검사한다.

## Android 이동 중 끊김 수정

이전 렌더러는 카메라 이동으로 새 청크가 나타날 때 화면 스레드에서 PNG 디코딩과 전경 픽셀 분리를 실행했다. 단일 저우선순위 worker로 CPU 작업을 옮기고, GPU 업로드는 프레임당 청크 하나로 나눈다. 512px 주변을 미리 읽으며 돌아온 경로는 LRU 텍스처를 재사용한다. 모바일은 가시 청크·미리 읽기·캐시 합계 RGBA 48 MiB, 데스크톱은 96 MiB로 제한한다. worker는 별도로 청크 하나와 해당 전경 조각만 CPU에 보유한다. 진입 시 첫 화면 준비는 동기로 수행한다. 지역 전환 시 이전 worker를 정리한다. 과도한 축소는 청크를 누락하는 대신 카메라 표시 범위를 제한한다.

에스카로스의 바닥 다각형 114개는 공간 색인으로 후보만 찾은 뒤 기존과 동일한 정확한 다각형 판정을 사용한다. 17,696개 점의 경계/무작위 비교에서 원래 합집합 판정과 일치했다. 전체 프레임의 다른 비용은 남아 있으므로 Android 이동 렉이 모두 해결됐다고 단정하지 않는다.

실제 Main과 기존 v5 원본으로 동일 경로 480프레임씩 측정한 결과는 `performance.json`에 있다. 소프트웨어 OpenGL 수치는 Android FPS 증명이 아니다. 실제 PNG 통합 검사는 비공개 팩으로 따로 실행하고, 공개 CI에서 팩 없는 통합 검사는 명시적으로 SKIP한다.

## 최초 PNG 연결 작업의 과거 검증 기록

아래는 몬스터 배치 이전 커밋의 기록이다. 최종 배치 검증과 최종 커밋 CI는 PR #137의 후속 검증 기록으로 구분한다.

- 원본 5개 → 176개 실제 PNG 청크 전수 디코딩/SHA 검증. 별도 재생성 결과와 설치 팩의 index SHA 일치. 3조각 합본 CRC/해시/설치 검증 통과. 정확한 3파일/목적지에 대한 사용자 승인 후 Drive 업로드·비공개 메타데이터·실제 재다운로드 SHA·새 폴더 설치까지 통과했다.
- 일반 실행 실제 Main: 새 5맵 225검사 통과(이동, 물리 경계, 카메라/축소, 포털/층 이동/귀환, 저장/재진입, 팩 누락 시 현재 필드·저장 보존). 별도 native 저장 실행도 225검사 통과.
- 기존 v5 실제 Main: 643검사, 101개 경로 목표, 실제 캐릭터 이동 101,493px 통과. 이 경로 검사는 물리 60Hz를 유지하며 `--fixed-fps 10`으로 시뮬레이션 시간을 가속했다. 지역 인구의 wake loop가 정지시킨 몬스터를 다시 깨워 경로 검사 중 캐릭터를 죽이는 문제는 검사에서 인구 wake loop까지 정지시켜 분리했다. 실제 인구/전투 검사는 별도로 유지한다.

## 사용자 승인에 따른 Git 원본 전달

- 원본 9개: `external_map_packs/source_pngs/manifest.json`에 각 파일의 크기·해상도·원본 SHA와 실제 저장 파일을 기록했다. 원본 총 517,237,588바이트.
- 8개 원본은 그대로 PNG로 추적한다. `Aden.png`(107,386,586바이트)는 GitHub의 100 MiB 파일 제한 때문에 64 MiB와 나머지의 두 **바이트 조각**으로 보관한다. 이미지 분할이나 재압축을 하지 않았고 아래 도구가 원래 PNG 바이트로 복원한다. Git LFS나 Drive 접속은 필요 없다.
- 새 런타임 팩은 `external_map_packs/aden_faith_png_v1/`의 187개 파일이다. 실제 PNG 청크 176개와 overview/manifest/index가 들어 있다. 최초 208,202,726바이트에서 이번 배치로 바뀐 것은 메타데이터뿐이며 현재 크기/해시는 장부와 receipt에 기록한다. 기존 v5 210개 파일은 그대로 보존한다.
- 상위 `.gdignore`는 거대한 원본을 Godot가 GPU용으로 자동 임포트하지 않게 유지한다. 게임은 기존 `Image.load` 청크 경로로 읽는다. 원본 보관은 APK 포함·전체 충돌 완성·Android 실기 성공과 구분한다.

```sh
# Git 추적·원본 SHA·9개 전체 PNG 디코딩 확인
python3 tools/map_restore/verify_map_source_pngs.py --require-tracked --decode
# 재생성이 필요한 경우 9개 원본 PNG를 새 외부 폴더에 복원
python3 tools/map_restore/verify_map_source_pngs.py --restore-to /private/restored-map-sources --decode
# 이미 checkout된 게임용 팩 검증
python3 tools/map_restore/verify_native_png_pack.py --pack external_map_packs/aden_faith_png_v1 --plan data/maps/aden_faith_png_plan.json
```

아덴·신념 번들이 Git에 있는 경우 Main 검사는 220개다. 앞선 225개 중 5개는 번들이 없는 환경의 기본 설치 폴더 손상·삭제 검사이며 그 조건은 그대로 유지한다. 별도 저장 이전 검사에서는 실제 번들보다 우선하는 테스트 소유 손상 설치를 지정해 원본 저장 바이트 보호를 계속 검증한다. 최종 Git 원격 사본 및 CI 결과는 PR에서 해당 커밋과 함께 기록한다.

`--legacy-aden-faith-layouts`는 아덴·신념 4층만 기존 지형/인구로 실행하고 기존 v5 PNG 필드는 유지하는 호환 옵션이다. 원래 4개 밀집 구역과 28개 서로 다른 보스 생명 검사는 이 명시적 기존 배치에서 그대로 실행하며 수치를 낮추지 않는다. 실제 새 5맵은 별도의 원본 PNG Main 검사에서 검수 구역 통행과 새 로컬 배치를 검사한다. 두 legacy 옵션의 저장 복귀는 실제 자식 Main 프로세스로 확인한다.

기존 A3 격자·서비스·비주얼·아덴 보스 계약 검사는 `legacy_aden_faith_fixture.gd`를 통해 같은 실제 Main을 명시적 기존 배치로 재실행한다. 기존 조건을 삭제하거나 몬스터·보스 수를 낮추지 않는다. 일반 전투·변신 저장 검사는 계속 새 PNG 아덴에서 실제 캐릭터 충돌 반경을 검사한다.
