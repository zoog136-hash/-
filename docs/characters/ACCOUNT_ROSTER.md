# 로컬 캐릭터 계정과 13슬롯

기존 작업 브랜치 `feature/character-roster-account-sharing-20261112`에서 이어서 구현했다. 초기 기준은 `main` `8634f931b6b749865c52dd6437b2d18d5f91c174`이며, 후속 작업 전 최신 main `b488fb3`을 병합한 체크포인트는 `29e2e06`이다. 후속 로비 통합에서는 main `8d030bb5ab68d78b7f45d2fef82a34cf0beb24a1`의 원본 UI·메모리 최적화와 최신 main `1c1bd94033b29b0642c79bf8c2473d73ba2953b3`의 스킬 변경도 기존 브랜치로 병합해 보존했다. main으로의 PR 병합·APK 전달·실기기 실행 여부는 각각 별도 확인한다.

## 실행 경로와 저장 선택

일반 화면 실행은 Loading → 캐릭터 선택 → Main 순서다. 플레이 중 목록으로 돌아가면 저장 성공 후 World 전체를 교체한다. 타이머, 전투 대상, 입력 및 소유자 캐시를 다음 캐릭터에 재사용하지 않는다. 저장 실패 시 현재 캐릭터에 남는다. 기존 직업 변경 동작을 여러 캐릭터를 대신하는 기능으로 사용하지 않는다.

최대 13슬롯은 사용자가 요청한 TWILIGHT 정책이다. **생성 가능 직업 13개와 저장 슬롯 13개는 별개**이며 같은 직업으로 여러 캐릭터를 만들 수 있다. 슬롯 유료 확장·캐릭터 삭제·온라인 계정 인증은 범위에 포함하지 않는다.

`save_profile.gd`가 로비와 World의 저장 namespace 및 원본 지도 저장 이전 포인터를 함께 결정한다. 정상 포인터가 있으면 그 최신 대상 저장을 사용한다. 포인터 손상·누락 대상·허용 범위 밖 경로는 오류를 표시하고 생성·이전·접속을 막는다. 기본 저장으로 조용히 돌아가 오래된 진행을 덮어쓰지 않는다. 로비의 다시 확인은 경로를 새로 조회한다. 명시적으로 주입한 테스트 store의 경로는 바꾸지 않는다.

- 일반: `twilight_v20_save.json`; native PNG 모드는 `twilight_native_png_save.json`.
- 디버그 Android 및 `--playtest-full-cards`: 기존 전종 카드 시험 namespace 안에서 별도 13슬롯 계정을 사용한다. 일반 캐릭터와 시험 지급을 섞지 않는다.
- `--base508-source-test`, `--aden523-review`, `--png-review`, 디버그 `--growth-lab`는 명시적 검수·개발 경로로 분리하여 일반 로비를 우회한다.
- 저장 위치·포인터 조회 실패 상태나 구버전 계정의 업그레이드 대기 상태에서는 이전 화면의 선택/생성 콜백도 저장을 진행하지 않는다.

로스터는 최대 12자 이름과 직업을 두 줄로 표시한다. 360px 폭에서 목록을 가로로 밀어내지 않으며, 버튼 위에서 세로 드래그해도 목록을 스크롤할 수 있다. 접속과 새 생성 버튼은 목록 하단까지 스크롤하여 접근한다.

## 원문 사용과 한계

`current523_definition_rows.gd`의 기존 검증 입력만 사용한다. 원문 ZIP이 없거나 잘못됐으면 신규 생성은 거절하고 기존 저장을 보존한다. 분석용 다섯 표를 정상 원문 설치의 대체물로 사용하지 않는다.

- ZIP: 25,031,173 bytes, SHA-256 `d5192c3c735ff95c6b181bf2d4d77448d8b562fdb28dbd43f897fa4eae1f4832`. 초기 작업에서 CRC 전수 통과 및 1,075개 멤버를 확인했다. 원문 ZIP·원본 아트는 공개 Git 산출물에 포함하지 않는다.
- `Class.CanCreateClient` 13행의 원본 ID는 `1,2,3,4,5,7,8,34,52,81,94,111,142`다. 순번 1~13으로 원본 ID를 대체하지 않는다. 초기 STR/DEX/CON/INT/WIS/CHA를 적용하고 추가 원문 속성은 출처 메타데이터로 보존한다.
- `ClassAssets`는 `(ClassID, GenderID)` 복합 키로 정확히 한 행이어야 한다. 생성 가능한 조합은 25개이며 마검사는 남성만 있다. 신규 생성은 원문에 있는 성별만 허용한다. 기존 저장의 미지정 성별 0은 직업·진행을 유지한 채 한 번 선택할 수 있다.
- `BuffCardDeck` 1/2/98은 `CharacterBased=false`, 스킬 덱 41은 `true`인지 확인한다. 카드 스킬 각성과 캐릭터가 학습한 스킬은 서로 다른 저장 소유자다.
- `AccountSlot` 원문 두 행의 값 2/11을 보존·검증하되 원작의 무료 슬롯 정책이라고 추정하지 않는다.
- 검증된 source523 초상화 팩이 있을 때만 해당 초상화를 표시한다. 없으면 설명을 표시하며 다른 이미지를 만들거나 대신 넣지 않는다. 로비의 원본 전후 CSB 효과는 별도 검증 팩에서 연결·명시 재생한다. Spine JSON·atlas·페이지는 검증하되 호환 3.6 런타임이 없어 본체 재생은 남아 있다. [연출 입력·검증 범위](ORIGINAL_LOBBY.md)를 참고한다.
- `CreateTerritoryID`는 원문 메타데이터로 보존한다. 직업별 원작 최초 생성 지역을 복원한 것은 아니며 새 캐릭터는 기존 TWILIGHT 아덴 시작 정책을 사용한다.

## 계정이 소유하는 저장 구조

모든 캐릭터의 정보와 현재 선택을 **한 로컬 계정 저장 파일**에 담는다. 모든 정보가 캐릭터 사이에 공유된다는 뜻은 아니다. 스키마 v2의 `character_account.shared`가 계정 공유 자산을, `characters[].state`가 각각의 개인 진행을 소유하며 `selected`는 안정적인 캐릭터 ID다.

```text
character_account
  schema / revision / selected
  shared
  characters[]
    id / name / class_id / gender_id / initialized / state
  기존 저장 백업과 이전 기록
```

기존 World 소비자를 위한 루트의 선택 캐릭터 payload는 `shared + selected.state`의 호환용 투영이다. 별도의 독립 원본이 아니며, 계정 본문과 투영이 불일치하면 덮어쓰지 않는다. 로스터·선택·공유 자산·개인 상태는 기존 원자 저장으로 함께 커밋한다. 계정 파일만 저장되고 개인 파일은 실패하는 다중 파일 거래를 만들지 않는다.

계정 공유:

- 창고 stack·물리 개체 전체
- 변신·마법인형·성물 보유/중복/합성, 카드 컬렉션 정책
- 아이템 컬렉션, 문양·수호성 진행
- 해당 카드의 옵션·스킬 각성과 할파스 강화
- 계정 전체 물리 아이템 ID 할당자 및 원본 stack 소비·분할 원장

캐릭터별:

- 레벨·경험치·기본 스탯·HP/MP·아데나·소지품·장비
- 학습 스킬·퀵슬롯·자동사용·쿨다운·버프·퀘스트·몬스터도감 등 개인 진행
- 변신/인형/성물의 실제 선택, 추가 소환 선택 및 성물 추가 소환의 만료 시각
- 에바 아이템을 소비해 얻는 추가 소환 해금. 원문 `SaveDB` 버프이며 카드 덱 보유의 계정 범위만으로 해금까지 계정 공유라고 추정하지 않는다.
- 일반 맵 위치와 원본523 좌표, 바닥 아이템, 기존 몬스터·보스 상태

A가 부분 소비한 원본 아이템을 보유하고 B가 접속해도 공유 원장의 남은 수량은 증명되어야 한다. 비접속 캐릭터의 물리 개체는 원장 검증에만 포함하며 B의 소지량·무게·장착·사용 가능 아이템으로 취급하지 않는다. JSON을 읽은 뒤 비접속 snapshot의 증명 숫자도 정규화하되 원본 정의 행을 통째로 바꾸지 않는다. 책 학습·퀘스트·영구 소비 스탯의 지급 이력은 개인 상태로 유지한다.

## 원본 장비 컬렉션 등록

실제 원문 거래 검사에서 `마법 망토 · 원본#914`의 식별 표시가 기존 GUIDE 요구명 `마법 망토`와 달라 등록을 거부하는 결함을 확인했다. 원본 장비의 전체 이름·source ID·실물 UID·영수증 원래 이름은 유지하고, 현재 아카이브 신원·ItemClass 원문·descriptor·DTO 이름을 대조한 카탈로그에만 별도 비교 이름을 둔다. 수식어를 모든 이름에서 지우거나 저장을 재명명하지 않는다. 중복 원본 ID는 새 비교 이름을 받지 못한다.

기존 GUIDE 447개와 각인·이벤트·축복 이름 정책은 보존한다. 모든 current523 ItemBook 표를 새로 매핑했다는 뜻은 아니다. 원문 컬렉션 1672와 동일한 두 재료(ItemClass 914·256, 각각 +5)·MPPlus10을 실제 거래 보강 대상으로 사용한다. 빠른 신원 회귀 66조건을 기본 core에 포함한다.

## 기존 저장 보존과 명시적 이전

단일 캐릭터 저장은 로비의 백업/이전 버튼으로 이전한다. `원본경로.pre-character-account-<전체 SHA-256>`의 원본 바이트가 일치한 뒤 계정 저장을 만든다. 알 수 없는 기존 필드도 보존한다.

초기 로스터 v1 계정은 자동으로 쓰지 않고 `upgrade:true`로 연다. 로비는 계정 구조 업그레이드 버튼만 제공하며, 원본 SHA 검증 백업 후 v2로 이전한다. 실패하면 원인과 기존 파일 보존 상태를 표시한다. 완료 후 같은 버튼을 다시 실행하여 타이머를 재분배하지 않는다.

v1에서는 성물 추가 소환 타이머가 잘못 공유되었으므로 현재 타이머가 유효하고 선택 캐릭터의 성물 ID와 일치할 때만 그 캐릭터의 시간으로 보존한다. 다른 캐릭터의 사라진 만료 시각은 복구했다고 만들지 않는다. 해당 선택·해금과 과거 공유 타이머의 원문은 보존하면서 미확정 시간은 효과를 차단하고 실제 보유 소환 주문서로 다시 활성화할 수 있게 한다. 로비는 이 처리가 필요한 캐릭터 수를 알려준다. 처음부터 타이머가 없었던 정상 옛 저장의 기존 호환 정책은 유지한다.

백업·원본·기존 브랜치는 삭제하지 않는다. 손상 구조·중복 이름·중복 물리 ID·외부 저장 변경은 덮어쓰지 않는다. 저장 응답이 실패해도 의도한 전체 payload가 이미 정확히 저장되었다면 그 바이트를 확인해 중복 생성을 막는다.

원문 Main과 창고 검사는 실행 전후 게임 코드·테스트 해시 변경과 script/resource 오류가 없었다. 원본 ZIP도 전후 동일한 바이트 수와 SHA-256이었다. Main의 스킬 검사는 원문에 연결된 ID의 학습 상태 fixture를 사용한 저장 검사이며, 스킬북 학습 비용 검증을 뜻하지 않는다. 이름 검사는 `hud.character_state` 연결 확인이며 원본 HUD에 이름이 시각적으로 표시되는지 검증한 것은 아니다.
