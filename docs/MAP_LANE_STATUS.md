# 맵 전용 작업 통합 상태

UI / 맵 / 나머지 통합의 세 작업 단위를 유지하라는 사용자 지시에 따라,
기존 PR222와 기존 맵 작업공간을 맵 담당으로 사용한다. 새 PR이나 작업공간을
추가하지 않는다. 다른 두 작업 단위의 PR 정리는 상위 통합 담당 범위다.

## 이관과 보존

- PR222 원래 HEAD: `5de681308591a566115c266a69d01585c0f47d28`.
- 기존 base: PR217의 `feature/original-spr-runtime-20261101`,
  `c2e4dbd539431cde52cd7b636b5a74da7c004435`.
- 대조한 main: `00b84cfe19c05e01d30208384bf7fbcc4ae6bbf2`.
- 후속 통합 기준: `1333851bb2eb193a6ac1fc3e3b852787c08994ff`.
  동일 맵 브랜치에 충돌 없이 반영했다. 승인됐던 한 줄 타입 수정도 이 main의
  blob과 동일하므로 최신 main 대비 중복 수정이 없다. main 자체에는 쓰지 않는다.
- 기존 base는 main의 조상이다. 기존 변경44파일 중35파일은 main에 없고,
  9파일은 다르며, 동일한 파일은0개다. 이를 버리거나 중복 완료로 처리하지 않는다.
- 같은 맵 브랜치에서 main을 충돌 없이 병합했다. main 대비 원래44파일의
  변경은 그대로 유지하며, main의523 world-links 연결도 보존한다.
- 원래 PR222 HEAD는 로컬 `backup/pr222-before-map-consolidation-20261105`에도
  보존한다. 이전 맵 HEAD `786b9aac66fbc5582c090e2c902e5e2f6a9e74b6`와
  그 브랜치·검증 기록·정상 보유 원본·팩·세이브도 유지한다.
- main/다른 기능 브랜치에 쓰지 않는다. 원본 자산·팩·세이브·캡처를 공개 Git에
  추가하지 않고, 전체/수동 CI나 중복 리소스팩 업로드를 실행하지 않는다.

이 PR의 기존 기능은 base508 복원 도구와 명시적 source-edge 검토 경로다.
기본 게임을 이 검토 모드로 전환하지 않으며, 현행523 지형 또는 원작 통행 의미로
재분류하지 않는다. 과거33/34 맵의 원본 입장 컴포넌트 검토 결과는 과거 실행
범위다. 이 작업공간에서 새로 그 전체 검사를 실행한 결과가 아니다.

## 상세 맵·타일 인계 수신

사용자가 전달한 상세 감사 ZIP을 공식 Library 경로로 로컬 수신했다.
크기1,459,516byte, SHA256
`f44fffc357fa0542901e05335abfb6e928f181bd227bb75933f0f746b1e11d31`,
ZIP CRC와 manifest의 네 payload 해시가 일치한다. 맵·타일 목록은16,825행
(Map8,311 / Tile8,514), 별도 SP2 참조 목록은989행이다. UI 의미 분석과
사운드는 이 맵 작업에서 처리하지 않는다.

보유 런타임 목록과 메타데이터를 조인한 결과, 맵6,570개(보존 SEG12개 포함)의
크기·제공 SHA와 TI2 7,557개의 크기·SHA·CRC에서 차이가 없다. 이는 원본
재디코딩 또는 모든 파일의 실제 게임 open 관측을 뜻하지 않는다. 원본 Land의
슬래시 없는 AssetPath도 그대로 보존하며 제외 범위를 활성화하지 않는다.

989 SP2의 member·크기·CRC·파일 ID도 기존 registry와 일치한다. 선언 헤더
참조는986개에 있고 `24592-0.sp2`, `24592-8.sp2`, `24595-0.sp2` 세 파일에는
없다. 이 목록에는 액션 본문·틱·앵커·레이어가 없어 원본 정적 배치 연결을
완성할 수 없다. 같은989개를 다시 해시·디코딩·렌더하거나 원문 배치를
추측해 만들지 않았다.

## 원문 정적 SPR 지도 연결과 남은 범위

보유989 SP2(75,664,378byte)의 독립 로딩·추정 디코딩은 이미 별도 소비자에 있다.
main 디코더 SHA256
`ab105e0c54e5c45658513631443f3a356e6e14d849d97daccffc6ad25df49cbe`는
기존36,246항목 /17,115프레임 전체 렌더 검사와 동일하다. 이번에 다시 검사하거나
새 디코더·미사용 가드·임의 UI/그림을 추가하지 않는다. M 원작 픽셀/알파/합성
동등성 또는 실제 지도 배치의 증명은 아니다.

전역 ZIP 수신 차단과 이미 보유한 S32 원문을 구분한다. 보유 독립 원문 장부와
S32 tail에는 아덴 정적 효과2,125건의 ID·두 u16 값·선택 i32·바이트 위치가 있다.
184개 S32/184종 ID 전부가 보유 SP2 파일 ID와 직접 대응한다. 배치 자료 전체가
없다는 이전 판단은 이 보유 자료를 충분히 활용하지 못한 설명이었다.

`current523_static_spr.gd`를 실제 지도 렌더러에 연결했다. 확인된 S32 tail을
읽고, 고정 SHA의989 registry와 사용되는 SP2의 크기/SHA를 검사한 후 기존
디코더의 원본 유래 픽셀을 그린다. 원문 ID·원시 위치·확장값·trailer·출처 해시는
보존한다. 별칭을 추측해 다른 ID로 바꾸거나 지형·통행·포탈·전투를 추가하지 않는다.

공통 새 tail 파서를 정상577루트/6,558 S32에 적용해36,240건을 읽었고 파싱
실패0이었다.36,011건은 보유 동일 ID의 literal `-0.sp2`와 대응한다. 미대응229건의
ID는0,1850,1886,1887,3977,3978,3979,3980,3996,3997,3998,3999다.
이는 현재 직접 파일 선택 규칙의 미대응이다. 후속 수신한 전역 원문에도 이 ID의
별칭은 없으므로 별칭 해결로 집계하지 않으며 다른 ID/PC 자산으로 대신하지 않는다.
이 검사는 새 파서/참조 연결 검사이고577루트 전체 SPR 실플레이가 아니다.

별도 승인된 기존 Drive 단일 원문 `list_29.spr`는 공식 경로로 실제 수신했다.
크기1,210,871byte, SHA256
`03378c1a8b462d60c863e4808298918c6af57161491ef872eb4021aa1e058538`,
SHA1/CRC32도 인계값과 일치한다.793개 선언 중 아덴273건/6종
(29175,29177,29179,29181,29183,29475)의 본문이 있다. 이 파일을 선택하면
지원되는 비방향성 action3의 원문 프레임 순서·지속값을 저장 순서 추정보다
우선한다. 첫 프레임14→0 같은 원문 순서도 유지한다. alias, 다른 이미지 그룹,
프레임 modifier는 임의 처리하지 않는다.105.clothes 참조는 보존하고 미연결로
표시한다. 이 단일 원문 수신은30개 선언/전역 인계 완료가 아니다.

기존 게임 설정 화면의 맵 설정에서 정적 SPR 원문 폴더와 원문 선언 폴더 또는
`list_29.spr` 경로를 지정하고 표시를 켠 뒤 저장한다. 다음 원문 맵 입장에 적용되며 기본은
꺼짐이다. registry가 있는 정상 보유 폴더를 읽을 수 있어 ZIP 재생성이나 자동
Drive 다운로드가 필요하지 않다. 잘못된 registry/선언은 맵 입장 전 거부한다.
원본·설정과 게임 저장은 별개이고, 기존17조각 맵팩도 바꾸지 않았다.

다음은 명시적이고 되돌릴 수 있는 **TWILIGHT 표시 정책**이다.

- raw u16 두 값을 현재 필드 좌표계에 절대 위치로 투영한다. 원작 발 기준 증명이 아니다.
- 같은 ID의 literal `-0.sp2`, 선택 저장 그룹(기본0)을 사용한다. 접미사/비트를 방향이라고 부르지 않는다.
- 원문 선언/action3 프레임이 없으면 제외한다. 기본 정지, 자체 틱/초를0~60으로 조정할 수 있다.
- 원문 지속값의 비율은 보존하지만 초 환산·action3 자동 활성 의미는 원작 미확정이다.
- 자체 앵커(-48~48px)와 레이어(-4095~-1)를 설정한다. 기본 앵커0, 지형 위/인물 뒤다.
- 기존 `opaque_samples`/RGB565 bit replication 추정 디코딩을 사용한다. 검은 바탕을 임의 제거하지 않는다.

원작 alpha/blend·가림·추가 attachment 합성·자동 활성은 아직 증명하지 않았다.
모르는/손상/부재 항목은 미대응으로 계수하고 새 픽셀·좌표·통로를 만들지 않는다.
기존 플레이어 상대 SP2 샘플을 원문 지도 배치로 계산하지 않는다.

새 아덴 바이트 대조는2,694항목 통과(2,125원문 레코드/184청크)다.
실제 Main/GL의 원문 입장·175건 표시·레이어를 숨겼을 때 framebuffer 변경·
원문 순서131건·시간 경과 애니메이션·실제 걷기·잘못된 팩 입장 거부·세이브
보존·복귀/재입장은27항목 통과했다. 재로드가 재생성하는 노드의 identity와
재개되는 host simulation clock을 원본 저장/보스 상태 손실과 혼동하지 않는다.
원래 오류가 있던 중간 실행은 실패로 남겼고 필수 원본의 생성 캐시만 복구했다.
최신 main 반영 뒤 같은27항목이 다시 실패0·로그 오류0으로 통과했다. 이어서

SPR 표시·기존 저장 해시·아이템/재화·컬렉션/보스 상태 복원을 확인했다.
재접속 기대 장부도 JSON full precision으로 써서 보스 deadline을 반올림하지 않는다.
복귀 시 기한이 지난 ready 보스의 정상 alive 전환은 허용하되 기존 deadline,
layout revision과 플레이어 진행도는 보존하는 것으로 검사한다.

`3c8faabe2ea0166ef7d7d5262ef5e4bda042f45cbaf05da504fc3e23eb8bfca0`.

## 사용자 지정 연결 제외:229기록·11개 맵 SPR ID·명시적 M 더미

## 나머지 M 포탈 연결:실제 캐릭터 레벨·기존 면적 착지 API

229건·11종·명시적 M 더미 제외와 독립적인 포탈 소비 경로를 이어 연결했다.
원격 main 기준은 이 구현 시작 시1333851bb2eb193a6ac1fc3e3b852787c08994ff이며,
PR230의 공개 정의 로더/카탈로그를 다시 만들거나 다른 담당의 코드를 병합하지 않았다.
기존 provider를 확장해 같은 검증 정의팩의 원문을 소비한다.

M Content의 LandAttributeType91=MinLevel/Unit1,101=MaxLevel/Unit1을 실제
`world.level`에 연결했다. 예시 원문은 LandAttribute29991의 Land22701/MinLevel55,
55011의 Land32823/MaxLevel80이다. 둘 다Param1/2/3=0인 양의 단일 수치다.
이 값들을 새로 추정하지 않는다. 정확한 ID/이름/Unit과 양의 정수 Value,
0인Param들을 가진 행만 최소 이상/최대 이하로 비교한다. 행의Territory가 있으면
기존 원문 영역 필터를 통과한 출발/도착 셀에만 적용한다.0/누락·미해석 형식과
다른 조건은 종전대로 보류한다. actor context 없는 기존 provider API도 보류를
유지한다. UI가 임의로 넘기는 레벨 대신 실제 Main의 캐릭터 레벨을 읽으며,
이 레벨도 포탈 걷기 요청 ticket에 포함해 오래된 요청이 다른 조건으로 사용되지 않게 했다.

면적 목적지는 기존 `source_field.choose_source_landing()`를 실제 수동 포탈 소비
경로에 연결했다. 새로운 원작 착지 규칙을 만든 것이 아니다. 기본값은 여전히

```ini
portal_landing_policy="OWN_FIRST_CLEAR_IN_DECLARED_REGION_V1"
```

해당 도착점의 레벨/지역 속성과 원문 포탈/양끝Land/원문Territory 동일성을 소비한다.

원문 레벨 충족과 설정한 착지 정책만으로 입장 허가를 만들지 않는다. 기간/주간/서버/

표시가 아니다. 새 이미지·Sprite·프레임·UI·PC 호환은 도입하지 않았으며 제외 항목을

**추가 테스트·검증·품질 평가 실행 없이 작성한 미검증 연결 코드**다.

## 기존 시간·서버 소비자 재사용:맵 기간 조건 연결

제외 항목이나 자식 규칙을 다시 찾지 않고 남은 기간 소비 경로를 이어 연결했다.
별도 서버 선택기·달력·구매/던전 시간 풀을 만들지 않고 다음 기존 계약을 재사용한다.

- collection_runtime.source_server_context():선택된 source_snapshot/ServiceRegionCode/WorldNo의 복사본.
- source_collection_conditions.valid_context():명시된 서버 프로필 형식. 언어·Land·OS에서 서버를 고르지 않는다.
- source523_shop_runtime의 명시적 calendar_offset_minutes/server_context/clock_highwater와 저장 차단 상태.
- monsterbook523_clock의 civil date 형식/윤년 처리.
- patch523_craft_conditions.valid_window():원문 날짜·명시 UTC offset과 Unix구간의 일치 및 기존 시작 포함/끝 제외 계약.

새 `current523_map_runtime_context.capture()`가 이 기존 값을 읽고 컨트롤러가
정의 provider에 전달한다. 서버 snapshot 표식을 다른 버전으로 덮어쓰지 않는다.
카드 프로필과 기존 상점의 region/world가 정확히 일치하고 시간대가 명시되어 있으며
상점 상태가 정상이고 시스템 시각이 기존 highwater보다 이전이 아닐 때만 달력
문맥을 제공한다. 미설정·충돌·역행에는 보류한다. 상점 거래·보상/시간 풀·세이브를
호출/변경하지 않는다. ticket 문맥에는 서버/달력 선택 신원을 포함하되 매초 변하는
now_unix를 넣지 않아 시각 흐름만으로 걷기 요청이 무효화되지 않게 했다.

provider는 기존 검증 정의팩의 LandTimeLimit→LandTimeLimitGroup→지역별
DateTimes 원문 참조를 실제 출발/도착 Land에 연결한다. 선택된 ServiceRegionCode에
해당하는 날짜 표만 읽고 일반DateTimes나 빈JP/CN 표를 KR로 대신하지 않는다.
유효한 원문 StartDateTimeID/EndDateTimeID와 기존 명시 시간대가 모두 있어야
공통 구간 소비자로 open/closed를 판정한다.0/0은 달력 구간 미지정일 뿐 무제한
플레이를 뜻하지 않으며,한쪽 참조 누락·유효하지 않은 날짜/정책에는 보류한다.
시작 포함/끝 제외는 기존 공유 소비자의 명시 정책이며 M 원작 경계 동등성은
확정하지 않는다. 새 시간 수치나 UTC기준을 추정해 넣지 않았다.

달력 개방과 잔여시간 소유권은 별개다. 기존 dungeon_play.pool()는 해당 던전
실행의 저장/차감 주체이며 이 M 맵 세션을 소유하지 않는다. 잔여시간을 읽어 입장만
허용하고 실제 차감하지 않는 경로를 만들지 않았다. LandTimeLimit은 계속
native_land_time_pool_owner_required로 보류하며,기간이 닫힘/미확인인 이유도
별도로 소비한다. 주간 행은 기존 RAW_SERVICE_REGION_TIMES;
NO_UTC_OR_WEEKDAY_INFERENCE 계약으로 남긴다. 상점 구매 주간 reset을 맵 개방
스케줄로 바꾸거나 ServiceTypeID13을 ServerLimitSetID13으로 혼동하지 않는다.

기존 포탈 목록 문구에 달력 판정과 공유 시간풀 연결 대기를 연결했다. 새 UI나
이미지·Sprite·프레임·PC 호환은 만들지 않았다. 자동 활성·원작 충돌·기타 서버/기간
조건을 충족한 것으로 주장하지 않으며 이전 레벨·안전 착지·제외 코드는 유지한다.

**추가 테스트·검증·품질 평가 실행 없이 작성한 미검증 연결 코드**다.

추가하지 않는다. 원본 판정 값과 공유 소비자/자체 달력 정책의 경계를 보존한다.


주간 조건의 필요한 모바일 원문/공식 자료 탐색도 좁은 범위에서 진행했다.

원작 충돌 속성/방향/점유 및 자동 포탈 활성도 확인된 M 실행 계약이 없어 기존 자체
통행/수동 이동과 구분한다. 달력 판정 연결을 잔여시간 차감·주간 개방·서버 입장 조건
전체의 완료로 표시하지 않는다. 이 범위는 원본 파일 수신 재시도나 제외 기록 조사로
해결할 문제가 아니며,해당 M 실행 계약/공유 시간 세션 소유 API가 필요한 미완이다.

## 맵 소유 시간 세션 연결 — 미검증 구현

앞선 `native_land_time_pool_owner_required`만으로 중단했던 경계를 실제 맵 소유
등록·차감·종료 코드에 연결한다. 다른 던전의 `pool()`/재충전/거래/저장 ABI를
빌려 잔여시간으로 표시하지 않는다. 기존 M 정의 provider의 LandTimeLimit 및
LandTimeLimitGroup 원문을 전달하며 원문 값과 별도 자체 정책을 구분한다.

`current523_map_time_pool.gd`의 자체 정책은
`OWN_BOUNDED_SOURCE_LIMIT_NO_AUTO_RESET_V1`이다. 양의 원문 TimeLimit을 초
한도로 소비하며 ms 단위로 누적 차감한다. 기존 원문의 ServiceTypeID13만 이
제한된 소비 경로에서 지원하며 다른 서비스 타입은 보류한다. 그룹 원문 전체와
정의팩 pin을 보존한다. ContentsResetScheduleTypeID·MaxRechargeTime 등은 raw로
보존하지만 자동 초기화·재충전·충전권 거래를 구현하거나 다른 던전 수식을 가져오지
않는다. 이는 원작 초기화/계정 범위를 복원했다는 주장이 아니라 유한한 시간 사용을
제공하는 보수적 TWILIGHT 정책이다. 기간·주간·서버 제한을 해제하지 않는다.
기존 `user://current523_aden_play.cfg`의 play 섹션에서 `map_time_policy`를
`OWN_BOUNDED_SOURCE_LIMIT_NO_AUTO_RESET_V1` 또는 `DISABLED`로 명시할 수 있다.
기본은 전자이며 DISABLED는 시간 제한 지역의 입장을 보류하는 값이다. 시간을
무제한으로 바꾸지 않는다. 실행 중 정책 변경은 종료 후에만 가능하고, 기존 설정
화면은 이 값을 보존할 뿐 새로운 선택 UI를 추가하지 않는다.

원본 게임 세이브를 변경하지 않고 별도 `user://current523_map_time_v1.json`에서
선택된 ServiceRegionCode/WorldNo 범위의 그룹 잔여시간과 세션을 보존한다.
로컬 캐릭터가 달라도 같은 범위·그룹을 공유하는 것은 자체 정책이다. snapshot
표시를 바꾸어 새 한도를 얻지 않으며, 재읽기·재입장으로 기존 한도를 보충하지 않는다.
등록 표식 이후 장부 누락/손상, 기등록 그룹 원문 변경, 시간 역행, 다른 실행자의 세션과
동시 저장에는 안전 보류한다. 비정상 종료의 미정산 시간은 반환하지 않고 보수적으로
정산하는 자체 복구 정책이다. 원문 파일·이전 팩·게임 세이브를 삭제하지 않는다.

컨트롤러의 일반 소스 맵 선택·재열기에도 per-Land 원문 조건을 연결한다. 검증 정의
provider가 없는 일반 Land 입장을 무제한으로 취급하지 않는다. 원문 좌표의 안전한
셀과 후보 렌더 준비 후 그룹을 등록하고, 위치 설정 저장 후 시간 세션을 전환한다.
전환 실패 시 현재 필드는 유지하고 이전 위치 설정 복원을 시도한다. 새 목적지의
렌더/위치 저장 실패만으로 새 시간 세션을 시작하지 않는다. 포탈 전환에서는 원문
출발/도착 조건을 이동 직전 다시 소비하며, 같은 시간그룹 간 이동은 기존 한도를
정산·유지한다. 무제한 지역으로 이동하거나 복귀할 때도 이전 소유 세션을 종료한다.

기존 Main에 비시각 Timer를 연결해 1초마다 자체 시간 세션을 차감하고, 기간 종료·
서버 문맥 변경·시간 만료/저장 실패에는 기존 안전 복귀를 호출한다. 1초는 자체
감시 주기이며 M의 원작 tick이 아니다. 기존 세이브 호출에도 차감을 연결하되,
시간 장부 오류로 이미 성공한 아이템/진행도 저장을 실패로 바꾸어 중복 환불하지 않는다.
맵 실행 중 정의 제공자를 교체하는 경로는 세션 종료 후에만 허용한다. 기존 포탈
상태 문구와 맵 안내에 자체 시간정책을 표시하며 새 UI/이미지는 만들지 않는다.

달력 open이나 시간 한도 충족만으로 주간·경쟁 던전·미해석 속성/입장 조건을 통과시키지
않는다. WeekTypeID·WaitingMinutes 순서/포함 관계, 원작 점유/충돌 및 자동 포탈
트리거·입장료 상속은 여전히 M 실행 근거가 없는 미완이다. 제외229건/11종과 원문
명시 dummy·미선언 항목은 그대로 제외하며 원본 분모에서 지우지 않는다.

사용자의 최신 지시에 따라 **새 테스트·검증·품질 평가를 실행하지 않은 코드**다.
실제 Main 시간 차감·만료 복귀·재접속 성공이나 새 원본 소비 비율로 집계하지 않는다.
기존577/997 대표 지역 기록과 과거 SPR 표시 결과를 이번 변경의 통과로 승계하지 않는다.

## 기존 SPR 설정 버튼 → 현재 Main 맵 소비자 연결 — 미검증 구현

기존 설정 버튼은 `STATIC_SPR.save_options()`만 호출해 다음 원문 입장까지 현재
맵 소비자에 전달하지 않았다. 이제 같은 버튼에서
`world.apply_current523_static_spr_options()` → 맵 컨트롤러 → 현재 원문 렌더러로
이어지는 호출을 연결한다. 새 버튼/화면/이미지를 만들지 않고 기존 저장 버튼과
상태 문구만 사용한다. 원문 선언·파일·그룹·프레임을 이미 확인된 소비자에 전달하는
구현이며 새로운 원작 동작·방향·활성·합성 규칙을 만들지 않는다.

현재 맵에서는 후보 SPR 소비자를 보유 M registry/선언과 현재 필드 좌표계로 구성하고
원자적 설정 저장이 성공한 뒤 교체한다. 원문을 읽을 수 없거나 설정 저장이 실패하면
기존 소비자와 설정을 유지한다. 꺼짐은 기존 소비자를 제거하고 다음 입장에서도
꺼짐을 보존한다. 맵 비실행 상태에서는 같은 API가 설정만 저장하며 다음 입장이
기존 설정을 읽는다. 원문 이동 필드가 아닌 표시에서 SPR을 켜려는 요청은 보류한다.

지도 타일을 실제 읽는 기존 경로에서 S32 후미의 원시 정적 레코드와 파일/해시/offset
출처를 같은 제한된 청크 캐시에 유지한다. SPR 표시가 꺼져 있어도 현재 읽은 레코드를
보존하므로 켤 때 원본 전역 목록을 다시 훑거나 맵을 재입장하지 않는다. 현재 화면의
같은 원문 레코드만 새 소비자에 전달한다. 목록 보유·파싱이나 설정 교체를 실제
그리기 관측/원본 사용 완료로 집계하지 않는다. 기존 실제 Main `_draw` 관측 경계와
부분 사용 장부는 그대로 유지한다.

설정 적용 동안 지도 전환과 저장 후보의 교차를 보류하고, 현재 필드/플레이어 위치/
카메라/충돌/포탈 정의/맵 시간 세션은 교체하지 않는다. 기존229건·11종·원문 명시
dummy/미선언 항목 제외와 PC 비호환 상태도 새 소비자에서 동일하게 적용한다.
추가로 종료 저장 오류가 있을 때 실제 시간 종료/설정 저장 오류를 기존 신호와
HUD에 전달한다. 시간 종료 실패를 자동 시작 해제 오류로만 표시하지 않는다.

이번 연결도 **추가 테스트·검증·렌더·품질 평가 실행 없이 작성한 미검증 코드**다.
원본 픽셀/이미지·Sprite·프레임·UI 제작, 원본/팩/세이브 변경, 새 실제 소비 수치나
95% 사용 달성은 보고하지 않는다. 이전 체크포인트의 관측 수치를 유지한다.
