# 동료 원본 SP2 프레임 준비 재사용

OPT05의 동료 렌더링 경로를 검증했다. 원본 Twm `pack-63fb1355`에서 목각인형 12539와 버그베어의 몽둥이 성물 24765를 사용했다. 액션 JSON과 SP2 멤버는 게임의 원본 뱅크 매니페스트에 고정된 파일이다. Windows 원본 분석의 `RawSpriteFile` 및 `SpriteAsset` 경로와 Android `0x5544460`의 캐시 조회는 리소스 재사용의 정적 근거다. 이번 변경은 Godot에서 이미 쓰는 프레임 계획을 동료의 원본 SP2 재생에 적용한다.

주·보조 동료의 각 원본 뷰에 프레임 계획을 최대 16개 보관한다. 기존 레이어 텍스처와 순서를 유지하며 합성용 텍스처를 만들지 않는다. 계획을 재사용할 때도 원본 멤버의 검증 결과를 확인한다. 적용 범위는 `original_source_preview.gd`, `follower_motion.gd`, `relic_motion.gd`, `native_doll_subslot_visual.gd`다.

## 검증

Linux Godot 4.7.2에서 두 실제 원본 동료를 한 스텝마다 함께 재생했다. 준비된 SP2 파일을 사용해 240스텝으로 구성된 7회 실행의 중앙값을 비교했다. 원본 SP2 경로를 직접 비교하기 위해 사전 생성된 아틀라스 사용을 끈 별도 테스트 환경이다.

| 재생 상태 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 대기 | 482µs | 237µs |
| 걷기 | 435µs | 237µs |
| 방향·동작 전환 포함 | 465µs | 339µs |

비교한 동료 재생 640단계의 프레임, 레이어 순서, 위치, 텍스처 바이트, 알파와 블렌드가 일치했다. `actor_frame_composite_cache_test.gd`는 계획 상한, 재생 중 원본 멤버 삭제 시 거부, 화면 출력 일치를 점검한다. `frame_plan_limit_test.gd`와 `source_subslot_attachment_retry_test.gd`도 통과했다. 구버전 인형·성물 자산을 사용하는 두 테스트는 같은 준비본에서 `main`과 변경본 모두 동일 항목에 실패했다.

Android 523.743 화면의 2,958ms 최악 프레임에는 2,908ms의 미계측 구간이 있었다. 동료 203ms/초와 몬스터 231ms/초는 별도의 마지막 실행 구간 기록이다. 미계측 지연의 원인과 이 변경의 Android 프레임 시간 및 메모리 효과는 확인되지 않았다.
