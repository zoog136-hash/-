# 원본 UI 표시 머티리얼 조회 비용

원본 클라이언트의 Android `0x553ae80` 배칭은 호환 인접 명령의 상태를 기준으로 병합한다. Windows 확장76의 TextureCache와 Sprite 소유권도 캐시 보유와 활성 소비자의 수명을 나눈다. 두 정적 근거는 공유 상태와 렌더 순서를 그대로 유지할 이유를 제공한다. 아래 머티리얼 조회 구조는 TWILIGHT의 Godot 구현이다.

`sprite_scene.gd`의 CSB 색·알파 적용과 버튼·비트맵 글꼴 등이 `source_material.gd::bind_display`를 호출한다. 매 호출에서 원래 머티리얼을 두 번 찾고, 머티리얼 ID와 표시 색을 임시 배열에 넣어 조회했다. 이제 원래 머티리얼을 한 번 찾고, 머티리얼 ID 아래의 색별 사전에서 조회한다. 캐시 전체 최대 4,096개, 공유 머티리얼 동일성, 외부 셰이더 파라미터 변경 복구, 퇴출 후에도 활성 스프라이트가 보유한 머티리얼의 수명을 유지한다. 셰이더나 그리기 순서는 변경하지 않는다.

| Linux Godot 4.7.2 측정 | 기준 중앙값 | 변경 중앙값 |
| --- | ---: | ---: |
| 합성 스프라이트 6,000개에 색 적용, 전후 각 30회 | 19.083ms | 16.286ms |
| 실제 Twm 변신 외곽 CSB, 전후 각 240회 | 0.227ms | 0.232ms |
| 실제 Twm 강화 CSB, 전후 각 240회 | 0.347ms | 0.337ms |

합성 결과에는 셰이더 변경 확인과 배정 비용도 들어 있다. 두 원본 장면의 전체 프레임 적용 시간에서는 일관된 개선이 관측되지 않았다. 두 장면의 모든 샘플 노드 상태가 일치했으며 OpenGL 프레임버퍼 10개가 바이트 단위로 같았다. 지배석 창에서 실제 Twm 팩을 쓰는 검사 16개, 공유 머티리얼 검사 87개(GPU 비교 25개 포함), 비트맵 글꼴 127개, Android 합성 셰이더 53개 통과. Android에서 앱 실행 및 프레임 시간은 미검증이다.
