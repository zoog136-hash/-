# UI08: domination merge outcome probability

Baseline main 0c3bcba. PDF p37 and table 285 `DominationStoneMergeOutputGroup` distinguish the original client's special probability preview from the current two-stage offline reward policy. That policy is not established as the original server algorithm. This patch corrects a misleading TWILIGHT display, without changing the policy.

Actual path: source_main_domination_stone_window._fusion_probability -> runtime.merge_quote returns the special gate probability. runtime.merge tries that gate, then samples the entire base_groups pool on failure. The pool may contain the same group. The old message called the gate probability "same kind retained", omitting base re-selection. New message displays the final same-group probability and labels the special gate separately, explicitly including fallback selection.

For scale S=1,000,000, special gate weight p, and same-group base weight b, final numerator = p*S+(S-p)*b over denominator S*S. Integer arithmetic preserves sub-micro-unit probabilities until the existing two-decimal percentage formatting. Duplicate rows with the same group contribute separate intervals. No RNG calls, payout changes, new row selection, inventory/save mutation, or per-frame calculation are added. This is evaluated only when the probability action is invoked. Source validation and grade probability display remain in their existing owners.

Synthetic illustration: p=200,000, b=250,000 yields 40%, although the old label showed 20%. The source-native preview's residual-group renormalization is a different contract, and is not silently applied to the offline payout.
