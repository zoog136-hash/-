# 카드 컬렉션 전체 스크롤과 게임 연결 점검

원본 UI 팩의 `Change_CollectionView/Nd_Collection/ListView_Button`, `Change_List_Collection.csb`와 그 안의 `CardListView`를 사용한다. 기존 실행 창은 `card_collections.snapshot`을 읽은 뒤 결과를 60행에서 잘라서, 이후 행을 스크롤로 탐색할 수 없었다. 이 창의 스크롤 범위를 전체 필터 결과로 설정하고 원본 리스트의 높이·간격으로 화면 근처 행만 구성한다. 각 행은 멤버 카드의 가로 스크롤을 따로 가진다. 카드에서 시작한 세로 스와이프는 해당 행이 화면 밖으로 나가도 손을 뗄 때까지 이어진다. 소유권, 보너스 합계, 필터 조건과 저장은 기존 런타임을 사용한다.

## 검증

Twm UI 매니페스트 핀 `335af82d2794bafa4a9273cb309cde3a59f06a764467e66b58e29321c98eebaa`를 통과한 원본 창에 저장소의 523 변신 컬렉션 투영 841행과 대응 카드 카탈로그를 넣었다. 보유 상태와 화면 호스트는 테스트용이다. 수정 전에는 첫 60행과 카드 노드 181개를 만들며 끝 행에 도달할 수 없었다. 수정 후 전체 841행이 스크롤 범위에 포함됐고, 처음에는 4행과 카드 노드 8개를 만들었다. 스와이프 입력으로 841번째 행까지 도달했다. Linux headless의 준비 회차 이후 3회 중앙값은 약 661ms에서 216ms로 줄었다. 팩을 이미 연 상태에서 창 구성 호출만 재며, Android 프레임·메모리 측정과 실제 계정 플레이는 미검증이다.

자동 검사에서는 400행 합성 데이터로 끝 행, 두 행의 독립 가로 이동, 세로 드래그, 터치 도중 화면 밖 행의 수명과 필터 초기화를 확인했다. 컬렉션 20개, 리스트 드래그 7개 및 공통 창 179개 검사를 통과했다. OPT28 가운데 카드 컬렉션 화면에 해당하는 범위다.

## 스프라이트 외 추가 확인

| 영역 | 확인 결과 |
| --- | --- |
| 아이템 컬렉션 | #682·#683에서 원본 컬렉션 등록과 완성 효과를 연결했다. 현행 창은 12행씩 순환하고 검색·등급 선택은 숨긴다. 곧바로 원하는 아이템을 찾는 경로가 빠져 있다. 등록·효과 회귀 검사 57개를 통과했다. |
| 상점 | 현재 원본 상점은 이미 전체 상품 접근과 화면 근처 카드 생성 경로를 갖춘다. 기존 상점 전체 목록 검사 9개로 확인했다. `CurrencyDiscountRate`는 입력 목록에 있지만, 구매 견적은 원본 클래스체인지 할인 조건을 확정하지 못해 해당 경로를 거절한다. |
| 아이템 사용 | `ItemUsageLimitGroup`은 상자 사용 전 그룹 대기 시간을 검사하고 성공 시 사용 시각을 저장한다. `ConsumeTerritories`도 원본 소모품 사용 조건을 구성하는 경로가 있다. 두 테이블의 항목별 실제 적용 범위는 별도 검증 대상으로 남는다. |
| 제작 | #686 이후 메인 탭은 `ItemCraftRecommend.Priority`를 사용한다. 원본 `CraftableItemSortOrder` 12행을 현재 제작 목록 정렬에 연결하는 소비자는 확인되지 않았다. |
| 퀘스트 | 원본 창 준비 검사 39개를 통과했다. 보상 소비의 저장 재연결 시험은 이 작업의 격리 환경에 이전 보상 지급 저장과 SHA가 없어 초기 조건에서 종료됐다. |
