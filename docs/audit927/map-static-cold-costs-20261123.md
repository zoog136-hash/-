# 523 원본 지도 정적 표시: 지연 도착과 빈 render target

비교 기준은 GitHub main `c74e371e`의 동등 트리를 가진 로컬 베이스 `35857bd4`입니다. Windows 원본에는 사전 조회한 배치의 분할 처리와 셀 객체 재사용 경로가 있지만 그 구현이나 메모리 예산을 Godot에 복제하지 않았습니다.

- 명령·아틀라스가 모두 비어 있고 그리기 수가 0인 완료 지형 블록도 기존과 같은 사각 셀 위치와 계수·빈 명령을 유지합니다. 그 셀의 투명 화면을 만들기 위한 512 픽셀 SubViewport와 하위 그리기 노드는 생성하지 않습니다. 그려야 할 블록의 생성, 레이어 순서, 준비 판정에는 변경이 없습니다.
- 같은 가시 청크 목록에 원본 tail이 비동기로 도착하거나 캐시에서 제거되면 정적 배열 캐시를 무효화합니다. 그 프레임의 가시 영역과 읽기 작업 결과가 정해진 뒤 모아서 처리합니다. 새 지형/충돌 읽기나 카메라 이동을 유발하지 않습니다.
- 정적 SPR 구성 한 번에 이미 추가한 원본 그림과 텍스처는 128개 캐시에서 밀려도 동일한 텍스처를 재사용합니다. 현재 draw 목록이 이미 보유한 텍스처를 사용하는 것으로 캐시 상한을 늘리지 않습니다. 결정적인 빈 픽셀·디코딩 실패는 그 구성에서만 재사용하되 배치별 실패·빈 이미지 진단과 다음 구성의 재시도를 유지합니다.

## 확인한 범위

- Godot 4.7.2 headless 렌더러 단위 142개, 정적 캐시 단위 7개 검사 통과. 렌더러 단위에서 같은 카메라의 지연 tail 순서, 충돌 바이트 불변, 다음 프레임 불필요한 합성 없음, 명령 없는 블록의 계수 불변을 확인했습니다. 베이스 렌더러에 같은 회귀 테스트를 실행하면 신규 회귀 검사 3개가 실패합니다.
- 기존/수정 `_bake_block`을 번갈아 실행한 16개 빈 블록 headless CPU fixture(각 30회, 최초 제외): 시야 렌더 대상 생성 16→0, 묶음 p50 283→37 µs, p95 355→40 µs. GPU와 실제 원본 입장의 개선폭이 아닙니다.
- 129개 고유 프레임, 밀려난 프레임 반복 배치와 성공하지 않은 프레임 반복을 합친 정적 fixture에서 표시 순서·횟수, 기존 캐시 상한, 반복 결괏값과 실패 후 새 구성 재검사를 확인했습니다. 테스트 그림은 메모리 fixture일 뿐 전달된 원본 픽셀이 아닙니다.
- Android 실기기/Windows 원작 프로세스/전체 원본 SP2 설치본/전체 CI는 이 작업에서 미검증입니다. 작업 경로에는 원본·변환팩을 추가하지 않았습니다.
