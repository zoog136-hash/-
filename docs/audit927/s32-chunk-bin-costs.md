# MAP04 S32 지도 인덱스 준비 비용

- 근거: Library의 Windows 복원 EXE 정적 분석에서 `01CC2220`과 `01CC1F10`은 지도 배치 목록의 소유권을 넘기고 부분 처리한다. `01CBCF50`은 셀 정리 시 공유 참조를 해제하고 배치를 재활용한다. Android 1.10.18a 정적 분석의 `0x5543594 → 0x554389c → 0x5543c44`도 이미지 요청, 작업 스레드 읽기, 결과 발행을 분리한다. 이 근거는 준비와 소비의 경계를 비교하는 데 사용했다. TWILIGHT의 512px 블록 인덱스와 아래 성능 결과는 자체 구현이다.
- 최신 코드의 `_decode_chunk`는 원래 작업 스레드에서 S32 레코드를 투영하고 `_bin_chunk`를 호출한다. 기존 bin 구현은 배치마다 Dictionary에서 Packed 배열을 가져와 추가하고 다시 저장했다. 이제 같은 블록에 이어지는 동안 작성 배열을 재사용하고, 경계에 걸친 레코드는 겹치는 블록에도 원래 순서로 추가한다. 각 레이어가 끝날 때 저장 형식인 PackedInt32Array로 한 번 변환하므로 상주 인덱스 형식과 크기는 동일하다. 준비 중에는 한 레이어의 작성 배열이 추가로 존재한다.
- Godot 4.7.2 Linux headless에서 합성 배치 8,342개(바닥 8,192, 객체 150)를 사용해 입력별 워밍업 뒤 전후 50회씩 측정했다. 중앙값은 사선 좌표 2.610 → 2.153 ms, 64px 간격 2.598 → 2.173 ms, 16px 간격 2.524 → 1.990 ms, 밀집 1px 간격 3.722 → 3.570 ms였다. 각 반복에서 결과 Dictionary와 모든 Packed 배열이 일치했다. 렌더러 130개 검사에는 음수 경계, 네 블록 교차, 레이어 분리와 워커·직접 준비 일치가 포함된다.
- 리소스 연결: `Twm` 릴리스 `pack-63fb1355`의 월드 링크 애드온 ZIP CRC 및 게임의 manifest 고정값 `2de8cebb…ffa90`이 일치한다. 설치 선택이 정의 팩 환경을 구성하며, `World.bind_current523_source_definition_pack`에서 실제 portal provider와 land별 정의 로더로 이어진다. 실제 팩을 제공한 Godot portal provider의 26개 검사 중 25개가 통과했다. Portal 1101과 350의 좌표, 18111의 양쪽 NoTeleport=false 선언, 별칭 거부를 확인했다. 나머지 검사는 기준 main에서도 재현됐다. 기본 `OWN_ALWAYS_OPEN_V1`이 `LandTimeLimit`을 `waived_time_conditions`에 기록하는데 기존 테스트는 hold를 기대한다. 18111에는 별도의 제한 4개가 유지되고 원작 트리거는 미확인이다. 이번 작업은 여행 정책과 검사를 그대로 둔다.
- 523.699 화면의 `map.block_commands` 2,066ms 또는 미계측 잔여 29,010ms 중 이 인덱스가 차지한 시간은 확인되지 않았다. Android 프레임 시간 및 원본 S32 지도 화면은 실기기 미검증이다.
