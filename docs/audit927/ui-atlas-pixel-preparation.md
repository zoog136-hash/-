# UI 아틀라스 프레임의 CPU 픽셀 준비

Android 사진의 523.741 기록에는 한 프레임 4,257ms, 미계측 잔여 4,082ms, 콜백 후 구간 4,051ms가 있다. `ui.texture_new 77ms×200`은 같은 프레임 안의 세부 타이머 합계 77ms와 호출 200회다. `source_pack.gd`는 이 타이머에 텍스처 생성 호출을, `source_asset_pixels.gd`는 픽셀 변환과 생성 호출을 함께 기록한다. 콜백 구간은 벽시계 시간이다. 4,082ms 잔여의 원인은 이 사진으로 분리할 수 없다.

Twm `pack-63fb1355`의 UI 부가 팩 ZIP CRC 검사와 매니페스트 SHA-256을 확인했다. 사진과 같은 `7a2b59859b8c8abdead63e19fa4cd1c602c0324b7e0ca81d3e36e37186122371`이다. 이 매니페스트의 아틀라스 프레임 6,016개 중 4,300개는 잘라낸 영역이 이미 원본 프레임 크기와 같다. 해당 RGBA8 프레임은 기존 경계 검사를 통과하면 소유권이 분리된 잘라낸 이미지를 반환한다. 회전은 원래 순서로 적용하며, 투명 여백이 필요한 프레임에는 기존 캔버스 합성을 사용한다.

완전히 불투명한 RGBA8 이미지는 Godot의 알파 검사로 확인해 스크립트 픽셀 연산을 건너뛴다. 부분 투명 이미지에서도 RGB가 그대로인 불투명 픽셀과 이미 RGB가 0인 투명 픽셀은 다시 쓰지 않는다. 다른 픽셀은 기존 Cocos 식 `(channel * (alpha + 1)) >> 8`을 적용한다. 텍스처 캐시 키, 포맷, 원본 좌표·색·알파와 팩 검증은 유지한다.

Linux Godot 4.7.2에서 페이지를 미리 디코딩하고, 동일한 입력을 번갈아 처리한 7회 중앙값을 비교했다. 두 표본의 모든 결과가 변환 전후 바이트 단위로 일치했다.

| 표본 | 자르기·알파 변환 기존 | 변경 |
| --- | ---: | ---: |
| 실제 팩의 큰 배경 12개 | 1,390.8ms | 137.3ms |
| 실제 HUD·공통 프레임 200개 | 105.8ms | 84.1ms |

배경 표본 중 8개는 알파 처리를 요청하지만 실제 프레임은 불투명하다. HUD·공통 표본 200개에서는 103개가 중간 캔버스 복사를 피했다. 테스트는 프레임들을 별도의 표본으로 묶었다. 파일 I/O, 화면 구성, GPU 업로드, Android 프레임 시간과 메모리 최고점은 측정 범위 밖이다.

합성 RGBA8의 픽셀 1,262,433개를 독립식으로 비교했다. 회전 없는 자르기, 회전, 투명 여백이 있는 프레임을 독립 복사 기준과 비교했고, OpenGL에서는 텍스처 생성·재사용과 PNG 알파 결과를 확인했다.
