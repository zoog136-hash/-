The 523.699 device screenshot records a previous run at 31dfa907. The worst frame was 31,615 ms. Its map renderer section took 2,095 ms, with 2,091 ms in frame building and 2,066 ms across three block command builds. These are nested times. Automatic pickup took 455 ms. This timing alone cannot identify the cause.

At main 553ed34 the S32 worker and atlas worker changes are already present. The block builder still checks which tiles and subimages exist at every placement, even when many placements refer to the same pair. Now it reuses validity per packed reference for one synchronous block build and appends the three command fields without a temporary array. Texture acquisition failures still retry as before, and future block builds validate their own references. Command order, coverage at block boundaries, source pixels, sentinel counts and unresolved placement counts are preserved.

The new detail `map.block_atlas_acquire` records main thread time spent acquiring a texture within `map.block_commands`. A call can include a cache lookup, decode or worker wait, and upload submission. Its elapsed value is not a GPU timer. The existing on-screen fallback can still wait synchronously for an atlas.

The existing renderer suite verifies exact packed commands, the first acquisition failure retry, order, counters and fresh validation after a change. All 128 checks passed under Godot 4.7.2. Running the same suite against baseline code produced 1,537 tile checks and 1,025 subimage checks, versus 3 and 2 respectively with this change. The baseline failed only the new operation-count assertion. The tracked-resource guard passed. The historical resource integrity script is absent on main.
