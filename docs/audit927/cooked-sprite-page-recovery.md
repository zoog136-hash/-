# 변환 액터의 텍스처 페이지 복구와 재사용

검증 대장 OPT05의 동일 텍스처 공유를 변환 액터 `.twca` 재생 경로에서 확인했다. OPT01의 비동기 읽기와 OPT02의 업로드 분산은 별도 검토 항목이다.

원본 Android 1.10.18a 정적 분석에서 `0x5544460`은 캐시 적중 시 기존 텍스처를 반환한다. `0x5543594 → 0x554389c → 0x5543c44`는 요청·이미지 읽기·결과 반영을 분리한다. Windows 쪽 `01C74AB0`은 RawSpriteFile 캐시 적중 시 공유 참조를 반환하고, `01C716E0`은 Graphics가 있으면 재사용한다. 관련 출처는 [원본 함수 대조](native-runtime-keyframe-review.md)와 [Windows 수명 대조](../performance-prepared-bank-20261113.md)에 있다. 아래 포즈 처리와 재시도 간격은 TWILIGHT 구현이다.

`cooked_actor_store.gd`는 한 포즈의 필요 페이지를 먼저 확보하고, 읽을 수 없는 페이지가 있으면 마지막에 성공한 포즈를 유지한다. `original_source_preview.gd`는 포즈를 성공적으로 그린 뒤 상태를 기록한다. 페이지 읽기가 실패하면 같은 번들 페이지의 다음 읽기를 250ms 지연한다. 복구 시 해당 포즈가 계속 선택되어 있어도 레이어 전체가 표시된다. 기존 합성 순서, 이미지 내용, 팩 형식과 검증 계약을 유지한다.

Godot 4.7.2 Linux에서 합성 페이지 두 장을 운영 경로로 읽었다. 수정 전에는 포즈 보존과 같은 포즈 복구 검사가 각각 노드 상태와 OpenGL 픽셀에서 실패했다. 캐시가 한 장일 때 A/B/A 포즈는 페이지를 3회 로드했다. 수정 후 headless 317개, 소프트웨어 OpenGL 336개 통과(합성 픽셀 대조 81개와 GL 비교 7개 포함). A/B/A 포즈는 2회만 로드되며 두 A 레이어가 같은 텍스처를 참조했다. 독립 레이어 직접·프레임 캐시 검사 각 25개, copy-free OpenGL 검사 78개도 통과했다.

Twm의 [`cooked-63fb1355-v2` 릴리스 매니페스트](https://github.com/zoog136-hash/Twm/releases/tag/cooked-63fb1355-v2)에서 변환 팩 ID, 뱅크 매니페스트 SHA-256, 두 ZIP의 선언 SHA-256이 게임 핀과 일치했다. 해당 릴리스는 NPC 8개와 효과 9개를 변환하지 못했다고 기록한다. 사유는 원본 멤버 불일치 14개, SP2 디코더 미지원 레이아웃 2개, 레이어 선언 누락 또는 모호 1개다. 예시는 각각 `effect:spell:16322:0`, `npc:3136`, `effect:spell:26691:0`이다. 변환 매니페스트의 집계이며 실제 게임에서 폴백으로 표시되는지 여부는 항목별 확인이 필요하다.

실제 Twm ZIP 바이트와 실기기 프레임 시간·메모리 변화는 이번에 검증하지 않았다. 기존 변환 팩에 빠진 리소스는 원본 확인과 재변환이 필요하다.
