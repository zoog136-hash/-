# Single selected combination

The Main menu opens the combination list, grouped ownership requirements, confirmation and release. A private latest523 Content ZIP is installed from this screen. The importer verifies indexed table lengths and SHA-256 values and imports all 62 combinations, 272 requirement rows and 91 typed bonuses. Original tables and the private derived cache are excluded from this change.

Permanent transform and doll ownership is read from the current card ledger. Equipment must be physically in inventory at or above the minimum enchantment. Rental appearance, warehouse possession and a coincident numeric catalog ID cannot satisfy a requirement. A native item identity is preferred. The adjustable compatibility policy accepts a legacy instance only when its full name resolves uniquely in the current item catalog; it preserves engraving and validates any pinned catalog identity.

TWILIGHT policies cover rules not recovered from the original data: candidates with the same requirement index are alternatives, separate slots require separate equipment, selection consumes no materials and defaults to zero adena, and losing eligibility suspends the effect while retaining the selection. The fee and MP recovery interval (30 seconds) are adjustable in `scripts/combinations/policy.gd`. No source cost is claimed. Only one selected combination contributes effects. Actual server restrictions are retained and require a supplied valid source server context.

Selection writes the full normal save atomically before changing live state. Confirmation rechecks ownership and fee; stale, duplicate and failed writes preserve selection and resources. A malformed combination save blocks writes rather than replacing progress. Private source data can be reinstalled without granting ownership.

Flat elemental damage remains scoped to its original element. Status hit and resistance remain scoped. The named DTH bonus is exposed as DTH, without inventing a damage conversion. Charge-step reduction is available only to explicitly tagged charge-step durations; the current ordinary skill catalog does not expose the original charge-step contract. This is an integration limit, not a claim that ordinary cooldowns reproduce the original charge system.

Run tests with Godot and an isolated XDG profile. `tests/combination_source_catalog_test.gd` imports the private source archive. `tests/combination_full_contract_test.gd` accepts `--catalog=<private-normalized-json>` and checks the complete requirement/effect catalog. `tests/combination_main_test.gd` takes the same catalog argument and requires the existing verified `TWILIGHT_SOURCE_MAP_PACK`, exercising normal Main confirmation, cancellation, save failure, restart and corrupt-save protection. Tests do not use the user's save. Desktop testing does not establish Android touch behavior or original visual equivalence.

The current item catalog has a unique exact-name bridge for 116 of the 145 required native item identities. The remaining 29 identities are not silently fabricated or supplied. Every equipment requirement slot has at least one existing candidate, and already-native instances can satisfy their exact identity. Availability through existing drops or shops is distinct from a test granting ownership.
