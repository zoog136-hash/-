# 누적523 전체 ItemClass 연결

기존 드랍의 2,379개 ID에서 전체 ItemClass 카탈로그로 확장한다. 아이템이 카탈로그에 있다는 이유로 드랍·상점 상품·제작법을 새로 만들지 않는다. 드랍 확률·사용자 지정 비용, 기존 물리 장비 UID와 강화·속성·축복 상태를 보존한다. 다른 기능 PR과 main은 병합하지 않았다.

## 실제 코드 경로

전체 자료는 schema3 루트와136개 gzip 상세 조각이다. 루트는 필요한 표시·공급·기본 옵션을 보유하고, 전체 원문과 연결 행은 조각 두 개를 캐시하면서 읽는다. 조각 전부를 검증한 뒤 루트를 마지막에 설치한다. 해시가 다른 기존 파일은 덮어쓰지 않는다. 상세 조각 누락·손상 시 해당 버전의 활성화를 거부한다.

`patch523_item_catalog.gd`가 정상 전체를 등록한다. 기존1970개의 키·물리 장비 식별자는 그대로 유지하면서 원본 수치로 갱신한다. 장비는2,964개 정의이며 지배석·유물·낚싯대 부위도 장비창3쪽에 연결한다. 낚싯대 장착은 낚시 콘텐츠의 구현을 뜻하지 않는다. 원본 픽셀은 새로 생성하지 않았고, 정확히 검토된 기존 카탈로그 아트 참조와 미연결 폴백을 구분한다.

`world.source_item_record(item_class_id, bless_raw=1)`와 `world.source_item_definition(item_class_id)`는 정확한 ID만 받는다. 공급 담당자는 다음 계약으로 기존 거래 저장에 합친다.

```gdscript
var staged = world.stage_source_item_grants([
    {"item_class_id": exact_source_id, "amount": quantity,
     "bless_raw": original_bless, "enchant": original_enchant}
], {"kind": supplier_kind, "source_row_id": exact_supplier_row_id})
# staged.ok가 참일 때에만 staged.overrides를 거래의 전체 저장에 합친다.
# 재화 차감과 공급자 구매/제작 횟수도 같은 한 번의 저장에 포함한다.
```

stage는 live 상태를 바꾸지 않는다. 저장 성공 후에만 inventory/item_instances/gold와 공급자 상태를 게시한다. 장비마다 별도 UID·원본 ID·축복·강화·공급 출처를 남긴다. 일반 물건을 지갑 통화로 이름만 보고 변환하지 않는다. 정확한 기존 통화 연결 외에는 별도 아이템 키를 보존한다. Test·ID0·소수 수량·비장비 강화·미등록 카탈로그는 지급하지 않는다. 최대 묶음 크기는 원본 수량 변경이 아니라 물리 장비 생성의 구현 한도이며 초과 거래를 실패 처리한다.

null·문자열·불리언을 아이템 ID나 초기 강화0으로 변환하지 않는다. 지급 후 재화/수량이 JSON으로 정확히 왕복 가능한 정수 범위를 넘으면 기존 보유를 유지하고 거래를 거부한다. 장비 UID는 숫자로 변환하지 않고 정렬하므로 기존 숫자 ID와 UUID, 긴 숫자 형태 ID를 바꾸지 않는다.

PR239의 `--binding-catalog`에는 `export_patch523_item_bindings.py`로 실제 정상30,398개 런타임 바인딩을 내보낼 수 있다. 그 출력도 비공개 데이터다. PR247 상점·PR239 제작/가공의 상품·가격·재료·조건 판단을 여기서 복제하지 않는다. PR245 주문 엔진은 원본 주문 ID·전체 행 SHA·학습 제한 계약이 필요하며, PR249 추가/변경 카드도 정확한 원본 행이 일치할 때만 받는다. 이 문서의 계약 제공은 해당 PR들을 합친 거래·학습 실행 검증과 다르다.

## 사용·전투·장비 옵션

원본 선택/확정/확률/혼합 상자, 지정 카드, 순수 HP/MP 회복, 지원되는 지속 버프와 스킬서의 기존 실행 경로를 전체 정의에 적용한다. 서버·영토·선행 조건·주문 공급자·복합 효과가 남아 있으면 소비하지 않고 안내한다. 원본 보상 수량·원본 확률·축복/퀘스트 차이를 보존한다. 상자의 +0 초기 강화·선택 횟수 등 원본에 없는 기존 자체 규칙은 UI에서 구분하며 끌 수 있다.

UIShowFilter·NoAnnounce의 정확한 의미는 원본 정의·기존 보고서와 공개 검색에서 확인되지 않았다. 무조건0/1의 두 플래그만 표시·공지 메타정보로 해석하는 별도 추정 설정을 기본 켜짐으로 제공한다. 원본 사용 spec과 차단 사유를 수정하지 않고, 실행 직전에 설정을 확인한다. 그 두 이유와 이미 정확히 해소된 날짜 이유만 남은 경우에 한해 기존 실행 경로를 사용할 수 있다. 조건부·소지 옵션·다른 미지원 이유·원본 Test 보상·불완전 확률 합은 이 규칙으로 넘기지 않는다. 설정을 끄면 해당 물건은 소비하지 않는다. 전체 후보352개 중319개가 현재 사용 가능했고33개는 원본 기간·조건으로 보존됐다. 실제 선택상자56종의387개 엔티티 수령과 확정211/가중42/혼합10종 사용을 검사했다.

한국어 기간 연결은 사용·장착·재진입 및 실행 중 기한 검사에 반영한다. 만료 아이템은 소유를 지우지 않는다. 시각대는 원본 명시가 없어 기본 UTC+9의 설정값이다. 새 날짜 연결 덕분에 과거 만료 항목이 현재 사용할 수 있는 항목으로 오인되지 않는다. 테스트에서 기간을 해제해 성공 수를 부풀리지 않는다.

원본 강화표의 지원 단위는 정확한 단계의 행만 적용하며 하위 단계를 누적하지 않는다. 축복별 행·조건을 보존한다. 기존 사용자가 지정한 enhancement_options는 유지하고, 원본에 없는 강화 확률·비용·미지원 옵션은 기존 게임 규칙 및 미지원 표시를 유지한다. 원본 표 이름만 보고 전체 성공률이 있다고 주장하지 않는다. 원본 무기의 직업 제한과 WeaponType 사거리가 있으면 예전 대체 직업/사거리 목록보다 우선한다.

Arrow/Bullet/Sting 정상43개 중 일반 대미지와 단순 투사체 ID만 있는16개는 원본 WeaponType.AmmoItemCategoryID로 장착·발사·스택 소비·저장에 연결한다. 특수 주문 투사체27개를 일반 화살로 바꾸지 않는다. 원본 상한과 작은/큰 대상 값을 사용하고, 추첨은 원본 공식이 없어 `uniform`(기본1~상한 균등 추정), `maximum`, `disabled` 설정으로 구분한다. 원본 ShotWithoutArrow도 무조건 조건일 때 반영한다. 기존 일반 화살/총알과 사용자 수량은 보존한다. 원본 탄약의 픽셀을 제공한 것으로 표시하지 않는다.

장착 아이템537개에 있는 무조건 Value 단위의 RegenHP/MP·AbsoluteRegenHP/MP·AttackDrainHP/MP와 무게 회복 플래그는 원본 수치로 읽는다. 원본에 없는 회복 간격은 별도 기본30초 설정, 일반 명중 흡수 발동률은 기존 매 명중 동작을 따른 기본100% 추정 설정이다. 기존 카드·장비의 회복 간격과 사용자 규칙은 변경하지 않는다. 일반 회복은 현재 게임 무게가 수용량50% 미만이거나 해당 원본 플래그가 있을 때만 허용하고 절대 회복은 구분한다. HP 흡수는 남은 HP, MP 흡수는 실제 몬스터 MP와 플레이어의 부족한 MP를 넘지 않는다. 주문·특수 공격·조건부 옵션으로 이 자체 규칙을 확대하지 않는다. 설정·상세·로그에 자체 규칙임을 표시한다.

공개 근거는 [공식 무기 가이드](https://lineagem.plaync.com/guidebook/view?title=%EB%AC%B4%EA%B8%B0+%EC%95%84%EC%9D%B4%ED%85%9C), [공식 요정 가이드](https://rc-wstatic.plaync.co.kr/lineagem/guidebook/game_class_fairy.html), [무게 회복 관련 공식 마법 가이드](https://lineagem.plaync.com/guidebook/view?title=%EC%9A%94%EC%A0%95+%EB%A7%88%EB%B2%95)이다. 이 자료는 화살 사용·추가 대미지·흡수 옵션·무게 회복 의미를 뒷받침하며 모든 확률·간격·전투 공식을 제공하지 않는다. 원본 확인값을 먼저 사용하며 PC 리니지나 다른 버전의 수치를 최신M의 확정값으로 대체하지 않는다.

## 세이브와 설치

이전 세이브를 최초 변환하기 전에 전체 바이트 SHA가 동일한 불변 백업을 만든다. 기존 inventory/warehouse/장착 UID와 알 수 없는 외부 필드를 유지하고, 교체 전 record도 한 번 보관한다. 이름만으로 오래된 게임 아이템을 강제 변환하지 않는다. schema3 저장에 전체 팩이 없으면 원본 저장 덮어쓰기를 막는다.

실행 중 옛 팩에서 전체 팩으로 설치하는 경우도 첫 저장 직전에 원본 전체 바이트를 백업한다. 과거 material 슬롯으로 저장된 지배석의 축복·저주 스택 키도 별도 호환 장비로 남기며, 일반 이름의 새 장비와 합치지 않는다. 실제 이전 팩→설치 UI→수량·축복·물리 장비3개→장착→저장·재진입25개 검사와 불변 백업의 SHA를 확인했다.

최신 적용 ZIP은23,637,249bytes, SHA256 `fb2a4de030b7d302fd7d8d2c541ca3cc8d1fbe246cf67ef574d812d3ccb6fc8d`, 루트BIN은3,050,707bytes, SHA256 `38ee3ec74d12adaa9847c507f6fb093c41a4f7a8c5c1cefcd08c3a9629920d27`이다. 사용자가 이 파일과 기존 폴더를 명시 승인한 뒤 비공유 Drive 적용폴더에 저장했다. 같은 파일을 추가 업로드하지 않고 공식 재다운로드의 크기·ZIP SHA256·CRC·루트BIN 및136개 상세 조각의 SHA/gzip을 대조했다. 이전 phase4 적용팩과 원본 백업은 별개로 유지한다. 최신 팩의 보관·새 소비폴더·실제 실행 결과와 비공개 위치는 인계 영수증에 기록한다.

Drive에서 자동 다운로드하지 않는다. 사용자가 ZIP을 받은 뒤 설정의 설치 버튼으로 설치하거나 `--patch523-drop-root=<monster_drops.bin과 items 폴더가 있는 경로>`를 지정한다. 기본 설치 위치는 `user://lineagem_patch523_drops/<루트 SHA>/`다. 원본 백업과 적용팩, 이전 적용팩을 별개로 보존하며 공유권한을 바꾸지 않는다. 원문 표·팩·바인딩 출력·검사 캡처는 공개 Git에 넣지 않는다.

## 검사와 남은 범위
