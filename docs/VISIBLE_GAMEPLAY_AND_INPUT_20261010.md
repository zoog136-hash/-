# TWILIGHT: 화면/조작 실제 변경 내역

## 입력 수정

- 상점 목록: 손가락 이벤트가 Godot ItemList GUI 콜백까지 내려오지 않더라도 `_input` 단계에서 손가락 시작·이동·종료를 추적해 탭을 선택으로 반영. 원래 구매 권한·가격 검증은 게임 월드가 수행하며 탭만으로 구매하지 않음.
- 장비 인벤토리: 슬롯을 **오른쪽으로 72px 이상** 끌면 `item_activate_requested` 신호를 기존 버튼과 똑같이 발생. 상점과 혼동되지 않도록 장비 슬롯(`slot`)이 있는 아이템에 한함. 아래/위 세로 드래그는 스크롤로 유지.
- 변신·마법인형·성물 도감: 아이콘을 **오른쪽으로 96px 이상** 끌어 적용. PC에서 적용 버튼으로 끌어 놓는 것도 지원. 보유/적용 가능 검사는 기존 버튼의 `disabled` 상태를 따름. 좁은 화면에서는 완료 후 상세 탭으로 전환.

## 눈에 보이는 월드 수정

- 맵: 기존 지도 좌표와 충돌을 유지한 채, 제공된 프로젝트 속 `assets/maps/aden/props.png` 계열 아트를 이용해 나무·바위 주변 지형 잔디/자갈 디테일을 일정한 좌표에 렌더. 청크가 다시 로드되어도 배치가 변하지 않음.
- 캐릭터: 보통 달리기를 run 상태로 인지하도록 모션 속도 구분 수정, 질주 시 바운스·기울기를 강화. 기존 `SpriteFrames` 동기화 코드는 유지.
- 공격: 공격 스타일별 원호 궤적·마법진·활 화살 시각효과, 달릴 때 발밑 먼지를 표시. **타격 시점·공격력·물리 이동을 변경하지 않음.**

## 분명한 미완료 범위

- A3 지도 `.s32`/맵 캐시에는 실사 지형 PNG가 바로 들어있지 않음. 이번 수정으로 원작 지도 타일을 완전히 복제하지 않았으며 기존 시스템에서 시각 밀도를 높임.
- A2/A3 몬스터 초상화는 보통 1컷이며 원작 캐릭터 8방향 동작 프레임을 복원하지 않음.
- 이미지 팩은 공개 GitHub에 포함되지 않음. 원저작물 권리 검증 전 재배포하지 않으며 로컬에서 별도 적용 필요.
- PC/Android 실제 조작, PC 캡처의 눈대중 차이는 자동 스모크와 별개로 점검해야 함. 외형 충실도를 실제 원작 수준이라고 주장하지 않음.

## 병합/검증 요구

`VISIBLE_GAMEPLAY_SMOKE_OK`와 Godot 프로젝트 import/boot, 월드 렌더, UI 회귀 테스트를 확인. 특히 실기기에서 상점 다른 상품 선택, 변신/마법인형 오른쪽 드래그, 보유 무기 장착, 인벤토리 세로 스크롤, AUTO 사냥 후 바닥 드랍을 차례로 실행해 검증.

## 실제 PC 캡처 비교로 검증한 문제와 2차 개선

초기 PR 캡처와 `main`의 동일 시점 픽셀 차이를 비교한 결과 일부 던전의 차이가 1% 미만이었다. 이는 기존의 소품 근처 디테일만으로는 사용자가 체감할 시각 개선이 충분하지 않다는 증거다. 그래서 `FieldRenderer.refresh_visible`의 로딩 조건을 수정하여 기존에 소품이 0개인 빈 던전 청크까지 디테일을 배치하고, `_scatter_chunk_groundcover`에서 기존 prop atlas를 산재형으로 추가했다. 월드 좌표·맵 경계·충돌을 읽기만 하며 저장·AI·스폰을 변경하지 않는다. 이 코드는 프레임별 무작위 배치가 아니라 청크 좌표와 맵 ID로 결정적 배치를 만든다.

위 추가 변경 후의 Godot 렌더 및 회귀검사는 **별도 커밋 상태에 대한 성공 기록**으로 검증해야 한다. 기존 캡처와 같은 그림으로 테스트해서는 안 된다.
