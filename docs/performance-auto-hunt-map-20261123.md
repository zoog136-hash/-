# 자동사냥 경로 탐색과 원본 지도 블록 대기 처리

기준은 main `00feac743da64ded8816608bcabec3f747ce31a7`이다. 사용자 Android 523.812 기록의 최악 프레임은 8,771ms였다. 상위 구간은 자동사냥 8,130ms, 미계측 잔여 305ms, 던전 301ms였다. 하위 `auto.search` 3,623ms 및 `auto.path` 195ms는 자동사냥에 포함된다.

- 이전 자동 획득은 거리순 후보마다 같은 프레임에서 완전한 지도 경로를 조회했고, 추적 전환이나 실패 후 재획득에서 다시 조회할 수 있었다. 새 자동 획득은 후보 순서를 스냅샷으로 잡고 틱마다 경로를 하나만 조회한다. 성공한 경로는 해당 틱의 추적에 넘긴다. 대상의 현재 생명 ID, 부모, 생존, 원본 자동 선택 제한과 감지를 재확인한다. 수동 선택과 필드의 개별 검색 한도는 기존대로다. `auto.search_route`는 한 후보의 경로 계산 시간을 분리한다.
- 원본 경로 탐색기는 비용상 채택할 수 없는 간선을 걸러낸 뒤 지형을 읽는다. 같은 S32 조각이 연속 조회될 때는 검증된 최근 조각을 재사용한다. 최근 조각은 기존 48개 캐시의 마지막 항목이며, 맵을 닫으면 같이 비운다.
- 지도 표시에서는 정상적으로 새 블록을 만들 때와 타일 준비를 기다렸던 블록에 같은 작업 큐를 사용한다. 준비된 작업만 가져오고 명령 순서, 해상도, 아틀라스 실패 시 대체 처리 그대로 유지한다. `map.block_commands`는 동기 처리 시간을, `map.block_commands_worker`는 작업 스레드에서 받은 블록 수를 보여 준다.

원본 분석 기록 `docs/performance-20261112.md`는 Android 1.10.18a `0x5544460`의 디코딩 전 캐시 적중과 `0x5543594 → 0x554389c → 0x5543c44`의 요청·백그라운드 읽기·완료 분리를 다룬다. 보유 Windows 정적 분석 보고서의 `CONSUMERS_KO.md`는 `0x01CC2220`, `0x01CC1F10`의 월드 배치 분할 큐 및 `0x01CBCF50`의 배치 반환을 추적한다. 이 기록은 작업 분할과 자산 재사용의 참고 근거다. 이번 코드와 아래 측정은 TWILIGHT 구현을 대상으로 한다.

최신 main은 이미 화면에 그린 블록을 캐시하고 타일 배치를 워커에서 준비한다(#764, #765). 이전 표시 최적화 초안 #458은 최신 코드와 충돌한다. 그 초안의 관측 장부 변경을 적용하지 않고, 최신 구현에서 대기 블록만 동기로 돌아가던 분기를 수정했다.

## 검증

Godot 4.7.2 Linux에서 목록과 경로 일치 여부를 검사했다. 후보 13개 중 마지막만 도달 가능한 합성 사례에서 동기 기준과 새 코드 모두 13개를 확인했다. 자동 획득의 틱당 최대 조회량은 13회에서 1회로 바뀌었다. 새 코드가 선택한 대상과 경로는 기준과 같았다.

| 원본 S32 경로 시험 | 요청당 묶음 | main 중앙값 | 변경 중앙값 |
| --- | ---: | ---: | ---: |
| 아덴 Land 4, 기란 주변 | 36경로 | 822.5ms | 308.9ms |
| 말하는 섬 Land 0 | 36경로 | 156.0ms | 81.0ms |
| Land 4 재진입 | 36경로 | 871.6ms | 330.1ms |

각 묶음을 5회 실행했다. 출력 경로 좌표의 SHA-256이 각 지점의 기준과 일치했고, 원본 조각 읽기 횟수도 같았다. 위 수치는 전체 프레임 시간이 아닌 순차 경로 요청 묶음의 CPU 경과 시간이다.

지도 렌더러는 같은 원본 지도와 타일 팩으로 Linux Compatibility/llvmpipe에서 검사했다. 아덴 고정, 아덴 내 이동, Land 0 전환, 아덴 복귀의 최종 프레임 픽셀 SHA-256이 모두 기준과 일치했다. 아덴 첫 표시와 복귀의 동기 명령 준비는 각각 15회에서 3회로 줄었고, 나머지 12개는 작업 스레드에서 받았다. Land 0은 동기 12회에서 0회로 줄었다. 아덴 내 시험 이동은 이미 만들어 둔 블록을 사용했다. 아덴 첫 표시에서 계측한 렌더러 콜백 최댓값은 기준 279ms, 변경 284ms였다. 따라서 최악의 지도 프레임이 줄었다는 결론은 낼 수 없다.

회귀 검사에는 자동 대상 선택·생명 교체·수동 우선권 11개, 원본 경로 규칙 15개, 지도 표시·실패 보호 136개, 대기 지도 블록과 작업 스레드 32개, Main 저장·재로드 33개가 포함됐다. 변경분의 Android 실기기 실행과 성능 측정은 아직 없다. 단일 경로 계산과 준비 시간이 초과된 지도 아틀라스의 동기 처리는 다음 기기 기록에서 별도로 확인할 구간이다.
