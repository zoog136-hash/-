  `ROSTER.for_spawn` and `POLICY.admit(record, target_map_id, explicit_catalog)`.
  The exact full M Land, view/pack/link/territory, source archive and final-record

  Existing source-field `source_spawn_active` and `sample_source_spawn` use the

  a read-only snapshot. Boss cooldown evaluation/state creation affects only

  Active candidate territories sharing the existing boss-director key retain
  a shared-slot specification, not duplicate live-boss reservations; actual
  boss restore/selection remains pending with that same owner.
- Active reservation count must fit the existing source population budget.
  Every sampled point must be finite, supported by original source-member
  provenance, within both the original territory and its source rectangle,
  walkable, clear under the existing 4px host source-foot policy, non-safe under
  the existing field API, and free of duplicate cells/spacing conflicts.
  A rejected sample holds; no new outer reroll or invented coordinate is used.
- Reservations retain raw `IsOccupyLandTile` separately. Landing evaluation
  applies Main's existing 155px teleport margin to target reservations, never
  to the current map's actors. It is host policy, not a decoded native bit.
  Boss restore positions remain pending until an actual prepared boss actor
  confirms its owner-controlled restore; provisional boss points cannot claim
  complete target occupancy.

## Ownership and stale state

The new object owns only a detached, disabled, hidden Node2D **specification
container** plus its own records/slots/reservations. It has zero live actors;
no dummy NPC nodes are manufactured. The travel caller owns/closes the private
target field. `discard` frees only a still-detached owned container and clears
owned data; a changed parent/tree ownership holds rather than deleting it.

`revalidate` compares the original source/model identity, source field/player,
current actor IDs/lives/positions, roots/population, combat generation, wallet,
RNG and boss snapshot, target field/Land/AssetPath/pins, selected cell and exact
request. The caller also re-reads its real portal conditions, provider generation,
actor-condition identity and existing fee quote. No result authorizes movement.

The actual caller obtains `actor_batch_request()` while the stage is alive.
Its **map-owned** shape contains explicit encounter `records`, complete
`source_archive_identity`, `expected_npc_model_sha256`, exact target Land/AssetPath,
target instance, source/definition pins, and `activation_ready:false`. This does
not guess or invoke the data owner's pending method/result ABI.

The caller records a volatile preparation summary, discards the specifications,
then retains `TARGET_SOURCE_POPULATION_TRANSACTION_REQUIRED` and closes its
target field. Failed or absent producers/entries, zero admitted encounter specs,
unknown source positions and missing batch/actor owners cannot become an empty
population travel success. Prepared counts are not executed-game metrics.
