# Reward and death rules are consumed separately from entry — unexecuted

Held original conditions declare LandAttributeType612 NoExperience, Unit20,
and three exact global Value1/zero-parameter rows. The existing hunt award owner
now consumes that flag from the pinned admitted-Land context snapshot: earned
kill experience becomes zero before the existing experience/card-hunt-growth
calls. Existing gold/drop/quest/restoration/consumable owners are unchanged. This
is the hunt-experience connection, not a claim of complete every-channel reward
or Hell-system implementation.

Primary public corroboration of the hunt behavior is NC's LineageM guidebook,
"성향치 시스템":
https://lineagem.plaync.com/guidebook/view?title=%EC%84%B1%ED%96%A5%EC%B9%98+%EC%8B%9C%EC%8A%A4%ED%85%9C
The guide describes no experience/item acquisition from Hell monsters. The held
NoExperience rows belong to the Hell/entrance declarations. No item-drop policy,
Hell entry permission or missing source relationship was synthesized from this
public description. Other entry holds remain active.

The entry adapter previously held every positive reward/death flag as an unknown
admission condition. It now separates only exact supported bool declarations
when the actual runtime consumer is present: global612 with the hunt consumer;
3/4/494/878/1122 with the already-pinned death-rule source ready. The existing
source-cell death consumer and loss/recovery rules handle those death flags.
NoBookmark retains its separate previously implemented consumer.

Unknown types, units, values, parameters, unimplemented territorial612 forms,
and unavailable consumers retain their holds. Other level/time/server/party/
teleport/competition restrictions are unchanged. Processing a non-entry flag
is not itself permission to enter or travel. Consumer readiness participates
in existing actor-condition identity and stale-ticket rejection.

The admitted context retains each handled raw row/type. Hunt award reads that
snapshot, not another map or a fresh unpinned read. A missing/mismatched snapshot
does not synthesize a NoExperience value or replace the existing award owner.
No source file, actor identity, amount formula, entry route or original image is
created or rewritten.

UNVERIFIED: no tests, compilation, game, rendering or CI. Existing sources,
phone extraction, frozen v30/62ZIP/index, source bank and all configurations/
saves are unchanged. Historical representative map QA is not execution proof
for this change. Original 3-row scope is not a whole-map completion percentage.
