# TWILIGHT 공통 모션·보스 연출 개발 결과

활성 변신 **413종**, 일반 몬스터 **258종**, 보스 **60종**에 공통 표현 프로필을 연결했다. 기존 공격 시계·마커·전투 판정을 사용하면서 준비→타격→복귀, 이동/정지의 루트 움직임, 방향별 피격, 체형별 사망과 기존 보스 특수기 연출을 개선했다. 전용 SpriteFrames가 설치되면 생성 atlas보다 우선한다.

**공통 모션 적용과 개별 프레임 아트 완성은 다르다.** 이번에 새로 그린 개별 8방향/관절 원화는 0종이다. 기존 변신별 생성 atlas와 원화를 재사용했다. 원작 연속 전투 영상 확인과 Android 실기기 측정은 완료하지 못했다. 전체 회귀 검사도 기존 실패가 남아 있으므로 PR은 초안으로 유지한다.

## B. 기본 캐릭터

기존에는 4직업의 5×5 시트(`warrior`, `mage`, `archer`, `assassin`), 4방향 보행, 공통 공격 행, 절차적 호흡·반동·사망 및 공격 마커가 있었다. 이동은 8방향으로 판정하지만 기본 시트가 제공하는 시각 방향은 4방향이다. 원거리·마법도 동일 공격 시계를 쓰는 기존 투사체 시스템이었다.

이번 구현은 다음을 바꿨다.

- 보행 주기를 실제 사용 트랙의 프레임 수로 계산하고, 이동 속도에 맞춰 진행한다. 정지할 때 루트 흔들림을 짧게 감쇠한다. 전용/생성 관절 프레임이 있으면 공통 루트 움직임을 줄여 이중 흔들림을 억제한다.
- 공격 준비는 타격 반대 방향으로 힘을 모으고, 기존 마커에서 전진한 뒤 복귀한다. 한손검·양손검·단검·창/체인소드·도끼·둔기·활·총·마법의 시각 반동/궤적을 기존 무기 분류에 연결했다. 무기별로 새 관절 원화를 만든 것은 아니다.
- 받는 공격 방향에 따른 짧은 반동과 크리티컬 강조를 적용한다. 연속 피격 변위는 누적하지 않는다. 크리티컬 자세 정지는 시계·쿨타임·마커를 멈추지 않는다.
- 전용 사망 프레임이 있으면 공통 회전을 중복 적용하지 않는다. 기본 캐릭터의 기존 시체 VFX 및 즉시 부활 흐름은 유지한다.

실제 사용 리소스는 기존 `assets/sprites/classes/*.png`, `assets/catalog_motion/transform/*.webp`, 기존 타격/투사체 텍스처 및 자체 절차적 드로잉이다. 캐릭터 능력치, 공격속도 계산, 명중/피해/크리티컬 확률, 장비 옵션, 스킬 쿨타임은 변경하지 않았다.

남은 아트 작업은 기본 캐릭터의 전용 대기·피격·사망·각 무기별 시트와 실제 대각선 원화다. 프레임 간 보간은 루트 표현에 한정되므로 부족한 관절 프레임의 불연속이나 발 미끄러짐을 완전히 제거했다고 보장하지 않는다.

## C. 전체 변신

| 구분 | 개수 | 의미 |
|---|---:|---|
| 현재 활성 변신 | 413 | 최신 시작 main의 실제 도감 목록 |
| ID별 기존 생성 atlas 재사용 | 413 | 서로 다른 변신 원화로 만든 기존 리깅 시트 |
| 공통 프로필 적용 | 413 | 위 atlas와 함께 사용하므로 상호 배타적인 집계가 아님 |
| 4개 원본 시점 기반 | 78 | 실제 8방향 전용 원화라는 뜻이 아님 |
| 단일 시점/정지 원화 기반 대체 | 335 | 기존 생성 리깅 프레임 + 공통 모션 |
| 현재 런타임에서 원시 정지 한 장만 반복하는 fallback | 0 | 설치된 생성 atlas가 모두 로딩된 이번 검증 기준 |
| 새 개별 원화/전용 8방향 프레임 제작 | 0 | 전용 프레임 우선 로딩 구조와 구분 |
| 자동 검사 오류 | 0 | [개체별 CSV](TRANSFORMS.csv), [상세 검사 JSON](evidence/animation-presentation-coverage.json) |

명시적인 변신 ID와 실제 atlas 첫 포즈 검토를 근거로 인간형 121, 기사형 80, 마법사형 64, 대형 45, 궁수형 32, 특수형 30, 비행형 12, 야수형 11, 영체 6, 골렘형 6, 언데드형 6으로 보수적으로 분류했다. 보이지 않는 관절이나 원작 설정을 추정하지 않았다. 분류 데이터에 이미지 SHA-256과 근거를 기록했다.

적용 순서는 개체 설정→검토된 체형 프로필→전용 SpriteFrames→기존 ID별 생성 atlas→기존 시트/정지 원화의 안전한 표현이다. 새 ID는 보수적인 공통 프로필을 받고, 개체 `animation_profile`로 체형·전용 트랙을 지정할 수 있다. 잘못된 선택 리소스가 기존 외형까지 제거하지 않게 fallback을 유지했다.

Idle/Walk/Run/Attack/Hit/Death는 기존 트랙을 사용한다. RangedAttack/Cast/AttackRecovery는 전용 트랙이 있으면 사용하고, 없으면 기존 Attack 트랙과 공통 준비·발사·복귀 표현을 사용한다. 변신마다 전용 활/마법 원화가 있다는 뜻은 아니다.

모든 413종에 대해 8방향 선택, 리소스 로딩, 대기·이동·빠른 이동·피격·사망, 세 공격 지속시간×다섯 공격 스타일, 마커 직전 변신 해제/재적용, 공격당 한 번의 해제, 복귀, 원래 캐릭터 복귀를 검사했다. 위치·AUTO·콜라이더·진행 중 공격 시퀀스 보존을 확인했다.

## D. 일반 몬스터

`MonsterCatalog.expand`의 활성 318종 중 `LootDrop.is_boss_record` 기준 일반 258종과 보스 60종을 구분했다. 이름/등급 문자열만으로 보스를 세지 않았다.

| 구분 | 일반 몬스터 | 보스 포함 전체 |
|---|---:|---:|
| 모션 적용 | 258 | 318 |
| 전용 상태 SpriteFrames 설치 | 0 | 0 |
| 기존 원화 + 공통 루트/셰이더 모션 | 258 | 318 |

실제 리소스는 132개 레코드가 기존 원화 경로 78개(파일 해시 기준 75개)를 공유하고, 186개 레코드가 기존 atlas 외형을 사용한다. fallback 외형 연결에는 89개 고유 셀이 있다. **레코드 수와 고유 이미지 수를 별도로 집계**했으며 효과 레이어를 새 몬스터로 세지 않았다. [MONSTERS.csv](MONSTERS.csv)와 [inventory.json](inventory.json)에 전체 목록, 실제 경로, 공유 원화, 공격 방식·주기 및 남은 아트가 있다.

현재 설치 원화는 fallback 분류와 모양이 다를 수 있어, 실제 이미지 경로별 검토 결과를 우선한다. 늑대인간/라이칸스로프의 두 발 형태, 나이트메어·다이어울프·악어의 네 발 형태 등을 바로잡았다. 일반 몬스터 원화에 없는 임의의 무기나 문양은 새로 덧붙이지 않는다. 기존 atlas용 셰이더는 체형에 맞춰 제한된 다리·날개/몸체 변형을 하고, 원화/전용 프레임을 이중 변형하지 않는다.

대기·보행/추적·공격 준비/타격/복귀·방향 피격·체형별 기울기/소멸을 공통 적용했다. 화면 밖에서는 기존처럼 시계·판정은 진행하고 자세 적용은 제한한다. 사망 신호·보상/드랍은 기존 1회 규칙을 유지한다.

개별 관절·방향·전투 원화는 318종 모두 별도의 아트 완성과 구분된다. 특히 현재 소스가 화염/광택 위주로 몸체를 확인하기 어려운 사라만다·라바 골렘·이프리트·혼 켈베로스·불타는 전사/궁수·파이어 에그 계열과, 다족/날개/거대 체형은 전용 모션 제작 검토 대상으로 CSV에 남겼다. 없는 관절을 정지 원화에서 정확히 복원했다고 주장하지 않는다.

## E. 보스

**60종 모두** ID별 기본 공격·피격·사망 프로필을 적용했다. 기존 특수기가 있는 **26종**은 7종류의 기존 패턴과 같은 해제 마커로 연출을 연결했다. 특수기가 없는 34종에는 새 피해 패턴을 만들지 않았다. [보스별 전체 표](BOSSES.md)에 크기, 기본 공격 주기, 특수기 준비/쿨타임, 이펙트를 기록했다.

| 기존 패턴 | 보스 수 | 새로 연결한 시각 표현 |
|---|---:|---|
| nova | 7 | 실제 원형 범위 경계, 진행 표시, 속성 충격파 |
| cone | 6 | 실제 각도·반경의 부채꼴 경계와 파동 |
| summon | 4 | 작은 의식 문양·방사광. 피해 원으로 오인할 큰 원은 표시하지 않음 |
| beam | 3 | 실제 폭·길이의 직선 경계와 중심 광선 |
| charge | 3 | 실제 돌진 범위 경계, 발동 시 방향·자세를 고정한 잔상 |
| volley | 2 | 조준 표시, 기존 3발의 해제 간격에 맞춘 발사광 |
| drain | 1 | 실제 원형 경계와 안쪽 흡수선 |

경고 외곽과 실제 피해 판정은 `boss_geometry.gd`를 공유한다. 기존 부채꼴 반각 0.55rad, 직선 반폭 55px, 길이 `radius×2` 등은 그대로 옮겼다. 패턴 조건·AI·공격 주기·특수기 쿨타임·피해·드랍·리스폰 변경은 없다. 도형 추출은 판정 코드 구조 변경이므로 독립적인 8방향 경계/바깥점 회귀 테스트를 추가했다.

보스 설정은 `attack_animation`, `cast_animation`, `special_animation`, `animation_speed`, `special_motion`, `effect_color`, `effect_scale`, `death_animation`을 실제로 소비한다. 공격/시전 마커는 기존 `attack_hit_ratio`·`attack_hit_frame`·`marker_for`와 특수기의 기존 0.85 해제 지점을 사용한다. 복귀는 기존 공격 지속시간 내부에서 끝난다. `animation_speed`는 단계 내부 자세 완급만 바꾸고 실제 해제/공격 횟수는 바꾸지 않는다.

경고는 취소·타깃 사망·본체 사망 시 정리된다. 해제 효과는 시각 수명만 가지며 피해를 생성하지 않는다. 전용 프레임이 있는 보스에서도 경고 노드가 유지된다. 동시 상세 효과는 프레임당 8개로 제한하고 나머지는 경계 표현을 남긴다. 화면 전체 섬광·추가 카메라 흔들림은 넣지 않았다.

원작 영상으로 개별 확인한 보스 패턴은 **0종**이다. 위 패턴은 시작 main의 TWILIGHT 자체 적응 구현을 보존·보강한 것이다. 전용 보스 관절 원화, 원작 패턴 비교 및 특수기가 없는 34종의 신규 패턴은 이번 결과에 포함되지 않는다.

## F. 검증·성능·발견 사항

### 실행과 자동 검사

- 실제 Godot 4.7.2 import 및 Main.tscn 실행, OpenGL/llvmpipe 렌더를 수행했다.
- 최종 집중 검사 **12개 통과**. 전체 변신/몬스터 검사는 **76,231개 assertion**, 보스 검사는 **693개 assertion**, 실패 0이다. `evidence/*_test.txt`에 실제 출력이 있다.
- 공격 타이밍, 기존 전투 결과 동등성, volley, 변신 복귀, PR #92 타격/VFX, 원화 트랙 우선, 몬스터 모션을 검사했다. 원래 전투 계산 파일·세이브 구조·맵/충돌·인벤토리·장비 DB는 변경하지 않았다.
- 전체 회귀의 변경 전·후 결과와 기존 실패는 [REGRESSION.md](REGRESSION.md)에 별도로 기록한다. 집중 검사 통과를 전체 회귀 통과로 표현하지 않는다.
- Android preset의 실제 PCK 내보내기와 별도 빈 프로젝트의 pack 로딩 검사를 통과했다. 새 검증 폴더는 `exclude_filter`와 `.gdignore`로 제외해 이미지/영상/CSV 번역 import가 게임 용량을 늘리지 않게 했다. 런타임 JSON·Main 장면·변신 텍스처가 pack에 남는 것을 확인했다. 이는 APK 설치/실기기 테스트가 아니다. [검사 출력](evidence/export-filter.txt), [사용한 probe](evidence/export-filter-probe.gd).
- 무결성 검사: 기존 723 atlas / 41,442 프레임 / 233,420,026 bytes, 변신 413·인형 166·성물 144. 자산/manifest 변경 없음.

눈으로 검토한 대표 연속 프레임에서 과도한 루트 흔들림 감소, 방향 전환 후 자세 유지, 준비→타격→복귀와 피격/사망 전환을 확인했다. 보스 경고·발동 경계, 마커 시점, 왼쪽 돌진 잔상과 기본/특수 효과 중복을 검토했다. 192마리 밀집 장면에서는 기존 이름표·HP 바의 겹침이 몸체를 가리는 문제도 확인했다. 이를 가독성 개선 완료로 표시하지 않는다. 원화가 없는 몬스터의 관절 운동과 모든 개체의 발 미끄러짐까지 자연스럽다고 보장하지 않는다. PR에는 이 한계를 숨기는 완료 표시가 없다.

### 성능

[PERFORMANCE.md](PERFORMANCE.md)에 같은 서버·Godot·OpenGL/llvmpipe 환경의 시작 main과 변경 후 32/96/192마리 일반 사냥·보스 전투 비교를 기록한다. Android 실기기 결과나 보장 FPS가 아니다. 기존 SpriteFrames/텍스처 캐시, VFX 풀 160개·상세 타격 효과 한도, 투사체 수명/화면 밖 처리를 보존했다. 공통 glow 텍스처는 renderer마다 새로 만들지 않고 공유한다. 반복되는 삼각함수·구간 보간을 줄이고, 기본 시트는 중복 트랙 검색을 피하며 고정 체형 uniform은 생성 시에만 설정한다. 일반 원화 개체의 빈 드로잉과 보스 전용 시계 호출도 생략한다. 보스 도형은 공격 준비 때 캐시하며 이펙트용 노드를 추가 생성하지 않는다.

### 발견 및 수정

1. 생성 manifest가 설치된 전용 SpriteFrames보다 우선하던 경로를 수정했다.
2. 원화가 있을 때 보스 경고 노드가 사라질 수 있던 분기를 수정했다.
3. 전용/생성 관절 프레임과 절차적 몸체 움직임이 겹치던 진폭을 줄였다.
4. 특수기 위에 일반 무기 효과가 중복 그려지던 부분을 억제했다.
5. 사망 후 셰이더 보행이 남지 않게 자세를 정리했다.
6. 돌진 잔상의 좌우 방향과 자세를 발동 때 고정했다.
7. 원화와 fallback 체형이 다른 몬스터는 실제 원화를 우선 분류했다.
8. 초기 갤러리의 RGB/RGBA 합성 포맷 불일치 및 진단용 OpenGround의 누락 메서드를 고친 뒤 다시 렌더/검사했다. 실패했던 중간 결과를 최종 통과 증거로 사용하지 않았다.

## 재현

```bash
python3 tools/check_resource_integrity.py --root .
godot --headless --path . --editor --quit
godot --headless --path . --script res://tests/animation_presentation_test.gd
godot --headless --path . --script res://tests/boss_presentation_test.gd
godot --rendering-driver opengl3 --path . --script res://tests/capture_presentation_gallery.gd
godot --rendering-driver opengl3 --path . --script res://tests/capture_presentation_sequences.gd
godot --rendering-driver opengl3 --path . --script res://tests/benchmark_presentation_battles.gd
python3 tools/test_project.py --godot /absolute/path/to/godot --logs /tmp/twilight-tests
```

각 실행에는 별도의 `XDG_DATA_HOME`/Windows 사용자 데이터 폴더를 사용한다. 렌더 검사에는 실제 OpenGL 디스플레이 또는 Xvfb가 필요하다. CI 워크플로는 같은 엔진을 고정해 집중 검사와 화면/성능 자료를 artifact로 보존한다. 참고 자료의 접근 결과, 원작 확인 한계 및 외부 리소스 처리 원칙은 [REFERENCES.md](REFERENCES.md)에 있다.
