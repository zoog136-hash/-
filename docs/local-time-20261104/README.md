# 기기 로컬 시간 기준 초기화

기준 main: `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`. 구현 커밋:
`582861981a816782711e8da7da234572e5f3ee05`.

기존 일일 퀘스트의 **KST 오전 5시** 판정을 **사용자 기기 로컬 오전 5시**로
바꿨다. 기존 화면에도 같은 기준을 표시한다. 별도 퀘스트나 화면을 추가하지
않으며, 새 원본 이벤트나 시간표를 활성화하지 않는다.

실행 경로는 매번 `Time.get_datetime_dict_from_system(false)`의 로컬 달력을
읽는다. 달력 필드를 일자 번호로 인코딩하므로 자정·월말·연말·윤일과
서머타임의 반복/생략 시간을 처리할 때 고정된 UTC 시차나 하루의 경과 초 수를
로컬 일정으로 오인하지 않는다. 오전 5시 정각부터 새 일일 구간이다.

초기화는 화면 조회·수령·저장뿐 아니라 첫 처치·습득 기록 **전**에도 적용한다.
화면을 닫은 채 초기화를 넘겼을 때 새 날의 첫 진행도가 지워지는 문제를 막는다.
월별 드래곤의 보호 구매 제한은 기존에도 로컬 달력을 사용했으며, 이번에
`false` 인자를 명시했다.

## 저장 이전과 시간 변경

- 신규 퀘스트 상태는 `schema_version: 2`, `time_basis: device_local`,
  `reset_hour: 5`를 저장한다. 퀘스트 상태 내부의 버전이며 전체 게임 저장의
  장비·지도·보스 형식을 바꾸지 않는다.
- 구 schema 1에는 KST 일자만 있고 수령 시각·사용자 시간대가 없다. 정확한
  과거 로컬 일자를 추측하지 않고 **첫 이전일의 수령 기록과 진행도를 보존**한다.
  다음 로컬 오전 5시부터 정상 초기화한다. 오래된 일일 완료 기록도 이 첫날에는
  즉시 해제하지 않는 보수적인 이전이다. 기존의 미래 일자 보호는 상대 일수로
  유지한다.
- 관측한 가장 큰 로컬 일자를 저장·복원한다. 기기 시각이나 시간대를 이전
  날짜로 돌린 뒤 재접속해도 이미 관측한 날짜의 보상을 다시 주지 않는다.
  시계를 먼 미래로 옮겼다가 되돌린 경우에는 그 날짜를 넘을 때까지 기다린다.
  서버 없는 게임에서 모든 시각 조작을 차단한다는 의미는 아니다.
- 메인·업적 완료 기록은 일일 초기화 대상이 아니다.

보스 재출현, 바닥 아이템 만료, 드래곤의 보호 유효기간은 기존부터 **기기의
Unix 시각으로 저장한 절대 만료 시각**이다. 여기에 로컬 시차를 더하면 저장된
남은 시간이 바뀌므로 해당 값과 형식은 유지한다. UTC 컬렉션 등록 감사 시각도
절대 시각 기록이다.

누적523의 시즌패스·출현·주간 개방 조건 원문은 이 main에서 활성 일정 판정으로
연결돼 있지 않다. 원본 요일 숫자·서비스 지역·활성 조건을 임의 해석하거나
과거 이벤트를 현재 이벤트로 바꾸지 않았다. 향후 실제 일정 연결 작업에서는
기기 로컬 달력을 사용해야 한다. 이번 결과가 이 미구현 연결의 완료를 뜻하지
않는다.

## 검증과 재현

Godot `4.7.2.stable.official.ed1daf0bf`를 사용한다. 모든 실행 검사는 별도
임시 사용자 디렉터리를 사용하며 사용자 세이브를 읽거나 쓰지 않는다.

- `tests/quest_local_time_test.gd`: 오전 5시 전후·자정·일요일/월요일·연말·윤일,
  서머타임 달력 경계, 날짜 역행과 재접속, 날짜 변경선 왕복, schema 1 이전,
  미래 일자 보호, 처치·습득 진행도와 실제 퀘스트 UI 문구를 검사한다.
- 8개 별도 프로세스의 `TZ`를 UTC, 서울, 로스앤젤레스, 뉴욕, 키리티마티,
  호놀룰루, 카트만두, 로드하우로 설정했다. Python `zoneinfo`의 현재 로컬
  일자·월과 실제 Godot OS 조회를 대조했다. 각각 70개 검사, 총 560개가
  통과했다. 실행 중 시간대 변경은 제어된 로컬 달력 시퀀스로 별도 검사했다.
- 기존 `instant_quest_smoke_test.gd`가 통과했다. 명시적 검사 시각으로 저장까지
  고정해 실제 실행 날짜가 결과를 바꾸지 않게 했다.
- 실제 Main/current source-map·저장 보존 32개, 동일 payload·외부 변경 보호,
  deferred save, 시간 회귀 68개로 구성된 핵심 검사 4개가 모두 통과했다.
  staging 도구의 Python 검사 7개와 리소스 723시트 SHA 검사도 통과했다.
- 기존 Ainhasad Main 회귀는 26개가 통과했다. 이 역사적 검사가 추가로 쓰는
  몬스터 초상화 1개가 핵심 stage에서 제외되어 첫 추가 실행에는 리소스 오류가
  있었다. 같은 커밋의 실제 추적 파일 1,027바이트를 stage에 복원·해시 기록하고
  해당 검사만 재실행해 오류 없이 통과했다. 폴백이나 검사 기준 완화는 없다.
- 새 시간 회귀를 `tools/ci_core.py`의 전환기 핵심 검사에 등록했다.
  핵심 실행·저장 검사 결과와 입력 SHA는 `validation.json` 및 `evidence/`를
  확인한다. 전체 수동 시각·게임플레이 CI를 반복 실행한 결과가 아니다.

핵심 검사 재현:

```bash
python3 tools/ci_core_map_pack.py --output /tmp/twilight-current-map
TWILIGHT_SOURCE_MAP_PACK=/tmp/twilight-current-map python3 tools/ci_core.py \
  --stage /tmp/twilight-local-time-core \
  --godot /path/to/Godot_v4.7.2-stable_linux.x86_64 \
  --logs /tmp/twilight-local-time-logs
```

새 stage 경로와 격리 사용자 프로필이 필요하다. 기존 사용자 데이터와 원본
리소스는 수정하지 않는다. Android/Windows 실기기의 시간대 설정 변경·전체
원본 이벤트 동등성·전체 아트 복원은 이번 검증 범위에 포함하지 않는다.

Godot의 로컬 달력·Unix 시각 구분은 [공식 Time 문서](https://docs.godotengine.org/en/stable/classes/class_time.html)를 참고한다.
