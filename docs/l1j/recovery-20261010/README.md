## 지도와 서비스 데이터

아덴 4번 맵과 오만 101..110번의 원본 캐시 헤더·좌표·크기·CRC를 확인하고 x-major 데이터를 y-major로 변환했습니다. 아덴은 2,048×1,536, 탑은 층별 192×192입니다. 모든 원본 기점을 보존합니다. 일본판은 두 맵의 헤더가 다르고 나머지도 타일 값이 달라 자동 병합하지 않습니다.

`TwilightL1JSourceNavigation`은 A3 `L1V1Map.checkMoveTile`의 방향별 연결을 사용하는 제한된 읽기 전용 탐색기입니다. 원본 11개 지도 로딩·좌표 왕복·실제 연결 및 경로 11건, 경계·대각선 등 합성 검사 15건이 통과했습니다. 문·동적 객체 상태와 본편 지형 정렬은 포함하지 않습니다. 기존 본편의 충돌과 지역 이동을 그대로 유지합니다. 원본 지형 텍스처는 미확보입니다. 캡처의 지형은 기존 TWILIGHT 지형입니다.

읽기 전용 추출: 아이템 6,230, NPC 5,117, 드랍 13,788, 상점 6,697, 몬스터 스폰 2,969, NPC 스폰 2,132, NPC 동작 참조 1,602, 텔레포트 참조 202. 제작 정보 2,137, 제작 NPC 94, 사냥 퀘스트 111, 초보 퀘스트 71, 마법인형 정보 102도 복구했습니다. 제작 정보의 `output_name_id`는 item_id와 다른 네임스페이스입니다. 제작 재료·대화 본문·보상 의미가 전부 검증된 데이터가 아니며 본편 가격·제작·퀘스트에는 적용하지 않았습니다. 플레이어/캐릭터 상태 테이블과 스킬 테이블은 추출 대상에서 제외합니다.

## 재현과 설치

원본/변환 리소스는 Git 코드와 분리된 검증 ZIP으로 제공합니다. 제3자 이미지 없이도 프로젝트는 기존 아트로 정상 실행됩니다. 최종 ZIP들을 프로젝트 루트에 다음 도구로 설치할 수 있습니다. 서로 다른 기존 파일을 덮어쓰지 않으며 전 항목 사전 검사 후 새 파일만 추가합니다.

```bash
python tools/l1j/install_verified_pack.py --root /path/to/twilight /path/to/VERIFIED_PART1.zip /path/to/VERIFIED_PART2.zip /path/to/VERIFIED_PART3.zip /path/to/VERIFIED_PART4.zip /path/to/VERIFIED_DATA_VISUALS.zip
python tools/test_project.py --godot /path/to/godot --logs test-results --timeout 450
godot --headless --path /path/to/twilight --script res://tests/l1j_full_pack_playback.gd
```

기존 합성 테스트 fixture와 실제 원본 맵 4 파일이 이미 같은 경로에 있다면 설치 도구가 충돌로 중단합니다. 실제 원본 팩 재생과 원본 지도 검사는 깨끗한 사본에서 실행해야 하며 fixture를 원본으로 표시하면 안 됩니다. 공식 회귀용 fixture는 `tools/l1j_ci_make_fixture.py`, 새 본편 fixture는 `tools/l1j/make_live_fixture.py`로 생성합니다. 원본 이미지가 설치된 경로에서 합성 fixture 생성은 거부합니다.

원본 재생성 도구는 `audit_sources.py`, `recover_spx.py`, `extract_a3.py`, `normalize_items.py`, `verify_item_candidates.py`, `recover_live_visuals.py`, `convert_maps.py`입니다. 각 `--help`에 필요한 원본/출력 경로를 명시합니다. Pillow가 필요한 변환 도구는 `pip install Pillow` 후 실행합니다. SQL을 실행하거나 기존 게임 DB를 갱신하지 않습니다.

## 남은 구현

1. native SPR 전체 범위와 SPX의 실제 몬스터/방향/동작/속도 연결을 확인하고 선택적으로 SpriteFrames를 본편에 적용.
2. 나머지 6,225개 아이템의 실제 정체성·슬롯·단위·가격·클래스·등급을 검증하고 기존 저장 호환 어댑터로 확장.
3. 원본 지형과 본편 원점을 정렬한 별도 필드에서 통행·문·자동사냥 이동을 검증한 뒤 아덴·탑 층별 NPC/스폰/입구 적용.
4. 제작 재료·대화·퀘스트 보상·가격 의미를 확인하고 기존 서비스에 연결.
5. 실제 리소스가 포함된 PC 패키지·Android APK 및 실기기 플레이 검사.

전체 통합률은 표시하지 않습니다. 위의 각 단계에서 변환/데이터 복구, 본편 적용, 실제 플레이, 패키지 빌드를 구분합니다. 커밋 HEAD와 CI의 최신 상태는 해당 PR 페이지에서 확인하며 main 병합은 사용자 승인 후 별도 작업입니다.
