# 남은 문양 강화정보 복구·일일 정책 마무리

기존 PR242 안에서 남아 있던 보관/복구와 일일 초기화 경로를 연결했다. 새 게임 기능이나 별도 실행 환경으로 범위를 넓히지 않는다. 현재 보유한 실제 문양 강화 기록만 사용하며, 없는 과거 기록을 자동 생성하지 않는다.

## 근거와 자체 설정

누적523 심층 자료 `REPORT_KO.md`7절, `relevant_ui_source.json`, `currency_backing_and_legacy_items.json`과 기존 조사 문서를 먼저 확인했다. 원문 `SYMBOL_POPUP_HELP LABEL10/11`은30단계의 초기화/저장/복구 금지와 실제 강화 기록 조건을 명시한다. UIText56445는 일일 횟수 초과,48572는 복구 시 포인트 부족 가능성을 말한다. 원본 두루마리 소비와 일반 강화 포인트 환급은 그대로다.

[공식2021년 추가 공지](https://lineagem.plaync.com/board/update/view?articleId=60107abf31e27200012bc72b)와 [현재 문양 가이드](https://lineagem.plaync.com/guidebook/view?title=%EB%AC%B8%EC%96%91+%EC%8B%9C%EC%8A%A4%ED%85%9C), 공개 검색도 대조했다. 과거 기능 공지와 다른 상품/이벤트의05시 제한은 현재 문양 복구 가격·일일 한도 숫자의 증거로 사용하지 않는다. 원본 SymbolPayment의1200/Currency4를 복구 가격으로 전용하지 않는다. Currency1492의 Item174272는 역사적 삭제 정보가 있고176932는 테스트 아이템이므로 현재 재료로 받지 않는다.

확인하지 못한 규칙은 사용자 승인에 따라 `data/growth/symbol_history_policy.json`의 **TWILIGHT 자체 정책**으로 분리했다. UI에도 자체 정책과 비용을 표시한다.

| 설정 | 기본값 | 의미 |
| --- | ---: | --- |
| history_enabled | true | 보관/복구 허용. 꺼도 기존 기록은 보존 |
| save_fee_points | 0 | 보관료. 실제 현재 기록을 문양별1슬롯에 저장 |

보관 무료는 별도 아이템을 생성하지 않는 단일 기록 슬롯의 로컬 선택이다. 복구100포인트는 기본형 첫 강화20포인트의5배를 참고한 로컬 수수료다. 문양별1회는7종 각각의 사용을 허용하는 자체 일일 한도다. 원본 가격/숫자로 주장하지 않는다. 원본 확률·강화비·환급·최대30단계·20회·정확한 실물 초기화 두루마리 ID는 바꾸지 않았다.

## 중복 복구·재화 복제 방지

보관은 현재 `growth.emblems[id]`의 실제 단계/횟수/원금/확정 상태만 복사한다. 지갑·아이템·다른 문양·절대 보상 전체를 되감지 않는다.30단계는 보관/복구를 거부한다. 이전 슬롯을 덮어쓸 때도 현재 실제 기록만 사용한다.

보관마다 증가하는 식별번호와 사용 여부를 남긴다. 같은 진행을 다시 저장해 새 복구권을 만들 수 없고, 재접속의 JSON 정수/실수 변환도 동일한 기록으로 비교한다. 복구는 보관된 기록을 한 번만 사용하고 완료 여부를 같은 저장 거래에 기록한다. 날짜가 바뀌어도 사용한 복구권은 부활하지 않는다. 서로 다른 새 실제 강화 기록으로만 슬롯을 갱신할 수 있다.

현재 강화 원금C, 저장 원금S, 지갑W, 수수료F일 때 복구 후 지갑은 `W+C-S-F`, 선택 문양 원금은S다. 즉 **지갑+투입 원금은 수수료F만큼만 감소**한다. 초기화로 이미C를 환급받아 현재 원금이0이면S+F를 다시 지출해야 한다. 부족하면 거부한다. 원금 정산/복구료 이력을 일반 강화 환급·충전·열쇠/절대 비용과 구분한다. 재료/다른 진행을 보관값으로 복사하거나 두 번 지급하지 않는다.

성장 revision, 지갑, 보관권 사용, 일일 횟수를 기존 원자적 `_save_game`에 함께 넘긴다. 쓰기 실패 때 라이브 기록·재료·지갑·기존 파일 SHA가 유지된다. 확인 요청에는 일자도 포함하므로 확인 창을 연 뒤 일자가 바뀌면 다시 견적을 요구한다. 취소와 중복 터치는 비용을 소비하지 않는다.

## 기존 날짜 API와 세이브 호환

기존 `TwilightQuestService.korean_daily_key(unix_time)` 정적 함수만 재사용한다. 기존 게임의 한국05시 기준이며 퀘스트 기능을 새로 인스턴스화하지 않고 전체 게임 시계/시간대 설정을 바꾸지 않는다.

문양의 마지막으로 저장한 일자와 횟수를 선택 필드 `symbol_daily`에 보존한다. 다음 일자에 성공한 거래만 횟수를 새로 시작한다. 이전 일자로 돌아가면 보관/복구/초기화를 거부하고 저장한 일자를 낮추지 않는다. 재접속에도 미래 일자/소비 횟수를 현재 시간으로 덮어쓰지 않는다. 테스트의 시간 입력은 해당 서비스의 격리 Callable뿐이며 실제 시계는 변경하지 않았다.

schema1 기존 세이브에 `symbol_history`/`symbol_daily`가 없으면 기록 없음으로 처리한다. 존재하지 않는 과거 진척이나 소급 일일 소비를 만들지 않는다. 그 외 기존 인벤토리/실물ID/재화/보스/컬렉션·문양 진행은 유지한다. 보관 기록과 일일 이력은 형식·숫자·문양ID·중복 복구권·단계/횟수까지 검증한다.

## 실행 검증과 전달 구분

Godot4.7.2에서 새 규칙 단위39개, 실제 Main의 X11 네이티브 터치39개를 통과했다. UI는 실제 강화→보관/취소→추가 강화→복구/취소→쓰기 실패→복구→재접속→다음 일자 초기화→쓰기 실패→초기화→역행/재접속→다른 실제 기록 보관→초기화→복구 원금 재지출→재접속을 검사한다. 복구할 과거 기록을 fixture로 만들어 넣지 않는다. 초기 자금·원본 ID 두루마리와 검증 시간 입력만 명시적인 격리 fixture다.

기존 문양753개·절대 효과104개, Python staging7개와 리소스723시트/41,442프레임 SHA도 통과했다. 로그/입력 SHA는 `validation-history.json`과 `evidence/history/`에 보존한다. 캡처2개는 `/workspace/symbol-validation/history/screenshots/`에 LOCAL_ONLY다. 초기 editor 실행의 설정 저장 경로 오류는 별도 로컬 로그로 남기고 성공 검사로 집계하지 않는다. 최종 런타임 검사는 파싱/리소스/실행 오류 없이 통과했다.

이 결과는 현재 원작 서버 상품/과금·제한 정책의 복원이 아니라 원문 제약을 보존한 명시적 단독플레이 정책이다. 코드 게시·최신4파일 데이터팩의 Drive 보관·다운로드/설치/실제 로드는 `RESOURCE_STORAGE.md/json`에서 별도로 기록한다. 이전3파일 데이터팩은 이 후속 정책을 포함하지 않는다. 다른 PR/main 병합, 수동 원격 CI, 제외 기능·M 엔진/APK/XAPK 작업은 수행하지 않는다.
