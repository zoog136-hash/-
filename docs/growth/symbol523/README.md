# 누적 523 문양 연결

현재 절대 옵션은 [기억 장소 후속 구현·검증](TRAVEL_FOLLOWUP.md)을 기준으로 한다. 에바 III 선택 이동을 연결해 실제 개방13개/효과 연결20개 묶음으로 확장했다. 최초 검증은 `d9fceac5c`, 절대 옵션 1차 후속은 `792def740`의 기록이며 현재 결과는 `validation-travel.json`에 구분한다.

기준 main은 `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`이다. 기존 성장 런타임과 문양 메뉴를 확장한 별도 feature 브랜치이며 main이나 다른 PR을 병합하지 않는다. 원본 전체 게임 복원 완료를 뜻하지 않는다.

## 연결한 범위

`symbol_source523.json`은 제공된 누적 523 ZIP에서 생성한다. 7종의 강화 비용 140행, 일반 옵션 485행, 절대 옵션 46행/35등급 묶음, 확률 범위 87행과 원문 상수·지불·아이템·날짜·한국어 도움말을 보존한다. 선택한 각 표의 원본 바이트 SHA-256과 ZIP SHA/크기를 함께 기록한다. 원본 이미지나 사운드를 새로 넣지 않는다.

일반 옵션은 원문의 단계별 증가분을 누적한다. 기존 전투·물약·축복·장비 컬렉션 능력치 단위에 명확히 대응하는 463행을 적용한다. 마프르의 첫 단계 HP, 아인하사드의 일반 옵션도 실제 능력치에 반영한다. 파아그리오의 SP를 별도의 마법 대미지·마법 명중으로 복사하던 기존 웹자료 근사는 제거한다. 원문 수치·단위·적용 조건은 변환된 수치와 별도로 남는다.

그랑카인의 조건부 대미지 감소, 실렌의 발동, KarmaDeath, 감소 무시 등 나머지 22행은 실행하지 않고 UI에서 보류로 표시한다. PvP·조건부 옵션을 PvE 수치로 바꾸거나 완전한 원작 전투 수식을 만들지 않는다.

## 거래와 세이브

- 1회/5회 강화와 30단계/20회 제한을 유지한다. 5회는 수동 변경 확률을 무시하며, 완성 시 남은 시도 비용을 차감하지 않는다. 원문의 말미 `SpecialRouteProbability=0`을 존중한다.
- 기본 확률은 기존 게임의 확인된 기본 표를 유지한다. 변경 확률은 원문 Min/Max와 0.1% 간격을 사용한다. 양끝을 포함한 균등 후보 선택과 기존 특수 경로의 이벤트 순서는 **TWILIGHT의 명시적 실행 정책**이다. 원본 서버의 RNG·분모·이벤트 순서를 검증했다고 주장하지 않는다. 후보 수를 모든 단계에 21개로 고정하지 않는다.
- 포인트 충전, 일반 강화 지출, 확률 변경 지출, 상점 지출, 절대 옵션 지출, 일반 강화 환급을 서로 다른 이력으로 저장한다. 환급은 해당 문양의 기존 `spent`만 사용하며 열쇠 구매·확률 변경·절대 옵션 지출을 돌려주지 않는다.
- 30단계 문양은 초기화를 거부한다. 초기화에는 원본 Currency712의 현재 바인딩 중 기간 없는 Item231772의 실제 ID가 보존된 아이템 한 개를 소비한다. 이름이 같은 31개 두루마리를 일괄 수용하지 않는다. 기간형 364424/346431의 날짜 연결도 보존하고 사용은 보류한다.
- 충전 정의 103개를 구분한다. 테스트·삭제 시각·추가 사용 조건이 없는 10개 정의만 실제 충전 재료로 등록한다. 이름뿐인 기존 스택을 원본 ID로 자동 이관하지 않는다. 실제 바닥 습득과 기존 명시적 테스트 도감 지급에서 새 실물 ID를 보존한다. 새로운 드롭 확률·수량·상점 가격이나 자동 지급은 추가하지 않는다.
- 기존 schema1 진행·재료·환급 기록을 보존한다. 새 재화 이력과 절대 등급 목록은 선택 필드다. stale revision·중복 실물 소비·저장 실패를 거부하며 인벤토리/실물 ID/성장 상태를 함께 저장한다.

## 실제 UI

기존 메뉴의 문양 진입, 7개 탭, 충전 재료 선택, 비용 확인, 강화 결과, 단계 점등, 확률 변경, 초기화, 포인트 열쇠 상점에 연결한다. 절대 옵션은 포인트 확률형과 열쇠 확정형을 나누고 원본 비용·성공률을 보여준다. 개방한 절대 옵션은 현재 적용 수치에도 합쳐 표시한다.

현재 개방 가능한 절대 옵션은 **사이하 I~V, 에바 I~V, 마프르 I, 그랑카인 I, 아인하사드 I**이다. 공식 가이드에서 순차 규칙을 확인해 앞 등급을 요구하며, 미연결 효과가 있는 등급은 비용을 소비하지 않는다. 추가 연결된 상위 보상은 이미 해당 등급을 보유한 상태에서 적용한다. 데이터와 화면에 모든 등급을 표시하는 것과 전투 실행 완료를 구분한다.

화면 검사는 실제 Main/HUD의 네이티브 터치→확인→결과 경로를 사용한다. 검증용 충전 재료는 기존 debug 도감 지급을 명시적으로 사용하고, 30단계 절대 옵션 검사는 격리 세이브의 유효한 단계 fixture로 시작한다. 일반 플레이에서 원본 재료 획득 확률이나 모든 성장 과정을 검증한 결과가 아니다. UI 검사 중에는 배경 전투·초기 생성 처리를 정지한다. 화면 자체는 실제 게임 코드이며 별도 모형 UI가 아니다.

실제 OpenGL 캡처는 `evidence/`에 보존한다. 문양 화면의 기존 자체 제작 도형·배경·버튼을 보여주며 원작 문양 아트의 시각 승인이나 원작 애니메이션 재현 증거가 아니다.

## 미확정 경계

원문의 ServerLimitSet1294와 상점512의 방향/서버 문맥을 추정하지 않는다. 현재 서버 없는 게임의 기존 문양·열쇠 상점 가용성을 유지한 **로컬 호환 정책**이며 원본 서버에서 모두 구매/강화 가능하다는 뜻이 아니다. 상점의 다른 두 신탁서 상품은 정의만 보존하고 새 구매·소비 규칙을 만들지 않는다.

초기화 일일 횟수·리셋 시각, 원작의 강화 정보 저장/복구 상품·거래 규칙, 미연결 전투 효과는 남는다. 기존 게임의 초기화 정책에 임의의 1회/05시 제한을 추가하지 않는다. 일반 세이브 저장/재로딩과 원작의 별도 강화 정보 저장/복구 기능은 다르다.

변신/인형/성물 각성 비용, 사용자 지정 드롭 확률·수량, 맵 및 다른 기능 PR은 변경하지 않는다. 수호성의 미확인 그래프·선택 규칙도 이 작업에서 활성화하지 않는다.

## 검증과 재현

Godot 4.7.2 및 실제 Git 자원으로 준비한 일회성 Linux 프로젝트에서 검사한다. 플랫폼 전용 stage의 ETC2/ASTC import를 끄고, 로컬 가져오기만 4개 작업 스레드로 실행했다. production `project.godot`과 이미지 바이트는 변경하지 않았다. 최초 핵심 Main/current source-map/save와 성장 검사는 `validation.json`에, 절대 옵션 1차 후속은 `validation-absolute.json`, 현재 기억 장소 후속은 `validation-travel.json`에 구분해 기록한다.

첫 UI 검사에서 stage가 누락한 기존 몬스터 초상화를 발견해 실제 Git 초상화128개/718,556바이트를 추가했다. staging 도구도 이 실제 경로를 보존한다. 이미지 대체나 오류 무시는 하지 않았다. JSON의 정수→float 디코딩 차이는 모든 키/값을 보존한 정수 정규화 후 비교한다. 첫 OpenGL 실행의 오디오 장치 오류는 기록하고 UI 최종 검사에는 명시적으로 Dummy 오디오를 사용한다. 실제 오디오·Android·Windows 성능 승인 결과는 아니다.

`python3 tools/check_resource_integrity.py --root .`는 723시트/41,442프레임 SHA 검사를 통과한다. 역사적 `--source-dir` 검사는 `/workspace/sources/a1.zip` 부재로 실패했다. 이번 제공된 문양·523 ZIP 두 개의 SHA·크기·전체 ZIP CRC와 선택 원문 행 비교는 별도로 통과한다. 원본 팩을 새로 전달하거나 원본 장부를 완료로 바꾸지 않는다.
