# 절대 옵션 후속 연결

이 기록이 현재 구현 기준이다. 최초 `d9fceac5c`에서는 사이하 I만 실행 가능했고, 이후 공식 설명과 523 원문 조인을 추가해 **효과 연결19/35개 묶음, 새로 순차 개방 가능10/35개 묶음**으로 확장했다. 미연결16개를 성공으로 집계하지 않는다.

## 확인한 근거

제공된 `TWILIGHT_523_symbol_guardian_crosslinks_20261104.zip`을 재검토했다. 문양30단계·두 재화·초기화 경계는 그대로 유지한다. 이 ZIP의 도움말만으로 등급 순서를 확정할 수 없다는 기존 결론도 옳다.

추가로 [NC 공식 문양 가이드](https://lineagem.plaync.com/guidebook/view?title=%EB%AC%B8%EC%96%91+%EC%8B%9C%EC%8A%A4%ED%85%9C)의 공개 API 본문을 정상 HTTP200으로 읽었다. 순차 활성화 설명이 확인되어 I부터 선행 등급을 검사한다. [2026-03-18 공식 업데이트](https://lounge.plaync.com/feed/62455?country=KR&locale=ko-KR)의 V등급과 단계별 열쇠 비용도 523 정의와 대조했다. 원문 API SHA와 짧은 근거, 조인한 원문 행은 `absolute-source-evidence.json`에 기록한다. 전체 공식 문서를 복제하지 않는다.

마프르 I은 `HPIntervalBonus.Value12 → IntervalBonusCategory12 → IntervalBonus42 → Bonus558492`로 이어진다. 범위0~30과 `DamageReductionPercent.Value30000`이며, 공식 가이드의 HP 비율 조건과 일치한다. 회복/재생으로 해석하지 않는다. `BonusApplicationType2`의 대상6은 Stun, 8은 Fear다. 두 숫자를 스탯 수치나 주문ID로 사용하지 않는다.

에바 I은 명시적인 자기 회복 마법 경로 두 곳에 +10%를 적용한다. 물약, 재생, 흡수나 출처가 불명확한 패시브 회복에 이를 복사하지 않는다. II와 IV/V는 각각 기존 물약 쿨타임/회복량/회복률 처리에 연결한다.

마프르 I의 3%는 피격 직전 HP 비율 조건에서만 적용한다. HP/최대HP 비율을 정수 교차 곱으로 비교하여 30.1%를 30%로 내리지 않는다. 그랑카인 I의5는 이미 스턴인 상태에서만, 아인하사드 III의5는 치명타에서만 적용한다. 기존 성장 피해 처리 경계에서 평면 감소 후 기존 백분율 처리를 사용한다. 이 로컬 처리 순서가 원본 서버 전투 수식이라는 주장은 하지 않는다.

아인하사드 I의 생명3은 기존 스킬 `lfe` 합산과 기존 `lfe_scale`을 사용한다. 실렌 III는 기존 1.5배 치명타 뒤의 세 공격별 평면 추가량에 연결한다. 파아그리오 III의 흡수3은 기존의 대상 잔여 HP 제한·추가 피해와 회복을 같은 양으로 처리하는 경로를 사용한다. 원본에 없는 추가 확률이나 새로운 전투 공식을 넣지 않는다.

스턴 내성/적중과 공포 내성은 원문 대상 enum으로 분리하여 실제 기존 상태 판정으로 전달한다. 보유 중인 모든 절대 등급은 합산 후 현재 적용 UI에 한 번 표시한다. 사이하 I~V는 기존 합산 모델에서 절대 보너스55%와 일반 보너스20%가 된다. 이를 원본 서버의 모든 합산·상한 정책까지 입증한 값으로 확대하지 않는다.

## 저장·UI와 검증 범위

새 개방은 앞선 등급을 모두 요구한다. 미연결 보상을 건너뛰거나 과금하지 않는다. 반면 이미 보유한 원문에 존재하는 등급을 효과 미구현이라는 이유로 삭제하거나 저장 로드를 거부하지 않는다. 전체35개 보유 상태의 저장/복원과 선행 등급이 빠진 잘못된 상태의 거부를 검증했다. 보유한 미연결 등급은 UI에 보류로 표시한다.

실제 Main의 제어된 전투·스킬·저장 검사75개, 기존 문양 거래753개, 실제 OpenGL/네이티브 터치 UI44개가 통과했다. UI에서는 사이하 다섯 등급, 에바 확률 실패/두 단계 확정, 마프르 조건부 옵션을 실제 확인창과 결과로 사용했다. 두 해상도/화면5장을 보존한다. 30단계 시작 상태와 이미 보유한 상위 등급은 명시적인 격리 fixture다. 일반 플레이의 모든 재료 획득과 전체 육성 과정을 시험한 결과가 아니다.

실제 Main/current map/save32, 동일 payload 저장, deferred-save, HP흡수·30초 회복 기존 회귀도 통과했다. 전투의 난수는 테스트 전용 World 하위 클래스에서 명중/치명타 여부만 고정하며 생산 코드는 바꾸지 않는다. 스킬 회복 검사의 `lfe_scale`은 검증용 계수를 사용하며 실제 스킬 정의의 수치를 변경하지 않는다.

`combat_hud_test.gd`에서 기존 성능 회귀를 발견했다. 최초 커밋 `d9fceac5c`와 후속 구현 직후 코드 모두192타에 최대HP조회192/최대MP조회0으로 동일하게 실패했다. 기존 옵션각성 경로가 회복0에도 최대HP를 재계산하던 부분을 실제 회복량이 양수일 때만 실행하도록 고쳤다. 테스트/임계값은 변경하지 않았다. 수정 후 기존 전투 HUD 검사1200개가 통과했고 최종 로그를 별도로 보존한다. Source Maphr가 없는 타격에는 조건 확인을 위한 추가 최대HP 조회도 하지 않는다. 프레임 성능·Windows·Android·오디오·원작 시각 승인은 이 결과에 포함되지 않는다.

`validation-absolute.json`과 `evidence/absolute/`에 현재 코드·출력 SHA 및 실패 비교를 기록한다. 최초 검증 파일은 `d9fceac5c`의 기록으로 구분한다. 사용자 지정 드롭/각성 비용, 원본 확률 수치, 서버 조건과 일일 한도 미확정 사항은 바꾸지 않는다. `[skip ci]`로 커밋하며 원격 CI 수동 실행/재실행이나 main 병합은 하지 않는다.

## 확률·비용 후속 지시 적용

[공식 확률 공개표](https://probability.plaync.com/lineagem/view?probCategoryId=683568e3068cf65296bc535e)의 30개 기본 확률을 기존 `data/growth/lineage_growth.json`과 대조해 전부 일치함을 확인했다. 일반 구간의 0.1% 균등 후보 방식과 절대 옵션10%도 공개 설명으로 교차 확인했다. 다만 원본523의 말기 Min/Max·SpecialRouteProbability가 일반 공개 설명과 달라지는 곳은 사용자 지시에 따라 원본을 우선한다. 모든 단계 후보를21개로 덮어쓰지 않는다.

일반 강화140개 비용, 절대 옵션35개 묶음의 두 소비 경로/성공률, 충전량은 원본값이다. 확률 변경 비용1도 이제 SymbolConstant14에서 직접 적용해 기존 설정보다 우선한다. 열쇠1000포인트는 MarketPayment116524와 제품 연결로 확인한다. 원본에 없는 경제 수치 때문에 막힌 문양 거래는 현재 없다. 기존의 초기화 두루마리1개, 일일 제한 없음은 현행 로컬 게임 정책이며 기존 설정을 보존한다. 기본 확률·기존 초기화 설정은 `lineage_growth.json`, 원본 비용/확률은 importer와 원본 projection에서 구분되어 설정된다. 새로 임의의 확률·가격을 만들 필요는 없었다.

남은16개 절대 보상은 비용·확률의 부재로 막힌 것이 아니다. 전투 소비자·PvP·순간이동·버프 해석 및 원작 별도 저장/복구 상품의 기능과 가용성 문제는 경제 수치 자체 설정 승인으로 활성화하지 않는다. 본 변경에는 실제 결제·외부 재화 처리가 없다.
