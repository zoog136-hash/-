# 상점 523 적용 범위와 비공개 팩 설치 — 2026-11-04

같은 Draft PR #247에서 세린에 이어 은기사마을 글렌을 연결했다. 원본 판매 그룹 192개 전체 구현 완료는 아니다. 기본 UI 경로는 기존 상점 → 원본 상점 → NPC 판매이며, 실제 지도에 원작 NPC를 배치한 것은 아니다. 아래 보관 팩은 데이터이며 이 PR의 게임 코드가 별도로 필요하다.

## 구현과 남은 범위

세린(그룹 13, 객체 27, 스폰 4)은 기존 소모 재료, 글렌(그룹 40, 객체 31, 스폰 160)은 기존 장비에 연결한다. 원본 이름/ID를 기존 아이템 정의와 대조한 목록은 각각 10종·36종이다. 모든 상품을 실제 결제·착용했다는 의미는 아니다. 실제 화면 검증은 마력의 돌 (각인) 2개와 기사의 면갑 (각인) 2개를 사용했다. 면갑은 원본 Cost 1000·Percentage 500·Amount 1을 유지하고 명시된 자체 최종가 공식으로 개당 5000 아데나를 적용한다. Normal 축복 코드·강화 0·속성 강화 0이 확인된 장비만 생성하며 서로 다른 물리 ID를 부여한다.

## NPC 전용 횟수 초기화

원본의 갱신 이름·시각 상수는 NPC 팩 v2의 `source_semantics`에 보존한다. `LimitCountRefreshTypeID`와 그 정의 사이의 불명확한 연결은 별도 설정 `data/shop/source523_npc_reset_rules.json`에 **TWILIGHT 자체 연결**로 기록한다. 기본은 NPC만 사용하는 UTC 달력이며 게임 전체 시각과 마켓 달력을 바꾸지 않는다.

| 원본 코드 | 자체 적용 주기 |
| --- | --- |
| 0, 31 | 평생 한도, 초기화 없음 |
| 1 | 매일 05시 |
| 11 | 수요일 05시 |
| 24 | 매일 00시 |
| 41 | 매월 1일 05시 |
| 62 | 월요일 05시 |

`LimitCountPerAccount`는 오프라인 저장 프로필/현재 캐릭터 저장의 범위로 표현한다. 실제 온라인 계정 서버를 구현했다는 뜻은 아니다. UI는 양수 한도 행에 잔여 횟수·다음 초기화·자체 설정 출처를 표시한다. 결제와 횟수 기록은 원자적으로 저장한다. 재접속·시계 역행·정책 변경으로 한도를 우회하지 못하고 이미 결제한 주문은 기존 규칙 변경 후에도 수령할 수 있다. 기본 두 NPC의 실제 LimitCount=0은 무제한으로 보존했으며 제한을 새로 만들지 않았다. 양수 제한의 UI 문구와 날짜 경계는 합성 행 검사로 검증했고 실제 제한 NPC의 운영 활성화로 집계하지 않는다.

최신 ZIP은 Drive 업로드 뒤 메타데이터의 크기·상위 폴더·비공유 상태를 다시 확인했다. 이어 정식 Drive 다운로드 결과를 새 소비 폴더에 내려받아 ZIP 크기·SHA256·전체 CRC·각 내부 파일 SHA를 확인했다. 원본과 v1 백업은 업로드 성공과 메타데이터를 확인했으며 Drive에서 별도로 재다운로드한 것은 아니다. 표의 백업 SHA는 업로드한 로컬 원본의 검증값이다.

감사 JSON·조사 보고서·실행 로그·화면 캡처는 `LOCAL_ONLY`다. 이들을 새로 외부 업로드하지 않았다. Space에는 이번 최신 팩이나 검증 자료를 저장하지 않았다. 실행 모듈의 과거 Library 401은 바이트 수신 전 실패였으며 사용자가 엔진 자료 작업을 철회했으므로 재시도하지 않았다. 현재 확보한 비엔진 표의 수신 차단은 없다.

## 설치와 실제 소비

Drive 보관만으로 실행 중인 게임이 바뀌지 않는다. 다운로드한 ZIP을 아래 도구로 **새 디렉터리**에 설치하고 출력된 네 CLI 인자를 게임 실행에 전달한다. 도구는 기존 설치·저장을 덮어쓰지 않고 ZIP 멤버 이름·크기·CRC·SHA를 검사한다.

```sh
python3 tools/shop/source523_runtime_pack.py install /private/download/runtime.zip 04fa772c58e2a629566f04021efc193c083cfbb33a199ebe9cb05dd60ca52334 /private/applied/shop523-v2
godot --path /path/to/game -- --source523-shop-pack=/private/applied/shop523-v2/shop523.json --source523-shop-sha256=f9e0582927bfad5c13b6c478ed583d38979e5b69b64f2980441f1525af5ef13a --source523-npc-pack=/private/applied/shop523-v2/npc523.json --source523-npc-sha256=a3a6c7468dc67faa84465e8a64b2ea7b2102ea2bbdef3d405556221799dfe3c7
```

실제 소비 검증 경로는 `/workspace/shop-drive-consumer/download/runtime.zip` → `/workspace/shop-drive-consumer/applied/shop523-v2`다. 공식 Godot 4.7.2와 실제 코드/아트를 갖춘 `/workspace/shop-stage`, 검증된 맵 `/workspace/shop-current-map`에서 이 설치본의 네 인자를 사용했다. 별도 XDG 저장 디렉터리는 `/workspace/shop-drive-live/{data,config,cache}`다. 사용자의 기존 저장을 QA 재화로 변경하지 않았다. 일반 실행은 CLI 팩 인자를 주지 않으면 이 팩을 자동 로드하지 않는다.

최신 집중 검사는 Python 감사/원본 팩 14개, 설치 보호 5개, 실제 NPC 정의 17개, 합성 거래·초기화 75개, 실제 Main/UI·수령·착용·재접속 51개가 통과했다. OpenGL 960×540 캡처 6장을 직접 확인했다. 장비 착용은 실제 production 착용 메서드와 저장 재로드로 확인했으며 캡처 자체가 인벤토리 착용 화면을 보여준다는 뜻은 아니다. 최신 실제 Main/current-map·저장 보존 회귀도 32개 통과했다. 불필요한 전체/수동 CI·다른 PR/main 병합은 하지 않았다.
