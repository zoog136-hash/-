# 원본 상점의 각인 탄약11종

기존 탄약 슬롯과 원본 구매·보관함·수령 엔진을 재사용한다. 원본 아이템 ID/이름/Normal 스택을 유지하며 기존 화살·총알이나 서로 다른 금속/스팅 수량을 합치지 않는다. 새 NPC 좌표·스폰·무료 탄약을 만들지 않는다.

원본 ItemBonus의 WeaponSmallDamage/WeaponLargeDamage와 MaterialID를11종에 대해 확인했다. 빌더는 원본 SHA·CRC, 모든 탄약 보너스의 유형·조건·중복을 검증하며 새 영토/기간/미지원 효과가 있으면 거부한다. `data/shop/source523_ammo.json`은 최소 기능 정책이며 원문 행을 포함하지 않는다. 원본 스프라이트 번호를 찾았다는 이유로 픽셀/이펙트 납품을 주장하지 않는다.

기존 활·라이플·핸드캐넌은 장착한 같은 계열의 원본 스택을 사용한다. 건틀렛은 각인 스팅을 명시적으로 장착한 경우에만 이 새 탄약 경로를 사용하며 기존 무탄약 건틀렛 플레이를 잠그지 않는다. 빈 원본 탄약이나 축복 불일치 상태에서 일반 스택으로 대신 소모하지 않는다. 인벤토리의 착용/해제, 선택 키 저장/재로드와 발사 소모를 연결한다. 원본 발사 수량의 저장이 실패하면 발사를 취소하고 수량을 보존한다. 기존 화살 소비 스킬도 선택한 정확한 원본 화살 스택과 MP를 함께 차감하며 쓰기 실패 시 복구한다.

일반 공격은 원래 선택한 탄약의 스냅샷을 사용하므로 마지막 발사분이나 투사체 도중 장비 교체가 다른 스택의 수치로 바뀌지 않는다. 원본 크기별 값은 유지하고, `1~원본 최댓값` 주사위를 기존 무기 주사위에 별도로 더하는 최종식은 **TWILIGHT 자체 정책**이다. 스킬의 기존 배율/수식에는 새 탄약 주사위를 임의로 확대하지 않는다.

[공식 무기 가이드](https://lineagem.plaync.com/guidebook/view?title=%EB%AC%B4%EA%B8%B0+%EC%95%84%EC%9D%B4%ED%85%9C)의 검색 본문에서 활에 화살이 필요하고 은 화살에 언데드 추가 대미지가 있음을 확인했다. 완전한 원작 최종식·추가량은 확보하지 못했다. 은/미스릴/오리하루콘에 적용하는 `언데드 +2`는 설정 파일에서 분리한 **TWILIGHT 추정치**이며 원본 수치라고 표시하지 않는다. 몬스터의 기존 `is_undead()`와 크기 분류를 사용하며 이름으로 종족을 추정하지 않는다. UI 설명에도 자체 적용임을 표시한다. 기존 일반 탄약의 수치와 사용자 밸런스는 바꾸지 않는다.

재생성은 `python3 tools/shop/build_source523_ammo.py /private/source.zip /private/ammo-check.json`으로 수행한다. 실제 검사는 격리 XDG 프로필, `TWILIGHT_SOURCE_AMMO_TEST=1`, 기존 상점/NPC 팩 CLI와 기존 맵을 사용하여 `source523_ammo_main_test.gd`를 실행한다. 검사는 실제 구매한 무기·탄약의 UI 착용·소모·저장/재로드와 쓰기 실패·축복 보호를 확인한다. 크기/종족 피해 검사는 제어된 계약 probe이며 원본 전체 전투/실기기 검증이 아니다.

실제 Main/OpenGL에서11종의 원본 묶음30개씩을 구매·수령하고 실제 구입한 활/라이플/건틀렛을 기존 호스트 직업 규칙으로 착용하여223검사가 통과했다. 원본마다 다른 단일 스택 한도를 각각 확인했으며100,000과500,000을 같은 한도로 가정하지 않는다. 이 단일 키 인벤토리의 상한 적용은 원본 다중 가방 스택 전체 재현과 구분한다. 발사 검사에는 실제 production 탄약 소비 게이트와 실패 원복, 크기/언데드 피해 계약 probe를 사용했고 원본 전투 수식 전체를 복원했다고 주장하지 않는다. 원본 무게 값은 메타데이터로 보존하고 실제 적재 계산은 기존 호스트 탄약 무게0을 재사용한다.
