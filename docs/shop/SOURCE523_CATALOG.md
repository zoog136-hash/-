# 523 원본 상점과 게임 거래

기준 main은 `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`이다. 기존 상점의 **원본 상점**에서 상품·NPC 판매·재화·누적 보상·보관함을 이용한다. 검증된 원본 팩을 지정하면 진입점을 표시한다. 일반 게임의 기존 상점 가격, 용옥 월 1회 제한, 각성 비용·성공률·실패 규칙은 변경하지 않는다.

상품 목록 조회에 그쳤던 단계를 실제 게임 내부 거래로 확장했다. 구매 재화와 미수령 주문을 함께 저장하고, 보관함 수령 시 아이템·마일리지와 수령 기록을 함께 저장한다. 별도 모형 지갑을 만들지 않고 기존 `gold`, `inventory`, 물리 장비 개체, 실제 원자적 저장기를 사용한다. 외부 현금 결제·영수증·쿠폰 자격을 생성하지 않는다.

## 입력과 실행

Library에서 정식 materialize한 입력의 실제 바이트와 전체 ZIP CRC를 확인했다. 원본 JSON·Library 파일은 변경하지 않았다.

| 입력 | 바이트 | SHA256 |
| --- | ---: | --- |
| `lineagem_patch523_all_content_validated_and_508_520_deltas.zip` | 25,031,173 | `d5192c3c735ff95c6b181bf2d4d77448d8b562fdb28dbd43f897fa4eae1f4832` |
| `TWILIGHT_523_shop_currency_time_semantics_20261104.zip` | 310,481 | `b5d682539e411f8d84618f7ed6d54c48043aec79980b2c9444834d24f16d0d7b` |
| 파생 `shop523.json` | 68,250,624 | `f9e0582927bfad5c13b6c478ed583d38979e5b69b64f2980441f1525af5ef13a` |

```sh
python3 tools/shop/build_source523_shop.py /private/lineagem_patch523_all_content_validated_and_508_520_deltas.zip /private/shop523.json
godot --path . -- --source523-shop-pack=/private/shop523.json --source523-shop-sha256=<빌더가 출력한 SHA256>
```

빌더는 저장소 밖에만 팩을 쓰고 원본 ZIP 해시·CRC·엄격한 JSON을 검사한다. 원본 27표의 모든 행·순서와 필요한 한국어 설명 부분집합, 표별 원문 바이트 SHA·크기·행수를 보존한다. 상품 6,819개, NPC 판매행 4,328개, 제한 9,215행, 재화 272개·원천 279행, 누적 보상 3개·18단계를 포함한다. 로더는 팩 SHA·형식·필수 필드·고유 ID·연결을 다시 검사한다. 조회 결과는 복사본이다. 원본과 파생 팩은 `PRIVATE_LOCAL_ONLY`이며 공개 Git에 넣지 않았다.

## 거래와 저장

- UI는 상품 번호·구매 횟수만 보낸다. 실행 직전에 가격·재화·원본 지급량·판매 및 제한 조건을 다시 확인한다. 1회 묶음 수량과 구매 횟수를 구분하며 최대 1,000회, 정확한 정수 범위를 검사한다.
- 결제는 `pending` 보관함 주문을 만들며 즉시 아이템을 주지 않는다. 수령 때 원본 상품과 별도 구매 보너스를 지급한다. 같은 주문을 재수령하거나 재접속으로 되살릴 수 없다. 구매 당시 원본 팩 SHA가 달라지면 주문을 보존하고 지급을 거부한다.
- 실제 저장이 성공한 뒤 메모리를 변경한다. 저장 실패, 재진입, 무게 초과, 수치 오류는 재화·상품을 부분 변경하지 않는다. 무게 초과 주문은 수령 전 상태로 남는다. 진행 중인 기존 맵 저장 이전은 거래를 준비하기 전에 완료한다.
- 기존 장비 ID·강화 수치를 보존하며 새 장비에만 새 ID를 부여한다. 잠긴 아이템·장비 개체를 결제에 사용하지 않는다. 원본 용옥 상품은 기존 전용 상점으로 안내해 월 제한·사용자 가격을 우회하지 못하게 한다.
- 저장에 `source_shop` 필드를 추가한다. 해당 필드가 없는 과거 저장은 최초 읽기 때 `.pre-source-shop-<원래 SHA256>`로 정확한 바이트 백업을 만든다. 손상된 상점 상태는 진행도 적용 전에 거부하고 원래 파일 덮어쓰기를 막는다.
- 재화의 지급용 `ForGive`와 소비 후보를 구분한다. 지급 원천이 유일하지 않거나 없는 재화는 지급하지 않는다. 소비 순서 방향·혼합 소모를 모르는 경우, 하나의 후보만 잔액이 충분할 때 처리하고 복수 후보가 충족되면 거부한다. 이름만 비슷한 원본 아이템을 같은 재화로 취급하지 않는다.

## 원본 값 우선과 자체 가격 설정

마켓의 결제 금액·단위·1회 지급량·별도 보너스는 원본 값을 그대로 사용한다. NPC의 `Cost`, `Percentage`, `Amount`는 원본 입력이며 최종 가격 공식·세금·반올림·재화 종류까지 증명하지 않는다.

2026-11-04 공개 조사에서 [공식 2023-04-19 패치 노트](https://lineagem.plaync.com/board/update/view?articleId=643eb29f4c31e21977138d13)의 강력 체력 회복제 (각인) **기본가 850 아데나**를 찾았다. 현재 523 원본의 해당 기본값과 일치한다. 이는 과거 공식 기본가의 대조이며 현재 NPC 최종 세금·공식 검증을 뜻하지 않는다. 공식 검색 결과의 가격 문구를 확인했으며 동적 페이지 본문 전체를 취득했다고 주장하지 않는다. 다른 NPC의 통화·최종 공식을 이 한 예로 일반화하지 않는다.

사용자가 요청한 미확인 경제 수치의 자체 구현은 `source523_shop_economy.gd`에 격리했다. 자체 최종 가격은 UI 상세와 구매 확인에 **TWILIGHT 자체 최종가**로 표시한다. 확인된 명시 가격 정책이 있으면 그것을 먼저 사용한다. 명시 가격은 `origin` 출처가 필수다.

| 자체 설정 | 기본값 | 의미 |
| --- | ---: | --- |
| `currency_unit`, `currency_class` | 4, 26 | 게임 내부 아데나. 모든 원본 NPC의 공식 통화라는 주장이 아니다. |
| `percentage_divisor` | 100 | 원본 Percentage를 적용하는 자체 분모 |
| `tax_basis_points` | 0 | 자체 세금 0. 공식 성 세율을 재현하지 않는다. |
| `missing_base_price` | 500 | 원본 Cost가 양수가 아닐 때만 사용하는 자체 기본가 |

자체식은 `ceil(base × Percentage × Amount × (10000 + tax_basis_points) / (percentage_divisor × 10000))`다. 원본의 127,500,000,000 원시 곱을 공식 최종가로 오인하지 않는다. 64비트와 JSON 정확 정수 범위를 검사하며, 할인으로 이동 재화 할인표를 끌어오지 않는다. 기존 일반 상점의 가격 레지스트리는 수정하지 않았다.

NPC 자체 이용 규칙은 경제 설정과 분리한다. 최신 사용자 지시에 따라 별도 NPC 팩의 원본 참조가 확인된 말하는 섬 세린에는 설정 가능한 **TWILIGHT 오프라인 가정**으로 0시간·0날짜 상시 거래와 원격 목록 이용을 연결했다. 이를 원본 실행 의미의 확인으로 취급하지 않는다. 서버 공통 재고, 혈맹/공성·카드 등 기존 제한은 유지하고 장비의 미확정 축복·강화 지급도 자동 허용하지 않는다.

후속 [NPC 활성 조건 재조사](NPC_ACTIVATION_AUDIT.md)에서는 192개 그룹 중 121개의 NPC 객체·재화 참조를 찾았다. 확인된 참조와 없는 71개 그룹, 원본에서 미확정인 실행 규칙과 실제 적용한 자체 동작을 구분했다. 엔진 자료는 사용자 지시로 추가 탐색·전달·분석을 중단했으며 우리 게임의 선행조건이 아니다. NPC 팩 생성·실행·설정과 새 UI·저장 검증도 해당 문서에 기록했다.

## 명시 정책

[정책 예시](policy.example.json)를 저장소 밖에 복사해 팩 SHA를 채우고, 실제 확인한 조건만 추가한다. 정책 파일 SHA도 실행 인자로 필수 지정한다.

```sh
sha256sum /private/shop-policy.json
godot --path . -- --source523-shop-pack=/private/shop523.json --source523-shop-sha256=<팩 SHA> --source523-shop-policy=/private/shop-policy.json --source523-shop-policy-sha256=<정책 SHA>
```

정책은 다음 필드를 지원한다. 예시 기본값은 시간대·서버·일일 대상이나 NPC 활성화를 임의로 설정하지 않는다.

- `calendar_offset_minutes`: 원본 달력 시간대와 UTC의 명시 차이. 게임 전체의 시계·시간 설정을 바꾸지 않는다.
- `server_context`: 확인된 `world_no`, `region`. 원본 서버세트를 각각 판정한다.
- `period_reset_hour`: 기간 단위 61(일), 71(일반 주), 81(월), 11311(수요일 주)의 확인된 초기화 시각. 평생 한도 111은 시간 설정이 필요 없다. 미확인 기간 배수·제한 유형은 차단한다.
- `daily_purchase_ids`: 실제로 일일 활성화 대상임을 확인한 마켓 상품 번호. 숫자 4인 표시 카테고리를 추정해 채우지 않는다.
- `merchant_economy`: 위 자체 경제 기본값을 조정한다.
- `npc_local_rules`: 기본 NPC 자체 이용 규칙을 대체한다. 별도 NPC 원본 팩과 확인된 객체·스폰 연결이 필요하다. [NPC 상세](NPC_ACTIVATION_AUDIT.md)를 참고한다.
- `merchant_prices`: 판매행 ID를 키로 하는 조건·명시 가격 정책. `goods_sha256`는 런타임 `merchant_signature(id)` 값으로 원본 판매행 전체에 묶는다. 확인한 `time_unrestricted: true` 없이는 0~0 시간을 자동 허용하지 않는다. 명시 가격이 필요하면 `unit_id`, `class_id`, 1회 `amount`, 출처 `origin`을 함께 지정한다. 계정 횟수 한도가 있으면 원문과 대조한 `refresh_unit`도 필요하다.

정책을 적용한 거래는 정책 SHA를 저장에 기록한다. 다른 초기화·가격 정책으로 기존 구매 한도를 재설정하지 못하도록 정책 불일치는 거부한다. 정상 저장을 다시 불러와도 잘못된 실행 정책의 차단이 해제되지 않는다. 정책 변경을 위한 데이터 이전 도구는 이번 범위에 포함하지 않았다.

원본 `OnSale`, 현재 진열, DateTime 객체, 서버 조건은 독립적으로 적용한다. 명시 시간 기준이 없으면 원본 기간 경계의 앞뒤 이틀은 보수적으로 차단하고 충분히 내부인 구간만 허용한다. DateTime ID를 날짜로 비교하지 않는다. 구매그룹은 원본 `Index` 순서만 보존하고 선행 구매 의무를 만들지 않는다. 클래스체인지 추가 조건은 보너스 아이템으로 지급하지 않는다.

## 누적 보상

엔진과 보상 UI를 연결했다. 일일 무료 보상, 결제, 보관함 수령, 일일 활성화, 단계 보상 수령을 분리한다. 명시된 대상 마켓 주문을 수령할 때에만 하루 1회 활성화하고, 05시 일일 경계와 수요일 05시 주간 경계를 각각 적용한다. 무료·단계 보상은 저장과 함께 1회 수령하며 시계 역행으로 반복 수령할 수 없다. 같은 숫자의 NPC 주문 ID가 마켓 활성화를 만들지 않는다.

현재 원본의 3개 행사는 2026-11-04 기준 모두 종료됐다. 종료 행사를 임의 연장하지 않는다. 실제 화면에서는 기간 종료 사유와 수령 불가 상태를 보여준다. 활성 행사 전체 주기는 명시적 합성 규칙으로 검증했으며, 이를 현재 원본 행사의 실제 활성 확인으로 계산하지 않는다.

## 검증과 전달 경계

실제 원본 검사와 합성 계약 검사는 구분한다. 테스트는 별도 XDG 사용자 디렉터리, 검증된 현재 맵 팩, 공식 Godot 4.7.2를 사용한다. 플레이어 저장에 QA 재화를 넣지 않는다.

```sh
SOURCE523_SHOP_ZIP=/private/lineagem_patch523_all_content_validated_and_508_520_deltas.zip python3 -m unittest discover -s tests -p test_source523_shop_compiler.py -v
godot --headless --path . --script res://tests/source523_shop_runtime_test.gd
TWILIGHT_SOURCE_MAP_PACK=/private/current-map godot --headless --path . --script res://tests/source523_shop_commerce_main_test.gd -- --source523-shop-pack=/private/shop523.json --source523-shop-sha256=<팩 SHA>
```

`source523_shop_commerce_main_test.gd`는 실제 Main과 UI에서 취소, 원본 120다이아 결제, 미수령 저장, 실패 원복, 무게 초과, 재접속 수령, 원본 상품 10개·마일리지 240 지급, 중복 거부, 장비 보존, 손상 저장 보호와 과거 저장 백업을 확인한다. NPC는 실제 원본 판매행에 **QA 전용 명시 활성 조건**을 설정하여 화면 구매·차감·보관함·수령을 검사한다. 이 설정은 제품의 NPC 기본 활성화가 아니다.

OpenGL 실행에서 `--source523-capture-dir=/private/captures`를 추가하면 실제 확인창·보관함·수령 결과·NPC 가격/조건·NPC 구매/수령·종료 행사의 화면을 남긴다. `--source523-small-ui`는 960×540 검사다. Linux llvmpipe 결과이며 Android 실기기 검증이 아니다.

검증 결과는 PR의 로컬 결과와 이 환경의 `/workspace/shop-evidence/commerce-final/`에 기록한다. 기존 원문 전수 검사 7개와 카탈로그 38개, 이전 탐색 화면 검사는 앞선 카탈로그 커밋에서 통과했다. 2026-11-04 신규 거래 결과는 합성 59개, 실제 Main/UI OpenGL 1280×720 및 960×540 각각 58개, 실제 캡처 총 14장, core 저장 32개·동일 저장·지연 저장 모두 통과다. 기존 상점 권한·매입과 실제 구매 회귀 73개, 723개 시트·41,442프레임 SHA도 통과했다. stage 최종 import와 완료 로그에 스크립트·리소스 오류가 없음을 확인했다. 캡처 14장을 직접 확인했다.

실제 stage는 저장소의 코드·데이터·실제 아트와 검증된 현재 맵을 사용한다. 동적 참조 때문에 core stage에서 빠졌던 기존 초상화 및 매입 fixture는 저장소의 실제 바이트를 추가했다. 대체 이미지를 만들지 않았다. 리소스 검사의 723개 WebP 통과를 원본 아트 전체 통합으로 간주하지 않는다. 기존 `--source-dir` 장부 검사는 `a1.zip` 부재로 미완료이며, 이번 523 ZIP의 별도 SHA·CRC 확인과 구분한다.

원본 팩·스크린샷은 이 환경의 로컬 파일이며 영구 배포 완료로 표시하지 않는다. 공개 Git에는 코드·테스트·설명·빈 정책 예시만 반영한다. 다른 PR을 병합하지 않는다. 원격 CI 수동 실행·재실행·워크플로 변경 없이 `[skip ci]` 커밋으로 기존 Draft PR을 갱신한다. 원격 필수 검사 통과나 병합 가능 상태를 주장하지 않는다.
