# 523 NPC 활성 조건 재조사 — 2026-11-04

기준은 PR #247의 세린 연결 `843f735cd9f4d28ea733237c44e40f004bd46b50`과 main `7d550a78a8fd1a95a50ebb18b38c3134380c3fa6`이다. NPC 활성 근거를 재조사하고, 최신 사용자 지시에 따라 미확정 동작에는 설정 가능한 TWILIGHT 오프라인 규칙을 적용했다. 원본 정체·재화가 확인된 말하는 섬 세린과 은기사마을 글렌의 거래를 일반 상점 UI·저장에 연결한다. 기존 구매·수령과 종료 행사는 보존한다.

## 새로 확인한 연결

`NpcClass.ID`, `EarthObjectClass.ID`, `MerchantsID`는 같은 번호 공간이 아니다. 판매 그룹과 NPC 객체는 다음 명시 관계로 연결한다.

1. `Unit.ID=25`의 이름은 `MerchantsID`다.
2. `EarthObjectUnit.UnitID=25`의 `Value`가 판매 그룹 번호이며, 같은 행의 `EarthObjectClassID`가 NPC 객체다.
3. 같은 객체의 `EarthObjectUnit.UnitID=201`은 `CurrencyID`를 가리킨다.
4. `EarthObjectClass`, `EarthObjectDialogActions`, `EarthObjectSpawn`에서 정체·동작·스폰 정의를 각각 확인한다. `CurrencyUnitClass`에서 실제 재화 원천을 확인한다.

## 누락과 미구현을 구분한 차단 사유

- **실행 규칙 미확인:** 0~0 시간은 4,328행 전체에서 관찰되지만 '상시 판매'를 뜻한다는 제공 표·상수·공개 계약을 찾지 못했다. 값이 널리 쓰인다는 사실을 원본 규칙의 증거로 사용하지 않는다. 실제 연결에는 아래에 명시한 별도 자체 설정을 사용한다.
- **연결 정의 없음:** 아래 71개 그룹은 현재 523 `EarthObjectUnit`의 Unit 25 참조에 없다. 다른 표에 `MerchantsID`라는 필드는 없으며, 이름·동일 ID로 보완하지 않는다. 내부 서버 정의가 없다고 단정하는 범위가 아니라 제공된 표에서의 부재다.
- **초기화 enum 미확인:** 판매표는 `LimitCountRefreshTypeID` 0·1·11·31을 사용한다. `ContentsResetScheduleType`에는 1 Daily·11 WeeklyWed 등이 있지만 0·31은 없다. 이 두 필드 사이의 참조 규칙도 제공되지 않았다. `ConstantData`의 ContentsRefreshHour=5만으로 모든 상점의 초기화를 연결하지 않는다. 다른 공간인 `Unit.ID=31`은 BuffDeckID이며 구매 갱신 규칙이 아니다.
- **원본 정의는 있지만 실행/권한 연결이 남음:** 서버 공통 재고, 스폰 서버세트, 내성/성주 권한, 혈맹 가입일·등급, 카드 자격 등은 단순 경제 수치가 아니다. 일부 조건은 값이 실제로 있으나 현재 게임의 권한 처리로 확인하지 못한다. 혈맹·공성을 재도입하지 않는다.

## 실제 연결한 오프라인 NPC 규칙

`data/shop/source523_npc_local_rules.json`은 원본이 아닌 **TWILIGHT 자체 설정**이다. 현재 기본 대상은 판매 그룹 13 → 객체 27 → 스폰 4(말하는 섬 세린), 그룹 40 → 객체 31 → 스폰 160(은기사마을 글렌) 두 경로다. 원본 상품·통화·동작·스폰 참조를 먼저 검증하고 다음 자체 동작을 적용한다.

- `zero_hours_are_open`: 원본 0~0 시간에 시간 제한 없는 로컬 거래를 적용한다.
- `zero_dates_are_open`: 원본 날짜 시작·종료가 0일 때 로컬 날짜 제한을 두지 않는다. 양수 원본 날짜를 지우거나 종료 행사를 연장하지 않는다.
- `remote_catalog`: 실제 맵에 NPC를 임의 배치하는 대신 기존 상점의 NPC 목록에서 원격 거래한다. 원작의 NPC 접근 거리 재현이라는 의미가 아니다.
- `merchants`: 판매 그룹·객체·스폰 ID와 표시 이름을 명시한다. 다른 NPC를 추가해도 세린의 저장된 규칙 해시는 달라지지 않는다. 수동 스폰·원본 서버 제한·별도 객체 속성이 있는 경로는 자동 허용하지 않는다. 원본 혈맹·공성·카드·횟수·레벨 조건도 기존 검사로 남긴다.

재화는 원본 Unit 201의 Currency 1 → Item 26 아데나를 우선한다. NPC 최종 가격은 앞서 구현한 설정 가능한 자체 계산식이며, 마력의 돌 (각인)은 원본 Cost 300을 사용해 1개 300 아데나, 2개 600 아데나다. 공식 세율을 복원했다고 주장하지 않는다. 이름·ID가 일치하는 기존 인벤토리 아이템만 지급하며 임의의 새 아이템이나 가상 지갑을 만들지 않는다.

별도 NPC 정의 팩은 기존 상점 팩의 SHA에 연결한다. 기존 68,250,624바이트 상점 팩을 재생성하거나 덮어쓰지 않으므로 이전 보관함 주문의 팩 정체를 보존한다.

```sh
python3 tools/shop/build_source523_npc.py /private/lineagem_patch523_all_content_validated_and_508_520_deltas.zip /private/shop523.json <기존 상점 팩 SHA> /private/npc523.json
godot --path . -- --source523-shop-pack=/private/shop523.json --source523-shop-sha256=<기존 상점 팩 SHA> --source523-npc-pack=/private/npc523.json --source523-npc-sha256=<NPC 팩 SHA>
```

최신 NPC 팩 v2는 238,686바이트, SHA256 `a3a6c7468dc67faa84465e8a64b2ea7b2102ea2bbdef3d405556221799dfe3c7`다. 이전 v1(238,185바이트, SHA256 `65d625bf16dcaf5aa280260082eee587801f3e2d2567d48b8444c0a14e84d2f3`)은 별도 보존한다. 팩의 사실 데이터에 들어 있는 `activation_authorized: false`를 권한으로 바꾸지 않는다. 사용자 지시에 따라 별도 로컬 설정을 명시적으로 적용하는 구조다. 원본과 최신 적용팩은 비공유 Drive의 백업/적용 폴더에 분리 보관하며 공개 Git에 넣지 않는다. 설치·해시·실제 소비 검증은 [최신 범위와 설치](SHOP523_SCOPE_AND_INSTALL.md)에 기록한다.

기존 해시 정책 JSON의 `npc_local_rules`에 설정 전체를 넣으면 기본값 대신 적용한다. `enabled: false`로 NPC 거래를 끌 수 있다. UI 목록은 세린과 글렌을 표시하며, 상세·확인창·보관함에서 **TWILIGHT 오프라인 가정**을 안내한다. 작은 화면의 구매 버튼 위에는 실제 총액과 자체 규칙 표기를 함께 보여준다.

결제 저장에는 NPC 정의 팩 SHA와 해당 NPC의 유효 자체 규칙 SHA를 기록한다. 규칙을 바꾸면 해당 NPC의 새 구매를 차단해 과거 한도를 임의 초기화하지 않는다. 이미 결제한 보관함 수령은 새 NPC 규칙이 비활성화되거나 바뀌어도 구매 당시의 고정 지급 내용과 기존 상점 팩으로 처리한다. 다른 NPC의 규칙 추가와 일반 마켓의 자격 판정은 독립적이다.

## 검증과 산출물

## 후속 구현과 현재 검증

위의 이전 검증·감사 JSON은 당시 버전의 기록이다. 최신 결과는 [범위·설치 문서](SHOP523_SCOPE_AND_INSTALL.md)를 따른다. v2는 원본 `ItemBlessCode`와 갱신 관련 정의를 보존한다. 글렌은 원본 Normal이며 +0·속성 강화 0인 기존 장비에 한해 물리 개체를 생성한다. 축복/저주·강화 장비는 자동 허용하지 않는다. 기사의 면갑 (각인) 판매행 2171은 원본 Cost 1000, Percentage 500, Amount 1이므로 자체식으로 개당 5000 아데나다. 실제 2개 결제 10000, 별개 장비 ID 2개 수령, 기존 장비 보존, 실제 착용과 재접속 저장을 검사했다.

NPC 초기화는 별도 `source523_npc_reset_rules.json`의 설정 가능한 자체 코드 연결을 사용한다. 원본 enum 이름이나 5시 상수의 존재와 필드 간 계약 확인을 구분한다. 제한이 있는 행에서 잔여 횟수와 다음 초기화를 표시하고, 결제와 횟수 기록을 함께 저장한다. 기존 구매 이력과 규칙 정체를 보존하며 규칙 변경으로 한도를 초기화하지 않는다. 기본 두 NPC의 실제 LimitCount는 0이므로 새 제한을 만들지 않았다. 경계·횟수 동작은 명시적 합성 행으로 검사했다. 게임 전체 시각이나 마켓 달력은 변경하지 않는다.
