# TWILIGHT — 최상급팩 뽑기 및 변신·마법인형·성물 합성

## 적용 범위

이 구현은 2026-10-19 사용자 결정에 따른 **TWILIGHT 로컬 게임 규칙**이다.
리니지M의 특정 일자/상품/서버에 대한 공인 확률표 일치 증명은 아니다.

- 대상: **변신 / 마법인형 / 성물** 3가지. 카테고리별 카드 풀, 소유, 중복, 누적 실패는 서로 독립적.
- 최상급팩 11장: **고급 93.59%, 희귀 5.50%, 영웅 0.90%, 전설 0.01%**를 카드 1장마다 먼저 추첨.
- 결정된 등급의 **전체 등록 카드**를 한 종류당 같은 확률로 1종 선택. 카드 이름이 아니라 \`sourceId\`로 식별.
- 소유 이력이 없으면 도감 소유권 1장을 해금. 이미 획득한 카드가 다시 나오면 중복 수량 +1.
- 등급 카드 풀이 하나라도 비어 있으면 전체 11회 뽑기를 거절하며, 임의로 확률을 다른 등급에 몰아주지 않음.
- 계정/유료 상점/실제 팩 구매·가격 데이터가 없으므로 **무료 무제한 최상급팩 뽑기는 debug 빌드의 검수 버튼에만** 노출. 출시 버전의 팩 지급/차감/구매 연동은 미구현이다.

## 합성 규칙

| 중복 재료 등급 | 필요 중복 카드 | 성공 결과 | 성공 확률 | 실패 결과 |
|---|---:|---|---:|---|
| 일반 | 4장 | 고급 | 35% | 일반 카드 1장 |
| 고급 | 4장 | 희귀 | 17% | 고급 카드 1장 |
| 희귀 | 4장 | 영웅 | 12% | 희귀 카드 1장 |
| 영웅 | 4장 | 전설 | 11% | 영웅 카드 1장 |
| 전설 | 2장 | 신화 | 11% | 전설 카드 1장 |
| 신화 | 4장 | 유일 | 100% | 발생하지 않음 |

- **중복 카드만** 재료로 사용한다. 최초 획득으로 해금한 영구 소유권은 소모하지 않는다.
- 카테고리 및 등급이 같은 중복부터 등록 순서로 자동 선택해 정해진 개수만 소모한다. 결과 카드 종류는 **동일 등급 내 균등 랜덤**.
- 실패 20회 보상: **희귀→영웅** 및 **영웅→전설** 각각 카테고리별로 실패 20회 누적 시 목표 등급 카드 1장 추가 지급. 실패 시 받는 기존 등급 카드 1장과 별개다. 보상 후 해당 게이지 0으로 초기화. 성공하더라도 이전 실패 누적은 보존한다.
- 재료 부족/미지원 등급/목표 카드 풀 누락 시 합성 불가. 실패한 요청은 카드를 차감하지 않는다.

## UI, 저장, 이전 데이터

- 변신·마법인형·성물 도감 오른쪽에 최상급팩 검수 뽑기, 현재 소유 종류·중복 수량, 누적 실패, 등급별 합성 UI와 결과 텍스트 표시.
- 합성은 실제 카드 소유 중복 데이터가 충족된 경우에만 활성화하며, 수행 전 사용자 확인을 받는다.
- \`user://twilight_v20_save.json\`에 \`card_draw_fusion\` 확장 필드로 보유/중복/실패 누적을 저장. 이전 버전 저장 파일은 빈 카드 소유 상태로 호환된다. 손상된/미등록 카드 ID와 음수 재료는 복원 시 거절/보정.
- **기존 도감 장착/변신/소환의 접근 권한은 그대로 보존**한다. 오래된 세이브와 테스트 기능을 깨지 않기 위한 조치이며, 획득 카드로만 장착을 제한하는 후속 기능은 이번 PR에 포함되지 않는다.
- 뽑기/합성 애니메이션 제작과 상점 팩 지급은 이번 확률·보유 상태 PR과 별도 작업이다.

## 검증

- 새 테스트: \`tests/card_draw_fusion_test.gd\` — 등급 확률, 11장 지급, 동일 등급 균등 분배, 고급~유일 합성, 중복 소모, 실패 누적 보상, 허용되지 않은 범주 거부, 원본 ID 분리, 저장 왕복.
- CI: \`.github/workflows/card-draw-fusion.yml\` — Godot 4.7.2 import, GDScript 체크, 카드 회귀 테스트.
- 기존 UI 통합 검증: \`.github/workflows/ui-renewal-validate.yml\`의 \`scripts/ui/renewal_*.gd\` 경로 필터에 따라 PR에서 자동 실행.
- 저장소의 기존 \`.github/workflows/resource-integrity.yml\`도 PR에서 수행: 새 원본 아트는 추가하지 않았음.
- 본 작업에서는 리포지토리 전체 리소스가 로컬 컨테이너에 설치되어 있지 않고 GitHub 네트워크 직접 클론이 불가능하여 \`python3 tools/check_resource_integrity.py --root .\` **직접 실행을 완료했다고 주장하지 않음**. 결과는 GitHub Actions 성공 기록으로 별도 확인해야 한다.

## 변경 금지 및 후속

- 기존 \`catalog_v19.json\`, 카드 옵션, 전투 스탯 및 리소스는 변경하지 않는다.
- 새로운 카드 원본 이미지, 추출 파일 또는 제3자 리소스는 Git에 포함하지 않는다.
- 향후 실제 팩 아이템·지급·가격 연결 시 **팩 소모와 11장 수령을 단일 거래로 처리**하고, 저장 실패 복구 정책을 검증해야 한다.
